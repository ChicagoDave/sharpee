A Chord project has four everyday commands: **build**, **play**,
**test**, and **compose**. All of them run from the project directory.

## Build: including a playable web page

```shell
sharpee build
```

```text
🔨 Building browser bundle

  ✓ Validated orchard.story (gate-clean) and shipped it as story.story
  ✓ Story IR → dist/orchard.ir.json
  Bundling game.js...
  ✓ Built game.js
  ✓ Copied index.html
  ✓ Copied platform engine CSS (base, engine, decorations)
  ✓ Copied orchard.css

✅ Build complete! (game.js 1213.1 KB)

Output: dist/web/<id>/
```

`dist/web/<id>/` is a self-contained, static web page: your story, the
engine, and a browser client in one folder. Serve it locally with
`npx serve dist/web/<id>`, or host it anywhere static files go. For a
`.story`, the browser client is the default — `sharpee build` needs no
flag.

## Play in the terminal

```shell
sharpee play
```

```text
--- Play Mode ---  (/quit or /q to exit)

orchard

Story v0.1.0

Landing
A quiet place to begin. Doorways lead everywhere a story might go —
for now, this landing is the whole world.

> inventory
You are carrying:

a brass lantern

>
```

Type commands at the prompt exactly as a player would; `/quit` exits.

## Test the recorded tree

A story's tests live in one JSON document beside the `.story` file —
`orchard.story` pairs with `orchard.tests.json`. It holds a tree of played
turns, each carrying the assertions you made about its output.

You do not write that file by hand. You record it by playing: in Chord
Writer's Testing tab, play the story, and turn the turns you like into
tests. Branching where the story branches is the point — one document
covers every path you have played.

```shell
sharpee test
```

```text
Tree document: orchard.tests.json (seed 42, 2 line(s))
  ✓ opening-landing
  ✓ landing · inventory

  4 cards passing, 5 assertions passing
```

A failure names the card and shows what it wanted against what it got, and
`sharpee test` exits non-zero, so it drops straight into CI.
`--stop-on-failure` halts at the first miss; `--json` emits an NDJSON record
stream instead of this report.

<Callout title="Coming from .transcript files?">
  They are retired. Text transcripts, the `tests/` directory, `--chain`, and
  `--coverage` were replaced by the tree document — a Chord project has one
  test model, not two. Each retired form fails by name rather than silently
  doing nothing, so an older project tells you exactly what to move.

  Sharpee's own hand-authored transcript suites are a separate thing that
  still exists; they belong to the platform's test corpus, not to a story you
  write.
</Callout>

## Compose: the compiler on its own

`build` and `play` compile your story implicitly. `compose` is the same
compiler as a standalone step:

```shell
sharpee compose orchard.story --check
```

```text
compose: orchard.story is gate-clean (--check: IR not emitted)
```

`--check` runs every load-time gate and emits nothing, which makes it
the fast CI answer to "does my story still compile?". With `-o` it
writes the compiled story IR as JSON:

```text
compose: orchard.story loaded — 3 entities, 0 trait(s), 0 action(s), 0 hatch(es)
compose: IR written to orchard.ir.json
```

<Callout title="Gate-clean, then playable">
  Chord's compile gates catch unknown names, contradictory declarations,
  and misspelled references before the story ever runs. Each diagnostic
  is named, line-anchored, and usually carries a nearest-match
  suggestion. A story that composes gate-clean loads.
</Callout>
