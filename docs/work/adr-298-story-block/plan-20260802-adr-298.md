2. **`StoryConfig.author` (`packages/engine/src/story.ts`) has a wider blast radius than the ADR documents.** The ADR's Consequences section names only `stdlib/src/channels/standard.ts:91` (`StoryInfoData.author`), `story-loader`, and `devkit/src/standalone/browser-core.ts:98`. A verified repo-wide scan of `StoryConfig`/`config.author` consumers found it is *also* set directly (bypassing Chord entirely) in **7 TS-authored stories**' `index.ts` (`armoured`, `cloak-of-darkness`, `thealderman`, `dungeo`, `concealment-test`, `family-zoo-tutorial`, `channel-service-test`) and already join-formatted in several of their `browser-entry.ts` files (`armoured`, `cloak-of-darkness`, `thealderman`, `dungeo` all already do `Array.isArray(config.author) ? config.author.join(', ') : config.author` — this display convention pre-exists and should be simplified, not reinvented, once the field is always an array). It is also read in `packages/engine/src/save-restore-service.ts:282-284` (joined into the save's flattened `author: string` — the save-format field itself does not need to change shape, only its source expression) and typed independently (not derived from `StoryConfig`) in `packages/core/src/metadata/story-metadata.ts` (`StoryMetadata`, `SharpeeConfig` — Treaty-of-Babel-facing, singular `author: string`) and `packages/interpreter/src/types/story-metadata.ts` (`author: string | string[]`). **RESOLVED (2026-08-03, David)**: full platform-wide rename — `StoryConfig.author` → `authors: string[]`, including the 7 TS-authored stories and all internal plumbing. The boundary rule: **in-repo types go plural; external-spec-facing adapters stay singular**. Concretely, `packages/core`'s `StoryMetadata`/`SharpeeConfig` keep `author: string` — they mirror the Treaty of Babel iFiction record, whose `<author>` is a single string by external spec — with the join happening at record generation and the intentional divergence documented in a code comment (Phase 4). `packages/interpreter/src/types/story-metadata.ts` is resolved by the same rule at Phase 4 implementation time: if it feeds external iFiction/Babel serialization it stays singular; if it is internal plumbing it goes plural (verify its consumers before editing). The persisted save field (`IStoryConfig.author` in `core/src/types/save-data.ts`) stays a flattened joined string — source-expression change only, no save-format bump.
3. **`packages/ide-protocol/src/types.ts`** (in this repo) carries only the story `id`, not title/author/description — confirmed no change needed there. The Sharpee **IDE itself lives in a separate repo/session** (per project convention) — its consumption of the wire `authors` field is out of scope for this plan and must be coordinated separately; note this to the user rather than silently claiming IDE work is done.
4. **Zifmia needs no source change for the wire cutover.** `tools/zifmia/web/src/components/channel-renderer-host.ts` depends on `@sharpee/platform-browser` (workspace dependency, confirmed in `package.json`) and has no independent `.author`/`StoryInfoPayload` consumption of its own — it inherits Phase 7's `platform-browser` renderer fix automatically. Verification is a rebuild (`./repokit build --zifmia`), not a code edit.
5. **`ir.meta.title` stays a top-level `IRMeta` string** (confirmed by ADR Consequences: the IDE's window title reads it directly and must be unaffected) — Phase 1 populates it from the new `title:` field during analysis rather than folding title into the typed `fields` shape. `ir.meta.author` (the old positional single string) is retired in favor of the typed `fields.authors: string[]`.
