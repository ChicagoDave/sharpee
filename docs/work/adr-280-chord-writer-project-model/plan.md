# Session Plan: Implement ADR-280 — Chord Writer project model (typed artifacts, default home, devkit-owned scaffolding)

**Created**: 2026-07-28
**Overall scope**: Default New Story to `~/Documents/Chord/<name>/`, turn the Chord Writer sidebar from a raw file list into a typed-artifact view (Story/Walkthroughs/Transcript Tests/Assets/Web Template/Other), make `sharpee init` (devkit) the single owner of "what a project is" so the IDE calls it instead of scaffolding independently in Swift, and open the story in the editor the moment New Story finishes. D1-D4 of ADR-280. Work spans `packages/devkit/` (platform change — needs discussion first, per CLAUDE.md) and `tools/ide/` (Swift/Xcode).
**Bounded contexts touched**: N/A — infrastructure/tooling (authoring-tool UI and CLI scaffolding, no engine/domain behavior change). Per session-planner's DDD-applicability check, this is framed in plain technical terms.
**Key domain language**: not DDD in the engine sense, but this ADR family has its own settled vocabulary that phases must use verbatim rather than re-deriving: the five typed artifact groups **Story**, **Walkthroughs**, **Transcript Tests**, **Assets**, **Web Template** (plus the open-ended **Other** group), and the scaffolding verb **seeded, not empty** (ADR-280's own phrase for "each folder demonstrates its artifact type").

**Why this plan is scoped to ADR-280 alone**: ADR-280 is the parent artifact-model ADR three other ACCEPTED-but-unimplemented siblings depend on — ADR-284 (publishing, consumes Web Template + Assets), ADR-285 (asset management, manages the Assets group), ADR-286 (Web Template layout DSL, defines what the Web Template artifact *is*). None of those three are implemented by this plan; see the forward-compatibility notes under Phase 2 and Phase 3 for where this plan's choices must leave room for them rather than foreclose them.

**Cross-ADR gap found during planning (not in ADR-280's own text)**: ADR-286 (the Web Template layout DSL + devkit transform) is ACCEPTED but has no "IMPLEMENTED" marker — the transform that turns a `.templates` file into a working page does not exist yet. ADR-280 D3's seed set includes a Web Template seed ("the platform default `standard` template expressed in the layout syntax"), and Q-2 explicitly ties that seed's content to ADR-286's syntax. Until ADR-286 ships, a seeded `.templates` file has no build-time effect — it is inert text, not a working artifact. Phase 3 below scopes around this explicitly rather than silently assuming ADR-286 is done. **Phase 1 (the default project home) is deliberately upstream of all of this** — it touches neither the seed nor the template grammar, which is why it was carved out to run first (David's call, 2026-07-28).
