## G1. D16 conversation suspension — CLOSED (2026-08-15, this session)

**Finding.** "A conversation in progress suppresses goal pursuit" (ADR-310 D16, cited by
AC3) had no implementation: the goal sub-step never consulted conversation state, and the
only conversation-state object (`ConversationLifecycle`) lived inside the builder-path
dialogue extension — module state the chord path never touches and D17 forbids anyway.

**Clean fix (landed).** One new piece of *data*, one new *rule*, zero new services:

- **Data**: `CharacterModelTrait.activeConversation?: { partnerId, lastTurn }` — D17
  says everything the model remembers rides the trait, and "we are mid-conversation" is
  something the model remembers. It serializes with the trait, so a save mid-conversation
  restores mid-conversation. Never cleared in place — superseded or outgrown, so no
  per-turn mutation exists.
- **Rule**: `conversationSuppressesGoals(trait, currentTurn)` — fresh while
  `turnsSince(currentTurn, lastTurn) < DEFAULT_DECAY_THRESHOLDS.neutral` (the ADR-142
  lifecycle vocabulary, reused rather than a second notion of "conversation over").
  Turn arithmetic through the clock seam (`character-clock.ts`), so ADR-316 still
  changes one seam.
- **Stamps**: both dialogue surfaces call one helper (`markConversationTurn`), the same
  two-surface/one-semantics pattern as the claim bookkeeping in `claims.ts`: the chord
  topic arm stamps for ANY ask reaching a modeled owner (row hit, evasion, row miss —
  an evasion is still a conversation), the selector socket stamps on every handled
  delivery.
- **Consultation**: `executeNpcGoals` returns before step execution while the marker is
  fresh; `manager.evaluate` still runs first, because D16 is explicit that activation
  re-evaluates and "the goal simply does not act."

**Rejected.** Wiring `ConversationLifecycle` instances into the topic dispatch (module
state — violates D17, invents a parallel lifecycle store); a "recently talked" heuristic
inside the goal manager (second clock, second definition of conversation); an engine-level
conversation flag (the engine has no business knowing what a conversation is).

**Evidence.** 11 new tests across 5 files, all asserting on trait state
(`activeConversation`, `goalState`); mutation-verification clean; suites: character 405,
world-model 1479, story-loader 495, all passing (2026-08-15).

## G2. The acceptance fixture story (310-AC2 + 318-AC1's transcript leg) — CLOSED (2026-08-15; evidence in acceptance-audit.md AC2/318-AC1)

> As-built deviations from the design below: the deletion variants are
> self-contained sibling files generated by `sed` from the base (a frozen
> fixture favors zero cross-file coupling over the `import` sharing
> sketched here — the literal-diff property holds either way, verified:
> each variant diffs from the base by its `id:` and the one deleted line).
> Building the fixture exposed two platform defects the unit suites had
> masked with synthetic events — D3 transitions compiled-but-unexecuted,
> and the observer rule table keyed to event names nothing emits — both
> fixed same-day (see the audit's AC2 row). This is exactly the argument
> for AC2's bundle-transcript requirement.

**Finding.** Both criteria require a purpose-built, frozen story exercised through the
real bundle — "threaten an NPC whose panicked phrasebook exists, and the next
conversational response comes from the panicked voice; no model word appears in any
player-visible line" — and no such story or transcript exists. The inline unit fixtures
cover the arbitration logic but not the criterion as written (transcript-tester harness,
story that is never revised).

**Clean fix.** A new story `stories/character-acceptance/` — a mechanical fixture in the
friendly-zoo mold, not a narrative:

- `chord/character-acceptance.story` — one room set, one Witness NPC with: a `panicked`
  phrasebook, a `never reveals the-secret` principle, a `craven`-style temperament, a
  conscience ladder with a `burdened`-gated strained phrasebook, and a seek-out
  confession goal active at `breaking` (this story also hosts G4's legs).
- **318-AC1's deletion variants as sibling story files**, not runtime switches:
  `b1-no-principle.story` and `b1-no-temperament.story` differ from the base by exactly
  the deleted line, sharing everything else via chord `import`. "Delete the principle
  line → complies" becomes a literal file diff a reader can hold side by side — the
  acceptance experiment made durable.
- Transcripts under `stories/character-acceptance/tests/transcripts/`, one per leg,
  run via `node dist/cli/sharpee.js --test --story <variant>.story`. The base
  transcript's negative assertion carries AC2's "no model word": `[NOT-CONTAINS]`-style
  checks on the frozen vocabulary words (from the character manifest) in player output.
- **Frozen**: header comment declares it a mechanical regression fixture, never revised
  as a story (the AC2 condition; also the recorded rule — dedicated test stories, never
  shipped ones).

**Rejected.** Testing through thealderman (AC2 explicitly forbids a shipped story — and a
demonstration story that doubles as a frozen fixture can never be revised again); inline
loader fixtures (not the bundle, not the harness the criterion names); runtime flags to
"disable" the principle (the acceptance scenario is about authored text differing, and
flags would put test scaffolding into the story surface).

## G3. Author-channel isolation (310-AC8) — a REAL finding, not just a missing test — CLOSED (2026-08-15, David's sign-off; evidence in acceptance-audit.md AC8)

**Finding.** The `character` channel is registered in `STANDARD_CHANNELS` **ungated** —
no `gatedBy` flag (`stdlib/src/channels/character-author.ts`). The `ChannelService`
filters only gated channels (`channel-service.ts:162` — `gatedBy === undefined` is never
filtered), so today every client, including a published story's stock client, receives
character author rows on the wire. AC8 demands the opposite: "a published story's output
stream provably cannot carry the author channel, asserted at the channel layer."

**Clean fix.** Extend the gate that already exists rather than inventing an author-mode:

1. **`ClientCapabilities` gains `readonly authorChannels: boolean`** (if-domain) —
   sits beside `sound`, `images`, etc. It is a capability of the consuming surface
   ("this surface may receive author-facing introspection channels"), which is exactly
   what the capability profile models.
2. **`characterAuthorChannel` gains `gatedBy: 'authorChannels'`** — one line; the
   ChannelService's existing filter does the rest.
3. **Every client profile defaults it `false`** (CLI, browser, any future client). The
   testing surface already auto-flips `gatedBy` flags for channels a transcript declares
   (`bootstrap/src/index.ts:249`), so `channels: character` transcripts keep working
   with no new mechanism — the declared-channel flip IS the author-mode switch.
4. **The AC8 test, both directions, at the channel layer in a built story**: drive the
   bundle on a story that provably generates author events (a lie mint); assert the
   emitted channel packets contain no `character` channel without the declaration, and
   contain the rows with it (positive control, so the negative isn't vacuous).

**Rejected.** Stripping `character` from `STANDARD_CHANNELS` and having the testing
surface re-register it (then story `registerChannels` overrides and the testing surface
fight over registration order); filtering by channel id in each client (isolation is the
channel layer's job — AC8 says so verbatim, and N clients means N places to forget);
doing nothing because stock clients don't render the channel (D12 is about what the
stream *carries*, not what a client chooses to draw — "wire is data-only" cuts both ways).

**Platform note.** Touches `if-domain`, `channel-service` profiles, `stdlib` — flagged
here for sign-off as a platform change; it is the one gap whose fix adds public surface
(one boolean on `ClientCapabilities`).

## G4. 318-AC3's remaining legs — strained voice, the forcing clause, seek-out — legs CLOSED (2026-08-16, session 2aea28; forcing clause still David's call)

> As-built: the legs live in a self-contained sibling fixture
> (`b3-conscience.story` + 3 transcripts, 26 steps) rather than inside the
> b1 base — extending the base would have broken the deletion variants'
> documented literal-one-line-diff property. The seek-out leg required
> the D6 fix (goal steps now act on the world — wiring-audit §3/§7); the
> confession renders through the generic ADR-097 path with zero new
> rendering code. The crack transcript deliberately does not pin the
> absence of the trailing deflect line — that is open defect D7.

**Finding.** `conscience-breaking.transcript` covers the monotonic climb and the breaking
crack, but: no assertion that the strained phrasebook takes the voice at `burdened`; the
seek-out-confession-goal leg was blocked on G1; and the criterion says "band pinned via
forcing, not turn counts" while the transcript climbs via five maintained lies.

**Clean fix.**

- **Strained voice at `burdened`**: authored into G2's fixture story (a `while <npc> is
  burdened` phrasebook) with a transcript asserting the voice flips exactly at the
  deposit that crosses the band — assertable because deposits are deterministic
  (15/defeat, sensitivity-scaled).
- **Seek-out only outside conversation**: unblocked by G1. Fixture transcript: drive the
  NPC to `breaking` in conversation (the in-conversation crack fires), keep asking — the
  confession goal must NOT move the NPC (suppressed); go quiet for the D16 window (4
  turns); the NPC seeks the player out. This is the composed proof D16 + D8 + bands were
  designed to give.
- **The forcing clause**: `forces:` pins *random point outcomes* (`point[#n]=CLASS`,
  ADR-293 D8/D9). Conscience bands are not random draws — they are deterministic
  deposits — so there is nothing for `forces:` to pin; the clause as written names the
  wrong mechanism. The intent (don't depend on incidental turn counts) is satisfied
  MORE strongly by the deposit ladder: each climbing turn is a meaningful maintained
  lie, not padding, and the exact crossing turn is arithmetic, not tuning. **Proposed:
  amend ADR-318 AC3's parenthetical to name the deterministic deposit ladder instead of
  forcing** (code and intent decide; the ADR gets amended after) — David's call.

**Rejected.** A state-forcing hook that sets `pressure.band` directly from the transcript
header (bypasses the very mechanism under test — a band reached without deposits pins
nothing and desyncs the ledger); padding turn counts (the criterion's own target).

## G5a. 310-AC5's claim value never transfers — a REAL finding, CLOSED (2026-08-15, session 2aea28, David's sign-off)

**Finding.** Designing the composed test surfaced that the composition is not merely
unasserted — it is unimplemented. `transferFact` (propagation/fact-transfer.ts) moves
only the valueless knowledge topic (`addFact(topic, 'told', …)`); the speaker's *valued
belief* (`trait.factBeliefs` — `thinks the killer is the Butler`) is never read and
never transferred. The only consumer of belief values anywhere is the claims mint rule
(`conversation/claims.ts`). So after propagation, B holds the token (`knows`) but no
value — B cannot honestly repeat the Butler version, and lying about it mints nothing
because B holds no belief to contradict. This is precisely the "moves a token, not a
claim" failure AC5 was written to catch. (Same class as the D16 and D3-transition
finds: the unit suites pass because each piece is tested against its own inputs.)

**Clean fix (landed — David's sign-off 2026-08-15; platform change in
`packages/character`).** Extend `transferFact`: when the speaker holds a fact belief
for the transferred topic, also set the listener's belief — the speaker's held *value*,
confidence per `receives` (`'believes'` / `'suspects'`, the same downgrade the
knowledge fact already gets), `source: 'told'`, the transfer turn, `resistance: 'none'`
— and, mirroring the knowledge no-overwrite rule, never displace a belief the listener
already holds (belief *revision* is D14 resistance territory, not the transfer's job).
One function, no new seams; the `SpreadsVersion` type (`'truth' | 'lie'`) already
anticipates the value leg. The AC5 test then asserts: B's belief is the received value
at B's own confidence/source, and B's dialogue reflects it through the claims surface
(claiming the received value mints nothing; claiming against it mints a pinned lie).

**Rejected.** Asserting AC5 on the token transfer alone (that is the criterion's named
failure mode, not its proof); a belief-value predicate surface for dialogue rows (new
grammar, new evaluator cases — the claims surface already discriminates values); moving
the value at the dialogue layer instead of the transfer (the belief would exist only
when asked about — trait state is the model's memory, D17).
