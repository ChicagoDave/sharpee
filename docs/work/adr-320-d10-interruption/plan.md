## Code findings this plan is grounded in (verified by reading, not re-derived from the ask)

- **The blocker, confirmed**: `packages/character/src/tick-phases.ts` `ensureScene` (~line 1254) returns `undefined` when `sceneWith(world, openerId)` and `sceneWith(world, otherId)` are both set and differ. Step 4a (~1367-1395, thread floor turns) calls `ensureScene(npc.id, ctx.playerId)` with no interruption challenge in between — an NPC's `opens when` thread simply never opens while the player is seated with someone else. `packages/story-loader/src/runtime.ts`'s `ensureThreadScene` (~1882) carries the identical "party seated elsewhere → undefined" refusal for the player-initiated dispatch path.
- **The machinery to extend already exists and already does exactly this for world acts**: `packages/character/src/tick-phases.ts` step 1 (~1291-1298) calls `runtime.resolveIntrusion(scene.id, act.actorId, true)` for every world act in a scene's room; `packages/stdlib/src/actions/helpers/dialogue-selector.ts` `resolveSceneIntrusion` calls the same `runtime.resolveIntrusion(scene.id, context.actor.id, false)` when the player addresses an NPC seated in a foreign scene — **this is the "player's own address... that path works" GH #348 names.** Both go through `packages/character/src/conversation/scene-binding.ts`'s `resolveIntrusion`, which calls `resolveInterruption`/`sceneGrip` (`packages/character/src/conversation/scene-scoring.ts`) and, on any outcome but `blocks`, closes the foreign scene via `closeScene` (`packages/character/src/conversation/scene-runtime.ts`).
- **`resolveInterruption`'s actual logic** (`scene-scoring.ts`): `worldAct: true` always yields (D8 exemption); otherwise the outcome is grip-only — `passive` yields, `assertive` protests, `blocking` blocks — the `challenge.bid` field is carried on the type but **not read** by the switch. This means D10's "passive yields to any motivated interjection" is already satisfied by the shipped function with no threshold math to invent: calling it with `worldAct: false` for an `opens when`-ready thread is the same call the player-address path already makes for a *human* intruder. Phase 0 Q2 below asks David to confirm this reuse is the right shape rather than inventing a new comparison.
- **The `on parting` gap, confirmed broader than this facet**: `on parting` renders in exactly one place today — `packages/story-loader/src/runtime.ts` ~2600-2650, inline in the ask/tell postExecute step, only when the player addresses a *different topic on the same NPC* while that NPC's thread is ACTIVE (the D14 same-pair transition). Every other close path — world-act intrusion (tick-phases.ts step 1), player-address intrusion (`resolveSceneIntrusion`), movement-triggered exit close (tick-phases.ts ~1440), and silence decay (`ageScenes`, tick-phases.ts ~1447) — routes through `closeScene` → `parkActiveThreadsOnClose` (`thread-runtime.ts`), which mutates state and emits a bare `thread-parked` wire event with **no messageId** — nothing renders. This is a pre-existing gap, not unique to D10's new facet, but the W-10 acceptance bar ("`on parting` renders on the hand-off") needs it solved for at least the new opens-when-interruption close. Phase 0 Q1 asks David how far to take the fix.
- **The tick-order finding — a recorded decision, not an accident (corrected 2026-09-02 after plan-review)**: `PluginRegistry.getAll()` runs plugins by **priority descending** (ADR-120 §Plugin Priority Order, `packages/plugins/src/plugin-registry.ts:30`), not registration order. `ActorTurnPlugin` (which hosts the character tick and its step 4a) is priority 100 (`packages/engine/src/actor-turn-plugin.ts:45`); `SchedulerPlugin` is 50. ADR-120's rationale: "NPCs act first — their actions may trigger FSM transitions"; "Temporal events run last — daemons/fuses are background". ADR-328's amendment to ADR-120 kept that relative order when the actor phase became engine-owned. So a partner made `dancing` by a Chord `when <timer> expires` clause is read by the actor phase one turn later **by decision**. What has moved is the premise: ADR-325's Chord timers are story clocks that drive NPC state, not background texture — the rationale no longer covers the case. Reordering is therefore an ADR-120 amendment question with Dungeo's daemons and fuses in the blast radius (they would run before NPCs act), not a bug fix. Phase 0 Q3 surfaces it on that footing.
