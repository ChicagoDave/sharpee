are there any measurement tools for language syntax to evaluate them?

Yes, though nothing gives you a single score. There are three families, and they measure different things.

Grammar metrics (run on the EBNF itself)

Power and Malloy's "A metrics suite for grammar-based software" (2004) adapts code metrics to grammars: counts of terminals and non-terminals, McCabe complexity (decision points per production), average right-hand-side size, Halstead effort, and how tangled the non-terminal dependency graph is. These are mechanical and cheap, and good for tracking a grammar over versions. They measure the parser's burden, not the author's.

Cognitive Dimensions of Notations (Green and Petre)

This is the standard heuristic framework: about fourteen named trade-offs you score a notation against. It's a structured vocabulary for design review, not a measurement, but it's the most useful of the three for a language like Chord. From what I read:

Dimension	Chord
Closeness of mapping	High: create, a room, prose
Abstraction gradient	Deliberately low: no if, no user-defined abstractions beyond traits
Diffuseness	Costly in places: one gerund per on head
Hidden dependencies	Import order as arbitration order
Error-proneness	Mitigated by fix-its on removed forms
Progressive evaluation	Strong, if the IDE delivers room-by-room testing

Empirical studies

Stefik and Siebert's "An Empirical Investigation into Programming Language Syntax" (2013) put novices in front of several languages plus one with randomly chosen keywords. Novices did no better with Perl or Java than with the random one, while Quorum, Python and Ruby did better. Pane and Myers's "natural programming" work did the reverse: they asked non-programmers to describe behaviour in their own words, then compared that to language constructs. Both are methods you can copy, not tools you can download.

Diffuseness, measured

Of 875 on/after clauses, 278 (32%) are identical to a sibling in the same block except for the gerund. That is about 930 lines, or 7% of the code. The worst cases are farmland view and guards checking invites, where 9 of 10 clauses are the same refusal. A gerund list on the clause head would remove all of it.

Defects in the EBNF file

Parsing it strictly turned up four problems. They matter because the file is hash-pinned to the language version and served for download.

KIND-NOUN loses three kinds. A comment opens mid-rule and swallows | "container" | "supporter" | "region" ;, terminator included.
create-line loses three alternatives. The same thing happens to feels-line, knows-line and thinks-line.
define-conversation is orphaned. It is defined, but missing from the declaration list.
The header comment nests. It contains a (* … *) inside itself, so the file only tokenizes if comments nest.
