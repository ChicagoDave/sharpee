# Session Plan: GH #414 — meta commands work after an ending, and the browser client stops re-stranding the player

**Created**: 2026-09-11
**Plan Status**: ACTIVE
**Overall scope**: Three stacked defects behind one symptom (typed `restart` dies at end-game, reload doesn't help). Phase 1 fixed the engine so a `stopped` engine accepts meta commands (ADR-345 **D15**). Phases 2-5 implement **ADR-347** — the ending becomes an explicit concept — which is where GH #414's remaining two defects are fixed. **Rewritten 2026-09-11 (session aceb2e) after ADR-347 was accepted**: the original single Phase 2 gated the browser autosave at its call site, which ADR-347's Q-1 ruling declined in favour of fixing defect 2 through the concept. One phase became four because the decision spans `if-domain`, `world-model`, `stdlib`, `engine`, `story-loader` and `platform-browser`.
**Bounded contexts touched**: Phase 1 was engine lifecycle only — no domain modeling. **Phases 2-5 are domain modeling**: ADR-347 introduces the Ending as an explicit concept owned by the world, which is a new member of the domain language rather than a guard against an existing one. That change was made after the plan was first written, and this line is corrected rather than left saying N/A.
**Key domain language**: the **Ending** (`IStoryEnding` — kind, turn, messageId, cause; absent while play continues) and its declaring verb `endStory`; `EnginePhase` (`empty`/`ready`/`playing`/`stopped`) as the separate *permission* fact; meta command vs. regular command; turn route (`context.route`); channel packet (ADR-163); autosave envelope.

## Phases

### Phase 1: Engine — a `stopped` engine accepts a meta command, refuses everything else
- **Tier**: Medium
- **Budget**: 250
- **Domain focus**: `GameEngine.executeTurn` and the turn-stage router (`packages/engine/src/turn/runner.ts`, `stages.ts`, `parse.ts`) — the `EnginePhase` guard ADR-345 D2 put in place, now narrowed by D15 (added this session).
- **Entry state**: ADR-345 **D15** (added this session) states the ruling: a turn whose parse resolves to a meta command is accepted in `stopped`; world-mutating commands stay refused; `stopped` remains terminal and `restart` remains engine disposal. `executeTurn`'s current guard (`game-engine.ts:908-914`) refuses every turn while `stopped`, so `metaCommandStage` (`turn/meta-command.ts`) never runs at end-game.
- **Deliverable**:
  - `executeTurn` no longer refuses outright on `stopped`. It runs the turn far enough to parse and route (`SHARED_STAGES` through `parseStage`, which is the same shared prefix a meta command already runs through while `playing` — `undo-snapshot`'s `MetaCommandRegistry.isNonUndoable` already skips snapshotting for `restart`/`restore`/`quit`/`undo`/`save`, so no new snapshot-while-stopped case is introduced). If `context.route === 'meta'`, the turn continues into `META_STAGES` and the meta command runs exactly as it does while `playing`. If the route is not `'meta'` (a regular command, or a failed parse), the turn is refused at that point with the existing `stopped`-phase message ("The game has ended; call resume() to continue.") — refusal fires before `executeCommandStage`, so no world-mutating stage ever runs against a stopped engine.
  - Verify (do not assume) that `RESTART`, `RESTORE`, `QUIT`, `UNDO`, `SAVE` all route to `META_STAGES` from `stopped` the same way they do from `playing` — confirmed pre-session reading of `MetaCommandRegistry`'s default set (`packages/stdlib/src/actions/meta-registry.ts`) that all four are already registered; this phase re-confirms via a real-path test rather than by re-reading the registry.
  - Update the ADR-345 AC-2 rejection test for `executeTurn` (the one asserting a blanket `stopped`-phase refusal) so it pins the narrowed behavior instead of contradicting it — the AC-2 pin becomes "refuses a *regular* command while `stopped`," not "refuses every command."
  - `docs/architecture/adrs/adr-345-the-engine-lifecycle-phase-is-an-explicit-concept.md` D15 and AC-10 are already written (this session) — this phase's commit lands the code they describe; reconcile wording if the code diverges from what was drafted.
- **Exit state**: A `stopped` `GameEngine`, driven directly (no client), accepts `restart`/`restore`/`quit`/`undo`/`save` and refuses `look`/`take X`/any non-meta input with the existing message. `pnpm --filter '@sharpee/engine' test:ci` green. Dungeo walkthrough chain still 952/952 (an ending transcript reaching `stopped` and then issuing a meta command is new coverage the chain did not previously exercise — confirm whether `endgame-victory.transcript` or a sibling already types a post-ending command, and if none do, that gap is this phase's to close with a real transcript assertion, not a unit-test substitute, per rule 13a).
- **Status**: DONE (2026-09-11, session aceb2e)
- **Outcome**: `executeTurn` refuses only when the phase is not `playing` *and* the input is not something a stopped engine accepts; `acceptsWhileStopped` answers that before any stage runs, and refuses outright while an input mode is active. `resolveRoute` extracted from `parseStage` so the meta/turn rule has one implementation and two callers. `loadSaveData` and `undo()` return a *stopped* engine to `playing` over the existing back-edge. Gates, all green 2026-09-11: `pnpm typecheck` 77/77, `turbo run test:ci` 76/76, Dungeo walkthrough chain 952 passed in 17 transcripts (all goldens matched), `pnpm test:scripts` 14/14, `@sharpee/engine` 796 passed / 7 skipped (+6), `@sharpee/bootstrap` assemble-restart 4/4 (+1). Every new assertion mutation-probed in both directions.
- **`mutation-verification` findings, all three real and all three fixed**:
  1. The first undo-snapshot test proved nothing — it drove `look`, which is in `MetaCommandRegistry`'s non-undoable list (`meta-registry.ts:185-195`), so the stage skips it in every phase regardless of this change. Rewritten against `north`.
  2. An input mode still active at the ending would have consumed the line: `input-mode` runs *before* `parse` and `stop()` never clears the mode, so a line parsing as a meta command reached the handler — an unconstrained world write — before the route was consulted. `acceptsWhileStopped` now refuses while a mode is active, which also removes a chain-splitting divergence against `chainStage`.
  3. **RESTORE at the end-game prompt reproduced GH #414 one level deeper.** `loadSaveData` replaced the world but never touched the phase, so a restore loaded a live save into an engine that still refused every command — worse than the pre-change behavior, which refused `restore` outright. Fixed at `loadSaveData` and `undo()`, conditional on `stopped`: D8a's tolerance covers `playing` but not `ready`, and hosts do restore into an engine they never started (15 tests in the package do).
- **Owed**: the resume-on-restore/undo rule is a lifecycle behavior ADR-345 does not yet state. It uses the existing `stopped → playing` back-edge rather than adding one, so D10/D11 are unaffected — but it wants a D15 amendment line if David rules it in.
- **Corrections to this phase as planned**: (1) The ADR-345 AC-2 test needed **no** change — `engine-resume.test.ts:24` pins `executeTurn('look')`, a *regular* command, which is still refused; the plan assumed it pinned every command. (2) The planned "run `SHARED_STAGES` through `parseStage`, then refuse at the route switch" shape was **rejected on evidence**: `undo-snapshot` writes a snapshot, `turn-start` emits `turn:start`, and `input-mode` can advance the turn — all before the route is known. Refusing there would let a dead world overwrite the player's undo state. The refusal is therefore asked before any stage, at the cost of one extra parse on the accepted path.

### Phase 2: The concept — `IStoryEnding`, the world member, and the declaring verb
- **Tier**: Medium
- **Budget**: 250
- **Governing decision**: ADR-347 D1, D2, D2a, D2c, D2d. **Read the ADR before starting**; its D2d pins all three contracts, so none of them is this phase's to invent.
- **Domain focus**: `packages/if-domain/src/endings.ts` (the record type), `packages/world-model` (the member, its accessor, its serialization), `packages/stdlib` (the verb).
- **Entry state**: the ending exists as four unowned vocabularies — the world flag `STORY_ENDING_FLAG`, `story.victory`/`story.defeat`, `game.won`/`game.lost`, and `Story.isComplete()`. Nothing owns it.
- **Deliverable**: `IStoryEnding` beside the existing types in `endings.ts`, which stays types-only. A first-class `WorldModel` member with its accessor and serialization wiring, on the `getPlayer()`/`setPlayer()` precedent. `endStory(world, kind, opts?)` in stdlib beside `killPlayer`, setting the Ending and returning the blessed event, with **first-ending-wins** as its rejection rule (`killPlayer`'s idempotence precedent, `engine/src/turn/detect-death.ts:26-28`). No consumer is switched over in this phase.
- **Exit state**: AC-1, AC-3 and AC-4 satisfied. `pnpm typecheck` 77/77; the walkthrough chain unmoved at 952, because nothing reads the new member yet.
- **Status**: PENDING

### Phase 4: The restore seam, and Phase 1's patch retired
- **Tier**: Medium
- **Budget**: 200
- **Governing decision**: ADR-347 D3, D4, D4b; amends ADR-345.
- **Entry state**: Phase 3 merged. `loadSaveData` and `undo()` still carry Phase 1's `if (this.phase.name === 'stopped') this.resume()`.
- **Deliverable**: the phase derives from the Ending at the restore seam — a save carrying an Ending restores stopped, one without it restores to play. Phase 1's patch is **deleted**, not joined. `stopped` keeps its meaning and stays overloaded (D4). **ADR-345 is amended in this phase's commit** (D4b): D15's text stops describing the retired patch as a standing rule, and D9 gains a pointer to ADR-347.

### Phase 5: The client — GH #414 defects 2 and 3
- **Tier**: Medium
- **Budget**: 250
- **Governing decision**: ADR-347 D3a, D2d's channel contract.
- **Domain focus**: `packages/stdlib/src/channels/standard.ts` (the new state-mode sibling), `packages/platform-browser/src/BrowserClient.ts` and `src/channels/`.
- **Entry state**: Phase 4 merged. The browser receives the ending as **prose** on the `endgame` channel (`standard.ts:504`, `contentType: 'text'`, rendered at `platform-browser/src/channels/index.ts:206`) and can print it but cannot act on it.
- **Deliverable**: a state-mode channel sibling carrying `IStoryEnding` — `endgame` keeps its text payload untouched, because widening it would delete rendered output and move the goldens (D2d). The browser drives the input box's disabled state and an end-game prompt from that record, never from prose, and restores the normal state when the Ending clears. Any new prose is a `lang-en-us` message id, not a string in `platform-browser`.
- **The autosave fix is NOT what Phase 2 originally planned, and this is the clearest place the concept changed the answer.** The old plan gated the autosave so an ended world was never persisted, restoring the player to their last live turn. With the Ending explicit, the honest fix is the opposite: **persist the ended world, restore it faithfully, and present it correctly** — the reload lands at the end-game prompt, where Phase 1 already made `restart` and `restore` work. Suppressing the save to dodge a loop was a workaround for not being able to represent the state; the state is now representable.
- **Exit state**: AC-6 satisfied, its two premise checks first (the sibling fires; the client disables with prose mocked empty), then the chain at 952. A real-path test per rule 13a — a genuine ending driven through `executeTurn`, asserting the persisted envelope and the DOM, not mocks.
- **Status**: PENDING

## Advisory finding from `plan-review`
**[TENSION] Phase 1's refusal is conditional-mid-pipeline, not up-front.** ADR-345 D2's general sentence is "one guard per method, so there is no order," and Phase 1 moves `executeTurn`'s refusal to *after* parse/route resolution. D15 is the ADR's own carve-out for exactly this, on the same footing as D8/D8a's named exceptions, so it is not a contradiction — but keep the refusal's shape visibly tied to D15 with a code comment at the guard, the way D8/D8a's exceptions are commented in `game-engine.ts`, so a future reader does not mistake it for D2 eroding generally.

## Workarounds this plan leaves alone
`transcript-tester` (`packages/bootstrap/src/index.ts:377-379`) and `branch-tester` (`packages/branch-tester/src/tree-walker.ts:332,360`) call `resume()` by hand after a `stopped` engine, tolerated per ADR-345 D8a specifically because `branch-tester` calls it unconditionally on every tree line. Neither workaround is retired by this plan: Phase 1 makes `stopped` accept meta commands, it does not change what `resume()` itself accepts or make `resume()` unnecessary for a harness driving a tree that dies mid-branch and keeps going. D8a's tolerance stays exactly as ruled.

## Not in this plan
- No change to `stdlib`'s `MetaCommandRegistry` — verified during Phase 1 investigation that `restart`/`restore`/`quit`/`undo`/`save` are already registered defaults; if that verification surfaces a gap, it is a Phase 1 finding to report, not a silently-added fourth phase.
- No `lang-en-us` phase of its own — if Phase 2's end-game prompt needs new prose, it is a small addition inside Phase 2's budget, not a separate session-sized unit.
