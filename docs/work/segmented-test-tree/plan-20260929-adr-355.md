## Findings that differ from the ADR (see report to David)
1. Every tree document is at `version: 2` (ADR-356 D4 already moved `TREE_DOCUMENT_VERSION` to 2), not `version: 1`. Version becomes 3.
2. Nine artifacts exist, not six: the ADR's six plus `packages/devkit/tests/fixtures/derived-fail/derived-no-vocabulary.tests.json`, `packages/devkit/tests/fixtures/derived-pass/derived-skip.tests.json`, `docs/work/john-chord-samples/no-signal-home.tests.json`.
3. secret-letter has grown to 783,119 bytes: 1,470 cards, 54 fork points, 105 branches, depth 6, seed 1209, so 157 segments (root + 105 branches + 51 continuations; 3 of the 54 forks end their line and have none) — not 79 / 639. AC-2 and the End-to-End Scenario are stated on the 2026-09-22 numbers; tests must assert the rule (segments = forks + branches + 1; sum of cards preserved), with counts computed from the source, not hard-coded.
4. The run column keys on a derived label carried in the run-event wire's `file` field. Segmenting the file does not by itself stop keying on labels; #494 closes only if the wire and the column key on a line id (Phase 3).
5. The surface posts the WHOLE serialized document on every mutation (`{document:{text}}`, both hosts). Per-segment writes need a new bridge shape or the host rewrites everything and D1's purpose (small git diffs) is lost.
6. A fork-point run needs a parent-resume representation: 54 forks yield 54 "continuation" segments that are not branches. The ADR's "fork ordinal" is read here as the child's index among the fork's alternatives (0 = the main continuation, 1..n = branches in creation order); this also carries sibling order.

## Phase 1 design, as built (2026-09-29, session e31b07)
- **Line identity** is the id of the segment a line BEGINS with (the root for the main line, the branch segment for a branch), not its leaf: a line's later continuation segments come and go as forks are added and removed, its head never does. `TreeLine.id` / `parentId` carry it; `ordinal` (1-based sibling position) is kept for the room-less label fallback only.
- **Ordinal** is written from sibling position on every write (0 = continuation, 1..n = branches). The old numeric `branch` field is gone: one secret-letter fork holds its branches out of numeric order, so reusing those numbers as ordinals would have reordered it. Cost, stated in the module header: removing a branch rewrites its later siblings' files by that one field.
- **Model fields**: `TreeDocument.id` (root segment), `TreeBranch.id` (replaces `branch: number`), `TreeCard.continuation` (model-only, persisted as the continuation segment's own id). `ensureSegmentIds` allocates missing continuations in place; `segmentTree` is pure and throws on a model missing one (writer bug); `assembleTree` never throws; `diffTreeFiles` gives writers the changed files and removals.
- **Empty continuations are never written**, and the reader rejects one — it accepts exactly the canonical form the writer emits. Dotfiles in the directory are ignored.
- **Early AC-9 probe** (scratch, nothing written): all nine real trees segment and reassemble with identical cards, order and seed, and re-segment byte-identically. secret-letter: 157 segments, largest 35,127 bytes.
