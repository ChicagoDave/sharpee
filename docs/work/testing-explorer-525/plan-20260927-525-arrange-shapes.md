# Session Plan: teach the ADR-356 derived rule-test runner the next arrange shapes, ranked by secret-letter's SKIPPED count

**Created**: 2026-09-27
**Plan Status**: ACTIVE
**Overall scope**: GH #525 ranked the ADR-356 derived suite's SKIPPED-by-shape counts on secret-letter (721 branches, 358 exercised, 363 SKIPPED) to decide which non-floor arrange shape the arrange step learns next. This plan covers four of those shapes — `condition-not-and` (50), `condition-or` (17), `condition-condition` (15), `timer-phase` (25), 107 of the 363 rows — in two phases: Phase 1 extends `branch-tester`'s derived-runner planning logic alone (named-condition expansion, an `or`-must-hold witness rule, an `and`-must-fail two-pass check); Phase 2 amends ADR-356's D2 arrange floor to add a timer-phase read and write across `story-loader`, `transcript-tester`, and `branch-tester`. `command-none` (90) and `no-claims` (52) are explicitly not arrange gaps per GH #525's own body and stay out of scope. `subject-unreachable` (36) is a different bug family (GH #242's entity-topic scoping) and is not addressed here. `occurrence` (4) is deferred — Q-2's floor already SKIPs it by design and GH #525 ranks it last. **No implementation is authorized by this plan.** CLAUDE.md gates every `packages/` change on discussion first; David has given go for planning and for Phase 1's design (recorded below), but not yet for either phase's implementation — his explicit go-ahead is required before Phase 1 starts, and again before Phase 2 starts.
**Bounded contexts touched**: `@sharpee/branch-tester` (both phases — the derived-runner's precondition-to-arrange-term mapping and its arrange/check loop); `@sharpee/story-loader` (Phase 2 only — `arrange()` gains a timer-phase write); `@sharpee/transcript-tester` (Phase 2 only — the assertion core gains a timer-phase read, per ADR-340 D3's one-evaluator rule).
**Key domain language**: arrange floor (ADR-356 D2), SKIPPED shape, precondition, `ArrangeTerm`, witness (the operand chosen to prove an `or`), `TimerRecord` phase (idle/running/stopped/expired).

## Phases

### Phase 1: `branch-tester`'s derived runner learns named-condition expansion, the `or`-must-hold witness, and the `and`-must-fail two-pass check
- **Tier**: Medium
- **Budget**: 250
- **Domain focus**: `@sharpee/branch-tester`'s `derived-runner.ts` — `conditionTerms` (precondition-to-`ArrangeTerm` mapping, no IR threading yet) and `runDerivedBranch`'s single-pass arrange/check loop. No ADR amendment, no floor change — this phase teaches the runner to compose floor forms it can already write, not to write a new one.
- **Entry state**: ADR-356's first cut is DONE and merged (`docs/work/archive/testing-explorer/plan-20260925-520-adr356-first-cut.md`). `conditionTerms` returns `condition-not-and` for any `and` with `holds=false`, `condition-or` for any `or` with `holds=true`, and `condition-${kind}` (i.e. `condition-condition`) for a named condition (`{kind:'condition', name}`) — all three SKIP today. `runDerivedBranch` arranges every `mustHold` term in one pass via `arrange()`, then checks every `mustHold=false` term via `evaluateStateExpression` in the same pass, which lets a later write invalidate an earlier check (latent ordering bug, not currently observed but a prerequisite to fix before adding a check that depends on every write being done first). Secret-letter and fernhill measured 2026-09-27: 721/358/12/363 and 33/63 respectively. David's go-ahead for Phase 1 implementation obtained.
- **Deliverable**:
  1. **Named-condition expansion**: `conditionTerms` gains an `ir: ChordIR` (or equivalent) parameter, threaded from `planBranch`; the `condition` case looks the name up in `ir.conditions` (`IRNamedCondition[]`, `{name, open, condition, span}`) and recurses into `conditionTerms(found.condition, holds, subject)` — `it` stays bound to the existing `subject` parameter, unchanged.
  2. **`or`-must-hold witness**: when `holds=true`, walk `condition.operands` left to right, return the **first** operand whose `conditionTerms(operand, true, subject)` yields terms (no `shape`) as the term list for the whole `or`; SKIP with `condition-or` only if every operand fails to map. State the witness rule as a header comment on the function: leftmost mappable operand wins, not "cheapest" or "first floor form regardless of position" — deterministic and simple to explain in a SKIPPED detail line if ever revisited. Note the rejected alternative in the same comment: one enumerated leaf per operand (multiple derived tests per `or` clause branch) was rejected because it changes ADR-356 D1's one-test-per-clause-branch denominator, which is out of this plan's scope to reopen.
  3. **`and`-must-fail (`some-fails`)**: a new `ArrangeTerm` kind carrying the per-operand term lists of an `and` that must fail (`condition-not-and`'s current case). Split `runDerivedBranch`'s single loop into two passes: pass one performs every `mustHold` write via `arrange()`; pass two, after all writes land, evaluates every `mustHold=false` pin via `evaluateStateExpression` (fixing the latent ordering bug as a byproduct) and every `some-fails` term by checking that at least one operand's terms fail to hold in the now-arranged world. No witness is chosen among the failing operands — this matches the runner's existing "never write a negation" policy; SKIP with `negation` naming the `and` only when every operand holds (mirrors the existing `negation` SKIP for a single term that already holds, line ~806).
  4. Tests: `derived-plan.test.ts` (planning-only, no engine) and `derived-runner.test.ts` (end-to-end arrange+run) under `packages/branch-tester/tests/`, using fixtures in `packages/branch-tester/tests/fixtures/derived/` (a `reach.story` fixture already exists there — extend it or add a sibling fixture covering: a named condition referenced with `it`, an `or` of two `is-in` operands where only the second is arrangeable, an `and` of three predicates that must refuse).
- **Exit state**: `pnpm --filter '@sharpee/branch-tester' test:ci` green. `./sharpee test branch-stories/secret-letter` and `./sharpee test branch-stories/fernhill` re-run and reported with the exact command and date; expected (not asserted in advance — report the real numbers): roughly 42 of the 82 `condition-not-and`/`condition-or`/`condition-condition` rows convert to exercised, and the 40 `wary`-trait rows that were `condition-not-and` relabel as `timer-phase` SKIPs (their fourth guard is a timer read Phase 1 does not add) rather than converting — so `timer-phase`'s SKIPPED count rises from 25 toward ~65 even though Phase 1 touches no timer code. State this shift explicitly in the report so it isn't mistaken for a regression.
- **Status**: DONE (2026-09-27, session 814e84)

The three condition shapes went to zero (82 rows) but the expected timer-phase relabel did NOT happen — planning names claims and command shape before any run-time read, so the `wary` rows stop at `command-shape` (`talking` has no one-object pattern): command-shape 22→53, no-claims 52→74, subject-unreachable 36→51, timer-phase 25→26, subject-offstage 14→16, negation 4→6. ### Phase 2: the arrange floor learns timer phase (ADR-356 D2 amendment)
- **Tier**: Large
- **Budget**: 400
- **Domain focus**: cross-package floor amendment — `@sharpee/transcript-tester`'s assertion core (read), `@sharpee/story-loader`'s `arrange()` (write), `@sharpee/branch-tester`'s runner (stop SKIPping `timer-phase`). Touches the ADR itself (D2 floor list, Q-2 amendment note) and `arrange.ts`'s header.
- **Entry state**: Phase 1 DONE and measured (2026-09-27). **Re-estimate before starting**: Phase 1's measurement shows only 26 secret-letter rows SKIP as `timer-phase`, not ~65 — the `wary`-trait rows stop earlier at `command-shape`, which no timer work touches. Phase 2's honest expected gain is the 25 `refused escape-no-time` rows plus one. `pin-grammar.ts` already parses `<timer> has started|expired` into `{kind:'timer-phase', timer: <qualified>, what}` (line ~130); `conditionTerms`'s `timer-has` case already emits this exact pin text using the IR condition's `timer` field, which is already the timer's `qualified` key (`ir.ts:1281`, `1627`) — so no name-mapping work is needed between the IR's timer identifier and the pin's timer text; they are the same string. `state-keys.ts` defines `TimerRecord {phase: idle|running|stopped|expired, index, startedTurn}` at `chord.timer.<qualified>` (`timerKey(qualified)`). `assertion-core.ts` states explicitly (header ~425-440) that no read is defined for timer phase; `derived-runner.ts` line ~801 SKIPs `pin.kind === 'timer-phase'` for exactly that reason. David's go-ahead for Phase 2 implementation obtained (separate from Phase 1's).
- **Deliverable**:
  1. **Read**: `evaluateStateExpression` in `assertion-core.ts` gains a case for a `timer-phase` pin — reads `TimerRecord` at `timerKey(pin.timer)`; `started` = `phase !== 'idle'`; `expired` = `phase === 'expired'`. Lands beside the existing Chord-form cases, imported by branch-tester per ADR-340 D3 — not duplicated in the runner.
  2. **Write**: `arrange()` in `story-loader`'s `arrange.ts` gains the `timer-phase` case: `started` sets `{phase: 'running', index: 0, startedTurn: <current turn>}`; `expired` sets `{phase: 'expired', ...}` (index/startedTurn per whatever the running-to-expired transition already implies — check `timer.ts`'s own phase-advance logic rather than inventing new semantics). Remove `timer-phase` from arrange.ts's header list of the four non-floor shapes it does not write (now three: `occurrence`, `topic-history`, `timer-position`).
  3. **Runner**: `derived-runner.ts` line ~801 drops `timer-phase` from the unreadable-pin list; a `mustHold=false` timer-phase pin is now checked via the new read, not SKIPped.
  4. **ADR amendment**: append a dated amendment note to ADR-356 D2 (and Q-2, since Q-2's ruling named timer-phase as SKIPped by design) recording that the floor now includes timer phase, per rule 9's "constrains future sessions" bar and ADR-356 D9's pattern of a note owned by the phase that lands the change.
  5. Tests: `story-loader` (arrange writes both phases correctly, round-trips through save/restore since `TimerRecord` is ordinary world state), `transcript-tester` (assertion core reads both phases, plus the existing structural D3 test still passes with the new case added to the shared evaluator, not the runner), `branch-tester` (a derived test that arranges `<timer> has expired` and asserts a refusal governed by it now exercises instead of SKIPping).
- **Exit state**: all three packages' `test:ci` green. `./sharpee test branch-stories/secret-letter` and `./sharpee test branch-stories/fernhill` re-run and reported with the exact command and date; expected (report the real numbers): the ~40 `wary`-trait rows Phase 1 relabeled as `timer-phase`, plus the original 25 `market-escape` timer-phase rows (all `refused escape-no-time`), convert to exercised — roughly 65 of secret-letter's 363 SKIPPED rows clear. ADR-356's D2/Q-2 amendment note is committed alongside the code, not left for a later session.
