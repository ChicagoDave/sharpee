# The pure web application for Chord Writer — the evaluation's decision record, and the four-way comparison completed

**This is a recommendation, not a decision.** ADR-341 D2's toolkit ruling (WPF, David, 2026-09-12) stands until David rules otherwise, and the OpenSilver and Avalonia records' own recommendations are held rather than withdrawn. What this record adds is the fourth and last body of evidence, a per-control comparison across all four spikes, and a recommendation with its grounds in weighted order and the counter-case written out. **It also resolves the condition the Avalonia record left open** — its §7 was explicitly provisional against a pure web application that "still has no spike," and its §9 named "if the pure web application spikes well" as a thing that would change it. It spiked well. §7 below says what that means and §8 says what it costs.

**Written**: 2026-09-15, session e3fbf7, on `main`. **Sources**: `plan.md`, `phase-0-prerequisites.md` through `phase-6-shell.md`, `parity-table.md` (this directory) and their evidence under `evidence/`; `docs/work/avalonia-ide-evaluation/decision.md`, `docs/work/opensilver-ide-evaluation/decision.md`, `docs/work/archive/adr-341-spike/decision.md` (the three prior records); `docs/work/web-chord-writer/options-20260913-web-app-shapes.md` §6 (the judging frame) and `brainstorm-20260813-web-chord-writer.md`. Spike code outside the repository at `/Users/david/repos/spikes/web-ide/`. All Phase 0–6 evidence was gathered 2026-09-14/15 on this Mac, in Edge 153.0.4234.32, with Safari 26.6.2 and Firefox 155.0.1 cross-checks where a phase ran in more than one engine.

**Fresh check at write time** (this session):

```
$ ./sharpee test branch-stories/fernhill/fernhill.story --tree
  11 line(s) … 86 cards passing, 104 assertions passing

```

That is the exact baseline the in-page walker matched in three browsers, and fernhill is byte-unchanged since Phase 0 (`069f424d…fe4de6`, `git status --short branch-stories/fernhill` empty).

**What was evaluated**: a page. No installer, no process, no vendored toolchain, no host application — the IDE *is* the document, with the author's real folder reached through the File System Access API where the browser allows it and the origin private file system everywhere else. Scope ruling, David 2026-09-14: strictly O1/O2, nothing installed, **no local companion process** (O3 out of scope; a phase that reached for one would have found a finding, not a fallback). Cloud adapters were named as known cost and deliberately not built.

## 2. Three predictions this evaluation corrects

**The Avalonia replay over-run was not a defect.** That record carried "274 turn records and 12 `forkBoot`s where OpenSilver saw 31 and 1 … the settled document is correct; the path is not" as an open item inside the Testing surface — a product differentiator. On a host with no relay, no process boundary and no second heap, the number reproduces **exactly**, and every term is measured: the surface's driver types `restart` into the live client for each of eleven fresh boots (a real turn, then a fence) and replays the active line once more at the end so the board is left live on it. 222 + 11 + 30 = 263 turns, + 11 fences = 274. **The over-run was correct behaviour; OpenSilver's 31 was the under-run** — that host never fresh-booted the ten branch lines, which is why its count sits near the main line's 29 commands. Avalonia's 12 `forkBoot`s against this host's 11 is a single extra boot and is the one piece this evidence cannot settle from here. Commented on GH #462.

**The options doc's `esbuild-wasm` estimate was 29% low.** ~10 MB was the figure the whole Publish argument rested on; it is **12.88 MB**. That does not change the conclusion — it is paid once, at first Publish, and never during writing, playing or testing — but a decision record that carried the estimate forward would be pricing the wrong number.

**The plan's own hypothesis about the testing harness was wrong.** It expected `runner.ts` to be "the one node-bound file" in `@sharpee/branch-tester`. `packages/branch-tester/src/` imports **no** node builtins at all: the walker, the tree-document model, auto-assertion and the channel assertions are already browser-clean. What blocks a browser build is the **barrel**, which re-exports `@sharpee/transcript-tester`, which re-exports `watch`, `golden`, `coverage`, `search` and `story-loader` — 25 unresolvable imports for four functions. That makes GH #463 a packaging gap rather than a port, which is a much smaller and much more actionable thing.

## 3. The editor, and what D4 means when there is no native control

Four spikes, one 1755-line file, four numbers that measure four different things:

- **WPF, 14.8–15.9 ms** — tree-sitter parse plus a whole-document query, against a Chord grammar **that does not exist** (ADR-182 unimplemented since 2026-06-19).
- **Avalonia, 7.96 ms** — the compiler's lexer out-of-process under the vendored Node, of which **0.49 ms is the lexer** and the rest is an unoptimized pipe and an unoptimized index.
- **OpenSilver, 0.92 ms** — the compiler's lexer bundled into a page, in an iframe, in a web view, in a XAML app.
- **Web, 0.82 ms** — the same lexer, the same editor, in the page. The ~0.1 ms difference from OpenSilver *is* the host tax.

**ADR-341 D4 specifies two native editors consuming one tree-sitter grammar. This shape satisfies neither half of that sentence and satisfies what the sentence was reaching for.** There is no native control, and there is no second editor to keep in step, because there is no second codebase: one editor, one grammar, and the grammar is the compiler's own rather than a tree-sitter port that has never been written. The honest statement for an ADR is that **D4 would be rewritten, not met** — and that all three non-WPF shapes rewrite it, in three different directions: OpenSilver gave up "native" to get "one grammar," Avalonia got both, and this shape makes "native" meaningless by not having a control at all.

The qualification both prior columns carry does not apply here: there is no third copy of a keyword list, because the display list and the grammar are the same bundle.

What is not settled, and cannot be settled by measurement: **whether an author accepts a browser tab as the place they write.** The Avalonia record called its felt comparison load-bearing because a Skia-rendered Mac app replaces AppKit. This one is load-bearing for a blunter reason — every author already has strong, unexamined feelings about what a browser tab is for, and a 0.82 ms style pass does not touch them.

## 4. The kill question, and the fork it leaves

This evaluation's kill phase was storage, not rendering — the structural difference from every prior evaluation. The answer is split, cleanly, and the split is the product question.

**On Chromium it is better than the options doc predicted.** `showDirectoryPicker()` opens fernhill's real folder; the `FileSystemDirectoryHandle` persists to IndexedDB and survives a structured clone; a reload reacquires it **silently**; the first browser restart asks once more with a dialog that **names the folder rather than re-picking it** and offers "Allow on every visit"; every restart after that is silent (`granted`, 1.6 ms, no UI). A real write was verified from outside the browser and the fixture restored by hash. **The author is asked twice, ever** — where the options doc assumed a recurring reprompt.

**Off Chromium it is not a degraded version of that; it is a different product.** Safari 26.6.2 and Firefox 155.0.1 do not have the API at all — a clean `TypeError`, checked firsthand in both directions on this machine rather than read off caniuse. So the project lives in the origin private file system, which was proven as a genuine working copy rather than a fallback: a reproducible archive wiped-and-imported per-file-identical in all three browsers, exported back to a byte-identical-per-file archive, re-opened in the page **and** decoded and unzipped outside the browser in Node. The same compose → play → test call path runs unchanged over it in all three engines.

Three consequences that should not be blurred.

**ADR-280 A1's promise becomes tier-dependent.** "The story's own title names a real, editable folder at `~/Documents/<Story Title>/`" holds on Chromium and cannot hold in Safari, where no Finder path exists for OPFS. That is options doc **Q3**, and it is David's ruling, not a gap engineering can close.

**One grant is not durable in the way the headline suggests.** A stored handle vanished across a ~70-minute gap on an origin where `persisted: false` — the IndexedDB database survived, its one record did not (GH #461). `navigator.storage.persist()` was never called, which is the likely cause and is actionable, and **unproven**. Until it is proven, "the author is asked twice, ever" is a measured best case rather than a guarantee.

**The browser matrix maps onto the platform split that already exists, which is the strongest argument this shape has and the one most likely to be over-read.** Windows and Linux authors reach the Chromium tier by default; macOS authors already have a native Chord Writer. The residual is a macOS author who wants the web product in Safari — who gets OPFS with an import/export door, which is a real product, just not the same one. That mapping is an argument for the recommendation in §7, not a proof, and §8 says why.

## 5. D3's contract does not arise, and that is worth stating precisely

The largest single finding in *both* prior evaluations was the host contract for web panes. OpenSilver spent its Phase 2 on custom schemes and a `PaneBridge` shim; Avalonia's kill question **failed on the mechanism** — no response-supply door exists on the macOS backend at all, across 900 assembly types — and was answered instead over a token-scoped loopback origin, which is a network listener on the author's machine.

None of it arises here. The IDE page and the pane are the same document. There is no response to supply, no scheme to register, no port to bind, no token to scope, no `Range` to answer and no host shape to counterfeit — the client already runs in a browser, which is what it was written for. The shipped surface bundle loaded **byte-identically** (`sha256 cd46afaa…c3591`) and the entire Swift side of the round trip reduces to a fifteen-line object.

**The parity table records this as `void` rather than `PASS`, deliberately.** A void cell is a dimension answer: the question does not exist for this shape. Recording it as three rows quietly passing would overstate what was built and understate what was removed.

**One piece survives and is load-bearing under every shape**: `@sharpee/platform-browser`'s `turn-events.ts` and the IDE surface both look up `window.webkit.messageHandlers` **by name**, and gate behaviour on its presence. Every non-WKWebView host supplies that object — both prior spikes did, and so does a browser, where there is no host to impersonate. That is GH #464, and D3's contract module should own the post door under whichever shape wins.

## 6. Where the weight went: no toolchain, one big asset, and offline as the obligation

Both .NET shapes ship a **175 MB vendored Node toolchain** per architecture, resolve it by path, sign it, keep its seal through packaging, and give it its own entitlements. Velopack's inability to seal a macOS bundle shaped that way is the Avalonia record's worst row, and the fix is unpriced work outside Velopack.

This shape has no toolchain. What it has instead:

| | Weight | When it is paid |
| --- | --- | --- |
| The app's own bundle | 737 KB (Phase 5's page); 1.33 MB compose + 3.31 MB play unminified in Phase 2 | first load, then cached |
| Platform payload (21 `@sharpee/*` + 5 `ext-*` + 3 deps, 1,127 files) | **1.95 MB zipped**, 5.89 MB raw, unpacked in 40 ms | first load, then cached |
| `esbuild-wasm` 0.27.2 | **12.88 MB** | **first Publish only** — never during writing, playing or testing |
| Service-worker precache, total | **17.28 MB / 16 entries** | first visit |

**The offline claim was proven, not assumed.** The dev server was stopped — `curl` confirming connection refused — and the page reloaded, where it **compiled fernhill's real story from cache**, with the payload, the bundler, OPFS and its settings all in hand. The run banked its readouts in `localStorage` and the next online load drained them; the timestamps carry the proof. What was *not* proven offline is the testing surface and the walker: those pages are not in the precache list. Everything they need is cached, which makes it a gap in what was shown rather than a known limitation — and it is a gap.

And the in-page build brings its own unpriced piece, which the toolchain shapes get free from Node: **the host owns module resolution.** About eighty lines reimplementing the parts of Node resolution the platform uses — `exports` under the `require` condition, `main` fallback, relative paths, extension probing — learned in three failures that a shipping implementation would hit in the same order (`.cjs`/`.mjs` count; third-party layouts must be walked, not guessed; the four `ext-*` packages are unconditional, GH #465).

## 8. Recommendation

His reason, in his words: *"the Avalonia + Velopack score was as close to native as possible and still reach all three platforms."*

> **This section is left as written, not retconned.** It is what this evaluation's own evidence supports, and ADR-351 D2 names the web shape as the standing answer if one of Avalonia's three conditions fails — which is why the evidence below has to stay legible rather than be rewritten into agreement with the ruling.

**Recommend the pure web application as the shape that carries Chord Writer to Windows and Linux, with the macOS Swift app kept as the native product it already is, and recommend against both .NET shapes as the Windows answer. This supersedes the Avalonia record's §7, exactly on the condition that record named.**

**Re-ranked 2026-09-15 against David's requirement weighting.** The grounds below were first written in the order a host evaluation naturally produces — logistics first — and David ruled the requirement weights the same day (ADR-351, Context): R1 project files ● 4, and the recommendation must be read against that. The re-ranking changes the recommendation's *shape*, not its direction: **a Chromium-class browser becomes a requirement of the product rather than a preference, and the private-storage tier becomes a preview rather than a second tier of the product.** ADR-351 D2 carries the ruling; this section carries the evidence for it. The superseded order is recorded in ADR-351 D2 ground 4 rather than deleted.

Grounds, in weighted order:

1. **R1 (● 4) is where the shape is weakest, and the weakness is confined rather than general.** On Chromium it is met well — the author's real folder, a write verified from outside the browser, a permission cost of two dialogs for the life of a project. On WebKit and Gecko it is not degraded but **absent**, and the private store that replaces it cannot be reached by Finder, git, another editor or the author's own backup, and is destroyed by clearing site data. Requiring a Chromium-class browser is the requirement being met, not excused — and Windows and Linux, the platforms this evaluation exists for, reach that tier by default.
2. **The other four weight-4 requirements are met, three of them better than by any other shape** — the fastest editor over the compiler's own lexer (0.82 ms), compose at 11.8 ms against 89 ms with no process to start, play with no bundle and nothing served, and a tree-test round trip byte-identical to another host's in three engines with the walker running **in-page** rather than relayed.
3. **R12 (◕ 3) is unbuilt, which is what forces the preview framing.** On the private-storage tier a cloud adapter is the author's only route to their own files, and this evaluation implemented zero lines of one — deliberately, on the options doc's own ruling that the OAuth work is known cost rather than a spike question. iCloud, the platform where it would matter most, has no third-party web API at all (verified 2026-09-14).
4. **It removes the Windows problem instead of solving it.** No port, no installer, no `Setup.exe`, no Trusted Signing, no MSIX-versus-updater choice, no Windows launcher for a POSIX shim, no WebView2-versus-WKWebView door that could split D3's answer by platform, and no second codebase. Every one of those is a live, unpriced item in the Avalonia record — whose evidence is **zero percent Windows**.
5. **It does not touch the Mac app.** Avalonia's entire value is one codebase, which is why its own record calls "the Mac app is rewritten from day one" the most expensive sentence in it. This shape asks nothing of the AppKit app that ships at 1.4.0, so the least reversible decision in the track becomes **unnecessary** rather than deferred.
6. **The cost structure is categorically lighter and it was measured.** No 175 MB toolchain to vendor, sign, seal and notarize per architecture — the wall Avalonia hit — replaced by a 1.95 MB payload and a 12.88 MB bundler fetched once, at the first Publish, by authors who publish. The publish artifact was proven by extracting it outside the browser and **playing it from `file://`**.

Not a ground, recorded so it is not mistaken for one: **hatched stories bundle in the page**, closing the tier boundary brainstorm §6 expected. David weighted R10 at ◔ 1, so it resolves a question rather than supporting a recommendation.

**The conditions, stated as conditions.** Q2 and Q3 are product rulings and this record does not make them. GH #461 — whether `navigator.storage.persist()` makes a folder grant durable — is unproven and sits directly under ground 1. And the felt comparison is owed here as much as it was for Avalonia, in a different form: not "does Skia feel right on a Mac" but "does an author accept a browser tab as the place they write."

## 9. The strongest case against that recommendation

**It gives up the two things David actually ruled on.** ADR-341 D2 chose WPF over WinUI 3 on the drawing model, and D4 specified native editors. This shape has neither — not badly, but at all — and the recommendation above weighs a strategic row against two control-level rows David named himself. That is precisely the trade the OpenSilver record recommended and the Avalonia record beat by removing the price. Recommending it now means accepting the price after a shape existed that did not charge it.

**The product would carry a browser requirement, and Chord Writer has never told an author which application to open.** Under the re-ranked recommendation this is stated up front rather than discovered, which is the honest version — but it is still the first time the product would make that demand, and no engineering removes it: the API does not exist in WebKit or Gecko. The mapping onto the platform split (§4) is genuinely strong and is also exactly the kind of argument that looks tidier in a decision record than it will in a support conversation with a Mac author who prefers Safari.

**On the preview tier, clearing site data deletes the author's story.** No other shape has a data-loss property of that kind. It is the concrete reason R1 is weighted ● 4, and the reason the preview framing in the recommendation is load-bearing rather than a hedge.

**The durable-grant question is open, and it sits under the headline.** "The author is asked twice, ever" was measured on a fresh, disposable profile, and a stored handle then vanished across a seventy-minute gap on that same origin. If `navigator.storage.persist()` does not close it, the folder route's story becomes "usually silent, sometimes re-pick," which is a different product from the one in ground 1.

**The shell is the least built of the four columns.** Six PASS rows of eighteen, three rows not exercised at all, and no screenshot of the whole thing anywhere — deliberately, and the reasoning is sound, but the OpenSilver column has eight right-panel tabs and an Index view and this one has none. "It is DOM and OpenSilver already proved that DOM" is an inheritance argument, and inheritance arguments are how columns get credited for work nobody did.

**Three capabilities need a user gesture, and they are not edge cases.** Recovering a lost folder handle, opening a second window, and saving a published file all require a click the application cannot manufacture. Everything an author clicks works; nothing the app decides to do on their behalf does. A native host has no equivalent.

**The macOS answer is "keep the Swift app", which means two codebases forever — the exact thing this whole track set out to escape.** Ground 2 reads as a strength and is also a restatement of the status quo: a Swift app for Mac, something else for Windows. It is cheaper than Avalonia's answer and it is not one codebase.

**Offline is "after first load" and the testing path was not proven offline.** For a tool whose competitors are always-offline desktop applications, "works offline once you have visited it, and we did not check the test runner" is a real asterisk on the row that otherwise looks level.

## 10. What would change the recommendation

- **If David rules Q2 or Q3 the other way** — Safari authors must have the same product, or the real folder is non-negotiable everywhere — this shape cannot be the primary answer, and the recommendation reverts to the Avalonia record's §7 with its three conditions intact.
- **If GH #461 resolves badly** — `navigator.storage.persist()` does not make a folder grant durable — ground 1's "two dialogs, ever" weakens to "usually silent," and the folder tier stops being clearly better than the OPFS tier for daily use.
- **If the felt comparison comes back wrong** — a browser tab is not where an author will write — no further spiking answers it, and the field returns to three desktop shapes.
- **If Windows evidence arrives for Avalonia and is clean** — its Phase 7 is still owed, and a clean Windows run plus a solved macOS bundle layout would make it a genuine one-codebase answer rather than a two-thirds-evidenced one. That does not beat "no port at all," but it narrows the gap materially.
- **If the remaining three subprocess rows turn out to be closed** — `world-index`, introspection and scaffolding are all devkit commands with no browser entry point, and GH #463 shows that question is not answerable by inspection. If any of them cannot be reached from a browser, this shape loses a product surface the other three have for free.

## 12. Owed regardless of the ruling

- **The folder adapter at Phase 4's call sites** — `list`, `delete`, and an `externallyMutable: true` watch observing an edit made *outside* the browser, the one behaviour OPFS can never demonstrate. One click: `phase4.html?prefer=folder` after a re-grant. GH #461.
- **GH #461** — whether `navigator.storage.persist()` makes the grant durable. The sharpest open question under §8's ground 1.
- **GH #463** — the testing harness has no browser entry point; browser-clean logic behind node-bound barrels. Platform change, discuss first.
- **GH #464** — the surface bundle and the play client hard-code `window.webkit.messageHandlers`. True under every shape evaluated; D3's contract module should own the post door.
- **GH #465** — `story-loader` statically imports four `@sharpee/ext-*` packages, so `use scoring` does not mean what it reads like.
- **The three `process.env` defines** (`browser-core.ts:747-749`) — a browser host that does not know to replicate them builds clean and dies at boot with `process is not defined`. Worth a named export or a documented host contract rather than a line in devkit.
- **`CompileOptions.importResolver` is synchronous** — a host-neutral shape would be an async resolver or a compile entry that takes a pre-resolved fragment map. Platform change, discuss first.
- **Offline for the testing surface and the walker** — not precached, not exercised with the server down.
- **The felt comparison** — a browser tab as the place an author writes. David's, and §8's last condition.
- **Avalonia's Phase 7 (Windows)** — still owed for that shape, and its addendum folds back into its own record, not this one.
