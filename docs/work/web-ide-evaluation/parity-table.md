## What the column says at a glance

Of the eighteen **YES**-flagged rows the spike list was built against: **6 PASS** (theme tokens; the typed artifact tree; the editor, on tokenization and the undoable replace; syntax highlighting from the compiler's own lexer; Play, on hosting; and the ADR-307 Testing round trip), **1 partial** (editor diagnostics — the spans are proven, the display is not), **1 void** (the title band — there is no title bar), **3 not exercised** (auto-indent and bracket matching, the line-number ruler, word wrap — all present in the same CodeMirror build a prior column proved, none measured here), and **7 not built** (the four-pane window, the tab strip, the editor tab bar, the right panel, the Documentation tab, the World map, and the Testing Play *window* in the sense of `window.open`, which is PARTIAL on the channel). **None failed.**

**This column is thinner on chrome than either prior column, deliberately, and that is the comparison to draw carefully.** The OpenSilver and Avalonia spikes spent their phases assembling a shell, because for them the shell was the question: could a XAML page or a Skia renderer be made to look and behave like `MainWindow.swift`. For this shape the shell was never the question — it is DOM, and the OpenSilver column already proved that exact DOM in a web view. The questions this evaluation spent its phases on are the ones only this shape has to answer: **can the page reach the author's files** (Phase 1), **can the walker run without a process** (Phase 3), **can one interface serve both storage routes** (Phase 4), **can the page build and publish** (Phase 5), and **does any of it work with the network gone** (Phase 6). Every one came back yes. So a per-row tally against the other columns reads this shape as less complete than it is, and a per-row tally in the other direction would read it as more proven than it is on chrome. Read the two kinds of row separately.

Of the rows flagged **no**: the ones that touch a subprocess in every other shape — compose, build, test, publish, world-index, introspection, scaffolding — split cleanly in two. **Compose, build, test and publish are done, in-page, and measured** (11.8 ms, 759 ms, 128 ms, and a 490 KB archive that plays from `file://`). **World-index, introspection and scaffolding are not**, and each is blocked on the same unknown: whether the devkit command behind it can be reached from a browser at all, which GH #463 shows is not answerable by inspection. That is the honest shape of the remaining work in this column — not UI, and not small.
