Sharpee IDE · Testing · problem study

Miller columns are for branching. A split test is a chain.

Column view won the branch canvas because Fernhill is wide and shallow — 12 children off one node, depth 3 — and one column absorbs a 12-way fan without a palette or a pixel of extra height. The layout study also named where it breaks and left the question open: does it bite often enough to matter?

Not yet, and possibly never. This study records the shape and the trigger. Resolved 2026-08-06 as ADR-301 D6: the coalescing fix below is rejected — a chain gets List mode instead of a special case in the column layout. See branch-view-modes.html. Kept as the reasoning behind that decision.

The shape comes from ADR-302 D1's length discipline: split a long test and each part continues: the last, so a chain of N files is a tree of depth N. Fernhill's dawn-lose is 115 commands under timeline. Split it eight ways and the suite is depth 10 — with the view showing two of those steps and the rest shifted off the left edge.

But that split is the unnatural one. You split a long walkthrough where the state is worth hanging tests off — and a node with children is precisely where a column earns its width. Look at what normalized branch testing actually produces: Fernhill's arrival is 2 commands with 12 children, and key is 2 commands with 4. The spine is not long tests chopped up; it is minimal prefixes that fan out immediately. A run of single-child levels is what you get from splitting for length alone, at points nothing branches from.

The cost is not horizontal scrolling. Column view shifts left as you descend, so the newest column and its preview stay put and the ancestors slide away — you never traverse that width. The cost is what is left on screen, and how quietly it goes missing.

Do not build this yet

The rule would be dead code guarding a shape nobody has. The trigger is narrow and specific: a real Chord suite with a run of single-child levels more than three deep. Depth alone is not the trigger — a deep spine that branches at every joint is what column view is for.

Not run-folding — that was already killed

Folding a chain behind “+ 6 more” was built and then removed at your request: it was the one departure from Finder, and it hid nodes behind a summary. This keeps every step on screen with its own assertion count. A run is not summarised; it is stacked.

The rule would be structural, not a heuristic

Open a new column exactly when a node has more than one child. That is the only moment a column earns its width, because it is the only moment there is a sibling to choose between. Depth alone never opens one.

Porting a v1 story would not produce this

A 952-command v1 walkthrough does not become a 17-deep chain under D13. It becomes a spine split where tests attach — and every split point then has siblings to choose between, which is a column doing its job. The chain is an artefact of the linear walkthrough convention, not of long content.

The shift is why this is subtle

Because the view slides left on its own, a deep chain never looks broken — nothing overflows and no scrollbar demands attention. The context simply is not there, and the pathbar quietly becomes the only record of where you are.

Fernhill is the real branch-stories/fernhill suite — 22 nodes, depth 3 — and per ADR-302 D12 it is v2's only consumer. The split of dawn-lose is hypothetical: it is 115 commands today and nobody has proposed splitting it. Dungeo is deliberately absent. Its walkthrough chain is depth 17, but D12 keeps it on v1 indefinitely, the IDE never tests it, and D9 states that no branch, chain, or tree design is to be shaped by its corpus — which an earlier draft of this page did.
