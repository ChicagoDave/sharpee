# Chord 4.0 — DDD sweep of `main...chord-4-0`

**Date**: 2026-10-21 · **Session**: 3dcfd0 · **Plan**: `plan-20261013-chord-4-0.md` Phase 20 · **Asked by**: David, 2026-10-21, "a DDD sweep of everything in this branch".

The source set is every file under `packages/` and `tools/ide/web/testing-surface/src` that `git diff main...chord-4-0` touches, tests, snapshots, fixtures, generated API pages, Markdown and JSON excluded: 311 files, four of them deleted. Each was read against seven questions:

1. **Ubiquitous language** — one name per concept across Chord, IR, platform and lang; no name for two concepts.
2. **Bounded contexts and layers** — each rule in the layer CLAUDE.md's Logic Location table gives it; dependencies inward.
3. **Aggregates and invariants** — behaviors own every mutation; no trait field written from an action, the loader, a handler or a plugin.
4. **Domain events** — past-tense names; every command emits or refuses; no silent state change (DEVARCH rule 10).
5. **Domain services** — a rule consulted by more than one mover, action or condition lives in `world-model/src/world/` (ADR-379).
6. **Value objects** — one type, one spelling, one conversion per value.
7. **Anti-corruption seams** — the IR between Chord and the loader; the IDE protocol (DEVARCH 8b).

Findings are numbered D1–D22. Where the alignment ledger already holds the finding (F1–F23, `alignment-ledger.md`), it is cross-referenced, not repeated. Each finding is a fix at its home unless marked **design question**. None is fixed: every fix touches `packages/`, and platform changes wait on David.

## 1. Ubiquitous language

- **D1. `passage` names two concepts in Chord itself. Design question.** `passage: 3 turns` is a flight vehicle's time between destinations (IR `vehicle.passage: number`, `packages/chord/src/ir.ts:273-274`; ADR-366 D5d); `passage climb the rope to …` is an exit reached by its own words (IR `exit.passage: string[]`, `ir.ts:1038-1042`, keyed `passage:<form>`; ADR-378 D1). Both arrived on this branch. One of them needs another word, and that is a language change.
- **D2. Boarding has three names.** Chord `boarded through:`, IR `boardedThrough` (`ir.ts:278`), trait `VehicleTrait.boardingRoom` (`packages/world-model/src/traits/vehicle/vehicleTrait.ts:201`), translated at `packages/story-loader/src/loader.ts:365`.
- **D3. The movement type has two names.** Chord and IR say `movement` (`ir.ts:259`); the platform says `VehicleTrait.model` and `model.kind` (`vehicleTrait.ts:212`). The trait's own header calls the model "the declaration of the vehicle's built-in machine" and the analyzer calls the same rows "the movement table".
- **D4. A claim lock has three words, and one of them is taken.** ADR-367 and the Testing tab say *lock*; branch-tester says *pin* (`pinLockOnCard`, `packages/branch-tester/src/tree-document.ts:1096`; `ClaimPinResult`, `claims/claim-floor.ts:43`); the wire says both (`ClaimLockPin`, `packages/ide-protocol/src/run-events.ts:514`). In an IF platform *lock* already means `LockableTrait`.
- **D5. A predicate is spelled with a function that answers a different question.** The command validator's "is this a landmark room" test is `holderOf(this.world, room)` (`packages/stdlib/src/validation/command-validator.ts:696`); `holderOf` answers "the positioned thing this is held in". The domain word is *landmark*; nothing exports it.
- **D6. A query is named as a command.** `ContainerBehavior.addItem` mutates nothing — its success path says "the actual mutation happens via events" and returns `success: true` (`packages/world-model/src/traits/container/containerBehavior.ts:282-287`). Emptying, new on this branch, calls it, discards the result, then moves the item itself (`packages/stdlib/src/actions/standard/emptying/emptying.ts:174-181`). Fix: emptying drops the call (its `accepts` already asked `canAccept`); `addItem` is renamed for what it is, a platform rename for David.
- **D7. One directory breaks the action naming.** Multi-word action directories are `snake_case` (`asking_for`, `looking_under`, `saying_no`, and the older `switching_on`, `taking_off`) and match their ids; `setting-course/` is hyphenated while its id is `if.action.setting_course` (`packages/stdlib/src/actions/constants.ts:101`).
- **Cross-referenced:** the entity-id derivation written eight times (F18); the movement words spelled four ways (F19); a repeated destination dropped where a repeated stop is an error (F20); diagnostic codes that do not name their fault (F22).

## 2. Bounded contexts and layers

- **D8. The vehicle machine decides who hears about a move by containment, not perception. Design question.** `tickVehicles` reports an arrival when the player is aboard or in the room reached, and every other step only when aboard (`packages/plugin-state-machine/src/vehicle-machine.ts:117-150`). Whether a player in a dark room sees a tram arrive is a perception question, which `PerceptionService` answers for every other event.
- **Cross-referenced:** English typed text read in stdlib and the language-neutral loader (F5); the grammar collapsing ten gestures into one action (F5); the claim result types mirrored instead of shared (F14).

## 3. Aggregates and invariants

- **D9. The loader's runtime writes an expanse's fields directly.** `set … visibility` and `set … wind` assign `ExpanseTrait.visibility` and `.wind` (`packages/story-loader/src/runtime/statements.ts:456`, `:465`); in the same `switch`, `set … sails` goes through the behavior `setSails` (`:473`). Fix: the expanse behavior owns both writes.
- **D10. One press writes `isOn` twice.** Pushing's execute toggles through `SwitchableBehavior.toggle` (`packages/stdlib/src/actions/standard/pushing/pushing.ts:231`); the `PUSHED` handler, rewritten on this branch, then assigns the raw field from the event's `newState` (`packages/event-processor/src/handlers/device/index.ts:31`), bypassing the behavior. An interceptor that changes the outcome after execute is overwritten by the event's prediction. Fix: the handler goes; the behavior is the one writer.
- **Cross-referenced:** behaviors that do not name their refusals, so actions copy their bodies (F6); an expanse edge's phrase stored twice (F7); where an open vehicle is computed in three places (F8).

## 4. Domain events

- **D11. Drift is a silent state change, and the hook its comment promises cannot fire.** `tickVehicles` calls `driftExpanse(world, expanse, random)` and discards the `DriftStep[]` it returns (`vehicle-machine.ts:157`; `DriftStep`, `packages/world-model/src/traits/expanse/expanseBehavior.ts:261-264`). The header says "the author's `when <thing> moves` clause is the hook" (`vehicle-machine.ts:22-23`), but that clause is bound to `if.event.actor_moved` (`packages/story-loader/src/runtime/move-clauses.ts:30`; `event-contract.ts:25`), which drift never emits. No story exercises it. Fix: the steps become events.
- **D12. Riding into a room is not arriving. Design question.** The machine carries the player by moving the vehicle and emits `if.event.vehicle_arrived`; no `actor_moved` follows, so clauses on the player entering a room may not fire for a passenger. Whether a passenger arrives is David's call.
- **D13. Event names that are not facts.** `if.event.expanse_edge` names a thing; `if.event.vehicle_in_irons` and `if.event.vehicle_at_end` name states (`vehicle-machine.ts:49-53`; `statements.ts:678`). `vehicle_at_end` is emitted by the loader, a third emitter of vehicle reports, spelling going's message id (`statements.ts:681`). Extends F4.
- **D20. "This light now gives light" has two events, chosen by mechanism. Design question.** Lighting a flame records `if.event.lit`; lighting a switchable lamp delegates to switching on and records `if.event.switched_on` instead (`packages/stdlib/src/actions/standard/lighting/lighting.ts`, the `delegateValidate` branch; ADR-374 D9 chose the delegation). A reaction keyed to the lamp being lit misses every electric lamp.
- **Cross-referenced:** the machine's reports owned by no module (F4).

## 5. Domain services

- **D14. Sight across an expanse is a system living in a trait folder.** `lookoutOf`, `sightingOf`, `sightings` and `inSight` (`packages/world-model/src/traits/expanse/sightBehavior.ts`) are read by `VisibilityBehavior`, `ReachabilityBehavior`, the evaluator, the scheduler constructs, and the looking, examining, throwing and look-through actions — by ADR-379's own test a system. The two world systems import it from `traits/expanse/` (`packages/world-model/src/world/ReachabilityBehavior.ts:9-11`, `VisibilityBehavior.ts`). Examining computes the system's answer itself: "seen only from afar" is a five-part condition in the action (`afar && !context.canReach(noun) && holderOf(…) === noun && lookoutOf(…) && placeOf(…)`, `packages/stdlib/src/actions/standard/examining/examining.ts`). Fix: sight moves to `world/` beside visibility, with `placeOf` and `holderOf`, and answers "seen from afar" itself.
- **FIXED 2026-10-21 (alignment-fixes Phase 1, session 9b0652):** `climb up`/`climb down` delegate to going as pushing does (`stdlib/src/actions/standard/climbing/climbing.ts:132`), so every traversal gate stops a climber; a missing or hidden way keeps climbing's own line; the move and arrival are going's events. Tests: `stdlib/tests/unit/actions/climbing-traversal.test.ts`. As found:
- **D21. Climbing moves the climber around the traversal system.** Phase 14 moved climbing onto `TraversalBehavior.exitOf`, which only hides a hidden way; `climb up` and `climb down` then move the actor with `world.moveEntity` (`packages/stdlib/src/actions/standard/climbing/climbing.ts:126-131`, validation at `:269`) and never ask `wayFor`, so a blocked way up or a closed, locked hatch overhead does not stop a climber. A walker is one of the movers ADR-379 names. Fix: climbing asks `wayFor` with a walker mover, or delegates to going as pushing does.
- **D22. Dropping spells the overboard rule twice.** "A floating actor dropping into an expanse loses the thing overboard" is written in the single-object path and again in the multi-object path (`packages/stdlib/src/actions/standard/dropping/dropping.ts`, both `receiveInExpanse` calls), each beside its own fragile-break check. Fix: one function both paths call.
- **Cross-referenced:** admittance answered outside the traversal system for a computed way (F1); "dark to this observer" re-derived beside `isDarkFor` (F3); seeing inside a container copied into stdlib (F2).

## 6. Value objects

- **D15. Direction has one constant and many spellings.** `Direction` is the value (`packages/world-model/src/constants/directions.ts:8-23`, whose header says the parser owns the word-to-constant mapping). The expanse code re-lists subsets as new types, `COMPASS_HEADINGS` / `CompassHeading` (`expanseBehavior.ts:37-38`) and `ExpanseSide` (`packages/world-model/src/traits/expanse/expanseTrait.ts:37`). The IR carries lowercase Chord words, converted by three copies of the same function in the loader (`loader.ts:3046`, `runtime/timers.ts:111`, `runtime/derived.ts:25`) and by inline `toUpperCase()` in the evaluator, statements, steering and `expanseBehavior.ts:64`. Going the other way, stdlib turns the constant into an English word with `toLowerCase()` — looking's sighting rows (`looking/looking.ts`, `sightingEvents`) and pushing's refusal (`pushing.ts:174`) — where rendering a direction is lang's. Fix: the subsets are `Extract<DirectionType, …>`; the loader converts once, at the boundary.
- **FIXED 2026-10-21 (alignment-fixes Phase 1, session 9b0652):** Chord's one spelling is the IR's (`chord/src/ir.ts:37`, `PASSAGE_KEY_PREFIX` and `passageKeyOfForm`), which the parser mints through (`parser.ts:2964`); going calls `isPassageKey` (`going.ts:554`); `story-loader/tests/admittance-and-passage-key.test.ts` pins Chord's prefix and minting equal to world-model's. As found:
- **D16. The passage key has four spellings.** The Chord parser mints it with a template literal (`packages/chord/src/parser.ts:2963`) beside Chord's own `PASSAGE_KEY_PREFIX` (`packages/chord/src/analyzer/entity/exits.ts:39`); world-model has `PASSAGE_KEY_PREFIX`, `isPassageKey` and `passageKey` (`directions.ts:72-87`); going tests the prefix by literal (`packages/stdlib/src/actions/standard/going/going.ts:507`). Fix: going calls `isPassageKey`; Chord mints through its constant; a test pins the two sides of the zero-dependency boundary equal (as F17 for bearings).
- **FIXED 2026-10-21 (alignment-fixes Phase 1, session 9b0652; Q13):** `Admittance = { vehicles: string[]; pushed: 'any' | string[] }` (`world-model/src/traits/room/roomTrait.ts:27`) on `RoomTrait.admits`; an exit carries a `Partial<Admittance>` read field by field before the room's, so a thing's `pushing` grant decides the pushed things alone and leaves the vehicles to the room (`admitsPushed` folded in). The loader lowers the IR's word lists (`story-loader/src/loader.ts:460`) and skips a grant on a way whose room already admits every pushable (`:476`); the class word is Chord's `ADMITS_PUSHING` on the IR (`chord/src/ir.ts`), no longer a world-model constant. Chord and the IR unchanged. As found:
- **D17. An `admits` list mixes two kinds of value.** `admits` holds entity ids and the reserved class word `pushing` in one `string[]` (`packages/world-model/src/traits/room/roomTrait.ts`, `IExitInfo.admits` and `RoomTrait.admits`), and a single pushed thing's admittance is a third field, `admitsPushed`. An entity whose id were `pushing` would be read as the class word. Fix: a shape with the vehicles and the pushing rule as separate fields.

## 7. Anti-corruption seams

- **D18. The IR encodes "outside" as an empty string, and the World tab's mirror drops it.** A `to outside` exit is `to: ''` with `toOutside: true` (`ir.ts:1071-1076`); world-index's loader mirror skips any exit whose `to` is not a known room (`packages/world-index/src/loader-semantics.ts:76`, `:250`), so the World tab's map and branch reading never learn that rooms aboard connect to anything. The analyzer uses the same empty id for error results (`send`'s `{ kind: 'entity', id: '' }`, `packages/chord/src/analyzer.ts:6541`). Fix: the IR names outside as a value of its own; world-index mirrors the vehicle semantics ADR-321 D3 requires it to.
- **D19. The expanse extension's data lands on core traits. Design question.** `seenFromAfar` is on `IdentityTrait` and a landmark's outlook is `RoomTrait.sight`, so every entity and every room in every story carries `use expanses` fields. A landmark trait would keep the extension's data in the extension's context.
- **Cross-referenced:** the claim result types mirrored by hand (F14); the Testing tab writing its own claims ratio (F23); the edge phrase's two lookup paths across the plugin seam (F7).

## What held

- **One exit model.** `ExitTrait` and `ExitBehavior` were deleted on this branch (ADR-378 D4); exits are `RoomTrait.exits` keyed by `ExitKey`, read by traversal.
- **Traversal is a system.** `TraversalBehavior.wayFor` is the one home its four callers ask (ledger, Aligned); F1 is the case it does not yet answer.
- **One way to apply events.** `withWorldReactions` (`packages/engine/src/events/world-reactions.ts`) is used by the command executor and the sound stage alike.
- **Pushable is a marker.** `PushableTrait` lost eleven fields nothing read; the way decides the move (`packages/world-model/src/traits/pushable/pushableTrait.ts` header).
- **Wire types are shared.** devkit's `claim` and transcript-tester's run-event stream import their shapes from `@sharpee/ide-protocol`; F14 is the one mirror.
- **The World tab's mirror is deliberate.** `loader-semantics.ts` mirrors the loader by ADR-321 D3, a pinned test per rule; D18 is the vehicle semantics it is missing, not the mirror itself.
