# Session Plan: declared states nothing assigns — the second testing-explorer lens

**Created**: 2026-09-24
**Plan Status**: ACTIVE
**Overall scope**: Build the second scoped lens for the testing-explorer (issue #515, next in #508's ordering): for every entity state a story declares, report which values no rule ever assigns (dead vocabulary, or a bug — a clause gated on it can never fire) and, separately, which values some rule assigns but no rule ever reads (an inert dimension). Static, zero-execution, decided against the compiled IR the engine runs — no walk, no room reachability, no engine invocation. Nothing under `packages/` changes; a platform need surfaced during design (a symmetric read-side derivation to sit beside `@sharpee/world-index`'s `collectStateWriters`) is named as a discussion item, not built.
**Bounded contexts touched**: N/A — infrastructure/tooling. A testing lens under `tools/explorer-probe/`; changes no domain behavior of the platform or of any Chord story.
**Key domain language**: N/A. The lens's own vocabulary ("declared state," "never assigned," "never read," "inert dimension") is fixed by issue #515's own text, not new domain modeling.

## Phases

### Phase 1: Read and write derivation, and the classifier — verified against fernhill's own history
- **Tier**: Medium
- **Budget**: 220
- **Domain focus**: N/A — infrastructure/tooling
- **Entry state**: `branch-stories/fernhill/dist/fernhill.ir.json` and `branch-stories/secret-letter/dist/secret-letter.ir.json` are compiled. `@sharpee/world-index` is built (`packages/world-index/dist/index.js` exists) and exports `collectStateWriters` — verified this session by reading `packages/world-index/src/statements.ts` and running it directly against fernhill's compiled IR (`node -e "require('./packages/world-index/dist/index.js').collectStateWriters(...)"`): it correctly resolves `vine → fruiting` to a trait-owned writer (`owner: {kind:'entity', id:'vine'}`, the `prunable` trait's `it`-bound `change`) and additionally finds `vine → flowering` written from inside the boiler machine's states — a second real writer of the same entity the spike never modelled. **This is the historical false positive from the spike, already fixed by the platform derivation that exists today** — Phase 1's job is to consume it, not to re-solve the problem the spike hit.
- **Deliverable**:
  - New `tools/explorer-probe/lens-declared-state.js` (CLI: `node tools/explorer-probe/lens-declared-state.js <story.story>`), static — loads the compiled IR directly (`dimensions.js`'s `loadStoryIR`), invokes no engine, no walk, no `explore.js` hook.
  - **Assigned side**: `require('@sharpee/world-index').collectStateWriters(ir)` — real path per ADR-322 D8, decided against the compiled IR (not Chord source text), per the goal's real-path-discipline line. `collectStateWriters` already covers every surface that writes an entity's state — entity `onClauses`, entity `topics`, entity `manner` (ADR-320 manner blocks — a sixth surface beyond the five issue #515 names, confirmed present in `packages/chord/src/ir.ts` and walked by `statements.ts`), trait `onClauses` expanded once per composing entity with `it` bound to that entity (the fifth causal surface the spike found), and `machine.states`' `onEnter`/`onExit` bodies (confirmed real: fernhill's boiler machine writes `vine`, not just its own role entity `boiler`) plus story-level `onClauses`/`sequences`/`actions`/`hatches`.
  - **Read side**: no equivalent derivation exists anywhere in `@sharpee/world-index` — verified by reading `conditions.ts` (the only other file matching `IRCondition`/`predicate`), which is scoped to reachability-gate evaluation and answers `unknown` rather than collecting every read, and by reading `dimensions.js`'s `harvest`, which currently walks only two of the six surfaces as roots (`entity.onClauses` via the per-entity loop, and `ir.actions`/`ir.conditions`/`ir.timers`/`ir.startBlock`/`ir.chapters`/`ir.story`) — **`entity.topics`, `entity.manner`, `ir.machines`, and `ir.traits` are never passed to `harvest` at all**, confirmed empirically: fernhill has a real topic-body `change` (`tobias → shaken`) and 4 real machine `onEnter`/`onExit` `change` nodes, secret-letter has a real topic-body `change` (`teisha → told`), none of which `dimensions.js` would see as a *read* root either (it only ever sees them as unrooted subtrees it never visits). Build a new, local, read-side collector in `lens-declared-state.js` — `collectStateReads(ir)` — mirroring `collectStateWriters`'s owner-tagged walk shape (same six roots: entity `onClauses`, `topics`, `manner`, trait `onClauses` with `it`-binding per composing entity, `machine.states` transition `condition`s plus `onEnter`/`onExit` predicate reads, and the four story-level roots), walking `predicate` nodes with `pred === 'is'` the way `dimensions.js`'s `harvest` already does for the two surfaces it covers. Do **not** modify `dimensions.js` in place — it is shared with `explore.js` and `plan.js` (`deriveDimensions`'s `placementEntityIds` feeds `plan.js`'s `carryable` set), and widening its harvest roots is a change with consequences outside this lens's scope; this lens owns a new, separate module.
  - **Initial-state exclusion**: verified against the real engine's own load path (`packages/story-loader/src/loader.ts:616`, `world.setStateValue(CHORD_STATE_PREFIX + irEntity.id, irEntity.states[0])`, and line 645 for the story-level state's `states[0]`) — an entity's **first declared state value is assigned at load time, by the loader, not by a rule**. Concretely: fernhill's `vine` declares `states: [seedling, flowering, fruiting]` and `seedling` is never targeted by any `change` statement anywhere in the IR — without this exclusion the lens would report `seedling` itself as "never assigned," a false positive on the very entity the issue's motivating example is about. Exclude `states[0]` (and the story-level `story.states[0]`) from the never-assigned set; document the reasoning inline where a future reader would otherwise "fix" this as a missed case.
  - **Classification**: for every entity with `states.length >= 2` (matching `dimensions.js`'s existing declared-dimension filter, with the reasoning for keeping that bound recorded rather than silently inherited): `neverAssigned` = declared value with no writer targeting it, excluding `states[0]`; `neverRead` = declared value with at least one writer targeting it, but no reader ever testing `(entity, value)` via an `is` predicate. Report both directions **separately** (goal's explicit requirement) — never merged into one undifferentiated list.
  - Report format: `{lens: 'declared-state', format: 1, neverAssigned: [...], neverRead: [...]}` — top-level `lens`/`format` keys shared with `lens-examinable.js`'s convention where they fit; the finding shape itself is per-entity/per-state, not per-room, since this lens has no rooms.
  - Run against fernhill; verify by hand: `vine.fruiting` is **not** in `neverAssigned` (citing the trait writer), `vine.seedling` is **not** in `neverAssigned` (citing the initial-state exclusion), and at least one genuine finding in each direction is confirmed against the story's own source.
- **Exit state**: `lens-declared-state.js` runs end-to-end against fernhill's compiled IR with no engine invocation; both directions report correctly on the two named historical cases (`fruiting`, `seedling`) plus at least one hand-verified genuine finding per direction. Nothing under `packages/` touched.
- **Status**: CURRENT (since 2026-09-24)
