Phases 2 through 5 are independent of one another (different packages/tools, no shared files) and may be done in any order once Phase 1 is complete. Phase 1 is placed first only because the proposal's own sequencing note says P-1 is a prerequisite for any `./repokit test:npm --local` verification elsewhere — none of Phases 2–5 currently need that verification path, but keeping P-1 first preserves the option at zero cost. This is not a linear pipeline; do not treat "Phase N" as "must follow Phase N-1" beyond Phase 1's placement.

**Global exit discipline for every phase (CLAUDE.md MAJOR DIRECTIONS)**: if a build or test fails, report the failure and STOP — do not loop on build-fail-fix-rebuild. Do not delete any file without explicit confirmation, including transcripts, fixtures, or files this plan itself creates as scaffolding.

### Phase 1: Fix `pack()` for npm 12's keyed-object `npm pack --json` shape (P-1, #199)
- **Tier**: Small
- **Budget**: ~100 tool calls
- **Domain focus**: N/A — tooling. `tools/repokit/src/consumer-gen.ts`.
- **Entry state**: `./repokit` is built and runnable; `tools/repokit/src/consumer-gen.ts:130`'s `pack()` reads `npm pack --json` output as an array (`JSON.parse(out)[0].filename`); under npm 12.0.1 this is `undefined` because npm now emits an object keyed by package name; the failure is a bare "Cannot read properties of undefined" naming neither `npm pack` nor the package. `tools/repokit/src/consumer-gen.test.ts` exists and is the test file to extend.
- **Deliverable**: `pack()` accepts both the legacy array shape and npm 12's keyed-object-by-package-name shape; when neither shape yields a filename, it throws an error that names `npm pack --json` and the package being packed (per the proposal's Done-when). Unit tests in `consumer-gen.test.ts` cover: array shape (regression), keyed-object shape (the npm 12 case), and the named-error throw when neither shape resolves a filename. Implements P-1.
- **Exit state**: `pnpm --filter '@sharpee/repokit' test consumer-gen` passes. `./repokit test:npm dungeo --local` gets past package staging and installs (the proposal's Done-when) — run once and report the result; a failure here is a stop-and-report, not a fix-loop. Re-measuring #120 becomes possible but is explicitly not part of this plan.
- **Status**: BLOCKED — the `pack()` half is delivered and verified (2026-07-29, session 5c4586); the "and installs" half of the exit state is blocked on a newly-found independent defect.
  - **Delivered**: `packFilenameFrom(stdout, packageName)` extracted as a pure exported function in `consumer-gen.ts`, accepting npm ≤ 11's array shape and npm 12's package-keyed object, throwing an error naming `npm pack --json` and the package when neither resolves; `pack()` calls it. Four unit tests added (array shape, keyed-object shape, named-error throw, non-JSON stdout) — `pnpm --filter '@sharpee/repokit' test consumer-gen` passes 11/11. Real-path verified: `./repokit test:npm stories/dungeo --local` now completes staging and packs the full 19-package closure; the original `Cannot read properties of undefined (reading 'filename')` is gone.
  - **Blocked by [#201]**: `npm install` then fails `ETARGET` on `@sharpee/bootstrap@^4.3.0`. `consumer-gen.ts` packs the `@sharpee/transcript-tester` dev dep as a bare `pack(TT)` with no closure expansion, so the one dep of transcript-tester that is *not* in dungeo's runtime closure never gets vendored and npm falls through to the registry (published 4.2.0 vs staged 4.3.0). Independent of P-1's shape fix — filed rather than folded in, since P-1's Done-when doesn't cover it.
  - **Also found [#202]**: the bare-name form `./repokit test:npm dungeo --local` fails at `test-npm.ts:217` — `lookupStory` reads only the user-level registry `~/.sharpee/devkit`, which does not exist in-container. `stories/dungeo` (explicit path) works. Not a regression; it fails before any packing code runs.
  - **P-1 therefore stays PLANNED, not DONE** — one Done-when clause ("and installs") is unmet, blocked externally.

- **Budget**: ~200 tool calls

Pattern precedent: #169 (book + Family Zoo) already did this cleanup elsewhere. A spot-check during planning found both shapes present: `forest.ts:269` (`nest.add(new SceneryTrait())`, bare — a removal candidate) and `thiefs-canvas-objects.ts:39` (`frame.add(new SceneryTrait({ cantTakeMessage: 'dungeo.frame.cant_take' }))`, configured — must be preserved).
