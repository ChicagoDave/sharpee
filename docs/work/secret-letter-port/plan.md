**Conversation stubs (standing, applies to every build phase — RULED 2026-09-01, session c2a3b7)**: David: "I'm not ready to write dialogue at this point — we need to keep this until we're done with the port. The conversations do have triggers, so we'd need to mimic those somehow." So the port builds the **mechanics** of every conversation and defers its **dialogue**. The source's trigger hardware is 40 `start conversation with X on Q` sites (room entry, trying to leave, plot beats, offstage voices), 38 `After firing Q` world side effects (remove Bobby, move the player and lock the shop, hand over the purse, start Jacobs' clock, give the wire), and each NPC's `talk to` initiating rule. Those are plot rails — chapters gate on them — and they are built as each chapter is ported, in the shape TE20 already has (`npc-teisha.chord`: trigger fires, side effects run through real acting statements, the text is a TODO): (1) each `start conversation` site becomes the story event it already is (`when the player enters`, an `on the player going` refusal, the plot-beat clock) and emits one `(TODO during play-testing — conversation BO7: Bobby corners Jack with the proposal)` phrase; (2) each `After firing` side effect runs on that same event, verbatim from the source; (3) each `talk to X` gets a one-line TODO reply so the command never falls to "I don't understand"; (4) where a conversation forks with a world consequence (Bobby's in-or-out, DS29's kick-out), the stub takes the source's progress path automatically and says so in its TODO — the one place a stub decides anything, flagged for David each time. Nothing is thrown away at the rewrite: the stub's `when` becomes the greeting arm's `when` and its side-effect body becomes the thread's `conclusion:` row, exactly as `rewrite-pattern.md` M1/M2/M11 map them. Consequence for sequencing: **Phases 7 and 8 follow Phases 10 and 11**, not precede them; Phase 7's five rulings and the RULED pattern doc stand and wait.
