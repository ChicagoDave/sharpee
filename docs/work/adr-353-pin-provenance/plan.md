**`[SKIP]` changes meaning, and that is the point.** Today the function returns `[{type:'skip'}]` when it has nothing to claim (`assertion-core.ts:689`), and its contract is stated in that function's own doc comment (`assertion-core.ts:653-655`): under a policy, "nothing of what I assert on was said" is a deliberate skip, distinguishable in the file from a command still awaiting its first run. **The contract lives there, not in ADR-294 D2** (fifth-pass review fold): D2's only sentence about `[SKIP]` concerns an *authored* skip — "`[SKIP]` survives for commands whose output is deliberately not asserted in assertion-tier tests" — and is unaffected by this change. Under D4 a room whose description is entirely a spliced snippet, or a heading that is entirely one `while` arm — AC-10's own case — has no stable span and so yields no prose claim. Gating identity behind prose would suppress it exactly there, which is the case D5 exists for: a prose claim catches the text regressing, an identity claim catches the world going wrong, and a suite with only one of them passes while half the system is broken. So **`[SKIP]` now means "neither a prose claim nor an identity claim was available"**, and a fully-variable room gets a real test of the thing that can be tested. **This owes an update to `synthesizePolicyAssertions`' own doc comment** (`assertion-core.ts:648-661`), which is the contract being changed — not an ADR amendment.
