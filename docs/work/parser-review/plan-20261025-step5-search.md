# Session Plan: Parser review step 5 — the parser searches slot extents and ranks readings by their nouns

**Created**: 2026-10-25
**Plan Status**: ACTIVE
**Overall scope**: Step 5 of `docs/work/parser-review/review-20261022.md`, root cause 1, implementing ADR-386. A slot consumer returns every extent it admits (D1); the grammar engine searches them with backtracking, bounded by `MAX_READINGS_PER_RULE` (D2); articles are optional in both directions (D3); every reading is ranked by how its nouns resolve through the one matcher, with the noun rank above ADR-384's keys in `compareGrammarRank` (D4, D5); a failure outranks a reading only when it names strictly more entities (D5); `and` and a comma are readings, not hard splits (D6); the quick reject counts what the match requires (D7); a number slot reads a compound number (D8). Fixes A1, A2, A3, A4, A5, A6, A7, A9, A10, A11. Step 7 (language and state) is NOT in this plan.
**Bounded contexts touched**: English parser and grammar engine (`packages/parser-en-us`); grammar contract (`packages/if-domain`, `GrammarRank`); language numbers (`packages/lang-en-us`); published references (parser-en-us CLAUDE.md, ADR-384 D2 amendment note, genai API reference); Dungeo transcripts (re-recording only, its own go)
**Key domain language**: reading (one complete way a rule consumes the input), extent (the token span a slot takes), search order, noun rank `{ named, unnamed, exact }`, names of an item, failure versus reading, list separator, `MAX_READINGS_PER_RULE`, `parseCardinal`

## Sequencing note
