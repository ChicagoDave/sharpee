Two build-host prerequisites, both discovered by failing, both reported by the tool itself:

  1. mksquashfs absent -> vpk aborts before producing anything:
       [FTL] Could not find 'mksquashfs' binary on the system ...
             'sudo apt install squashfs-tools'
     An AppImage is a squashfs image, so this is structural, not incidental.

  2. zstd absent -> vpk still succeeds, but silently degrades:
       [ERR] Could not find 'zstd' binary on the system ...
       [WRN] Zstd not available. Falling back to legacy bsdiff delta format.
             This will be a lot slower and more prone to breaking.
     Measured cost of the fallback on this same delta:
       bsdiff fallback   122,949 bytes   12,848 ms
       zstd              118,644 bytes    1,502 ms
     The size difference is small; the time difference is 8.5x, and Velopack's own
     wording about reliability is the reason this is recorded rather than ignored.

Not established here: no signing (Linux has no equivalent of the Windows Trusted
Signing step exercised in Phase 7, and none was attempted), the AppImage was not
executed, and no update round trip was applied. x64 is Phase 8's remaining leg.
