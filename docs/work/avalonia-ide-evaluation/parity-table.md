# Avalonia parity column — the ADR-341 table with a fourth column filled

**Written**: 2026-09-14, session 3b49f8 (evaluation plan Phase 6). The rows are `docs/work/archive/adr-341-spike/parity-table.md` (2026-09-08, session 4a2d5f) unchanged, reached through `docs/work/opensilver-ide-evaluation/parity-table.md` (2026-09-13, session 5c6bba): same features, same sources, same macOS implementation files, same **Spike?** flags. Nothing is added to the product surface. The **OpenSilver** column is copied from that table verbatim so the two hosts can be read against each other line by line; the **Avalonia** column is new, filled from the Phase 0–5 records in this directory (`phase-0-prerequisites.md` … `phase-5-velopack-packaging.md`) and their evidence under `evidence/`. Where a cell says PASS the phase record carries the command and output that earned it; where it says "not built" nothing was attempted and the cell is a cost estimate, not a result.

**Host**: Avalonia 12.1.2 on .NET 10.0.300 (runtime 10.0.8), macOS 26 (Apple Silicon), `net10.0`, with `Avalonia.Controls.WebView` 12.1.0 (WKWebView backend), `Avalonia.AvaloniaEdit` 12.0.0 and `vpk` 1.2.0 — a plain .NET process and a native window whose entire UI, chrome included, is **drawn by Avalonia's own Skia renderer**. No web view carries any part of the chrome; web views appear only where the shipping Mac app also uses them, as the three D3 panes. Windows (the WebView2 backend, `Setup.exe`, Azure Trusted Signing) is Phase 7 and has not run; every cell below is macOS evidence about a cross-platform toolkit. The spike is at `/Users/david/repos/spikes/avalonia-ide/` (`hello/` the Phase 0 scaffold, `pane/PaneHost/{Hosting,Shell,Theme,Editor}` the host and shell, `editor/` the lexer service).

**Fresh check at write time**: `dotnet test` in `pane/PaneHost.Tests` → `Passed! - Failed: 0, Passed: 20, Skipped: 0, Total: 20, Duration: 2 s` (2026-09-14, Phase 2 §3). Eleven tests drive fernhill's real built bundle and the IDE's real checked-in pane assets over a real `HttpListener`; nine drive the real `sharpee` shim, the real vendored `node`, and the real `~/Documents/` folder. No stubs.

**Cell vocabulary** (unchanged from the OpenSilver column): **PASS** — built and proven with inline evidence; **built** — works, screenshot or log, no separate measurement; **partial** — built with a named gap; **not built** — not attempted, with the expected cost; **same as WPF** — a plumbing or logic row where the host uses the identical .NET call (Phase 2 proved `System.Diagnostics.Process` and `System.IO` behave as ordinary calls, in code that names Avalonia nowhere).

## What the column says at a glance

Of the eighteen **YES**-flagged rows the spike list was built against: **8 PASS** (theme tokens, tab strip, editor, syntax highlighting, line-number ruler, word wrap, World map, and the Testing round trip — the last with its replay path unexplained), **2 PASS on hosting** (Play and Documentation, both over a loopback origin rather than a custom scheme, both without their surrounding controls), **6 partial** (main window without persistence; appearance without System-follow or persistence; project tree as a drawn list; editor tab bar not driven by document state; span navigation with no caller; right panel at four of eight tabs), **1 built in a different shape** (the title band), and **1 not built at all** (auto-indent and bracket matching — the only flagged row this column leaves untouched, and one OpenSilver got partly for free from CodeMirror's defaults). **None failed.**

Two of those PASSes are the ones the evaluation existed to get: the editor is **native** and carries the compiler's own grammar, and the World map is **drawn** through `Render(DrawingContext)` rather than composed. Set against them, the shell is thinner than the OpenSilver spike's — four right-panel tabs against eight, no Index, no Reach, no Incomplete, no compose scheduler, no test relay — so the two columns are not equally far along, and the comparison to draw is per row rather than by tally.

Of the rows flagged **no**: everything that touches a subprocess or the filesystem and was attempted (compose, build, world-index, toolchain, vendored Node, Documents round trip) passed with the same two .NET namespaces WPF would use, in host code that names Avalonia nowhere — and then passed again from inside the packaged `.app`. Everything not attempted is standard controls or logic. One "no" row — Check for Updates — is where this column goes furthest (an 8 MB delta against a 100 MB app) and also where it fails hardest (the bundle cannot be sealed, so nothing was notarized).
