**Created**: 2026-09-10

## Sequencing rationale

D1's third condition (`isPlayable`) is decorative until D7 lands (today's default is `true`, so it never fires); D7's flip makes every un-opted-in actor non-playable, which D1 would then refuse at install. Phases are ordered so the tree is green at each boundary rather than only at the end:

1. **D6+D3** first — the engine no longer accepts a constructed player anywhere, and the fixture/story-less tests comply. This is the one phase every later phase's test runs sit on top of.
2. **D1+D2+D4** next — the seam gains its guard while `isPlayable` is still trivially `true` everywhere, so the guard is exercised (placement, `ActorTrait` presence) without the flip's blast radius landing at the same time.
3. **D5** — the loader fallback removal is independent of 1–2 (different package, different invariant) and could run before or after them; it is sequenced third for narrative continuity, not a hard dependency.
4. **D7** last of the code phases — the default flip and the loader write must ship in the same commit (a flip without the write breaks every Chord protagonist; a write without the flip is a no-op), and it is safest to make once D1's guard already exists to catch any protagonist the opt-in sweep missed.
5. **AC-8 wrap-up** — full-tree verification, AC-7/D8 confirmation by inspection, evidence compilation.
