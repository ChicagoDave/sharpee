# Session Plan: ADR-333 — Prose provenance and play-to-write

**Created**: 2026-09-05
**Plan Status**: ACTIVE
**Overall scope**: Stamp every rendered text block with the message id that wrote it (`ITextBlock.source.messageId`), extend it through descriptions' existing id mode (ADR-107), carry it across the wire and into the DOM, and consume it in Chord Writer's Play panel for click-to-edit play-to-write, including a platform-message override path and a Testing-tab-driven walkthrough. Standalone web client explicitly declined by David ("I don't need the mobile version (yet)") — the consumer is Chord Writer's Play panel only.
**Bounded contexts touched**: engine (prose pipeline), text-blocks (wire type), story-loader (description registration), stdlib (examining data), world-model (identity trait, already has the field), channel-service (pass-through, no change), platform-browser (DOM exposure), Chord Writer / SharpeeIDE (Play panel, Testing tab).
**Key domain language**: message id (the phrase key a block was rendered from), stamp (the additive `source.messageId` field), id mode (ADR-107's choice for an entity to carry a message id instead of literal text), play-to-write (click a rendered paragraph, edit the phrase, replay to the same turn), ADR-255 message override (a story-side entry that overrides a platform message id).

### Phase 3: Play-to-write in Chord Writer (D2's IDE half, D4, D4a, D4b)
- **Tier**: Large
- **Budget**: 400
- **Domain focus**: SharpeeIDE Play panel (`tools/ide/SharpeeIDE/Play/`), StoryIndex's IR-phrase span resolution, the write-reconcile-recompile-replay loop (ADR-309), the ADR-255 message-override file for platform-id lines.
- **Entry state**: Phases 1-2 complete — every rendered block carries a message id, including descriptions.
- **Deliverable**: clicking a rendered paragraph in Play resolves its `data-message-id` (D2) to `IRPhrase.span` via `StoryIndex.swift` when the id is a story phrase, opening the editor at that file/line/column; when the id is a platform id (`if.action.*` and the rest of the language pack) with no existing story override, Play opens a new `adr-255-message-override-acl.md` `messageOverrides` entry in the story pre-filled with the pack's current text for that id (D4a) — reusing the existing ADR-255 artifact, inventing nothing new. Saving either kind reconciles the file (ADR-309's write path), recompiles, restarts the IDE's fixed play seed 42 (`PlayViewController.swift:29-33`, `__SHARPEE_PLAY_SEED__`), replays the command history, and re-renders the same turn with the new text (D4). Replay history is session-only — no sidecar written, a relaunch starts fresh (D4b). Integration Reality Statement (rule 13a) before declaring done: OWNED = the bundled toolchain's recompile+restart+replay path; REAL-PATH TEST = an XCTest that drives an actual edit-save-replay cycle against a real story, not a stand-in compiler. Guard against IR-field drift per ADR-333 Consequences: the test must fail by name if the `span` field is removed from the IDE's phrase index (project memory: the IDE decoder follows IR fields).
- **Exit state**: AC-4 passes — click paragraph → editor opens at the phrase's span, edited text replays into the same turn with the seed and command history unchanged; deleting `span` from the phrase index fails the test by name. AC-2b passes — clicking the `Taken.` paragraph after `take apple` in a story with no override opens a new `messageOverrides` entry for `if.action.taking.success` pre-filled with the pack's text; saving changes the paragraph on replay.
