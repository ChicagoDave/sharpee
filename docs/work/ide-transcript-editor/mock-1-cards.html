Cards over a model

ADR-300 Q1, option A. The editor parses the transcript into turns and renders each as a card. Assertions are edited through controls, never by typing brackets.

Branch columns on the left are transcript files (ADR-300 D2), not tree paths — each column is something you can commit and diff. The badge colour is the last run's verdict for that turn. Selecting a column opens it as cards.

The bet: authors never see the grammar. The risk: a round trip through the parser reformats files people hand-wrote — comment placement, blank lines, block indentation. That is Q1.

Every assertion form in the grammar has a control here — Change… opens contains / not contains / exact / events / state / fail / todo / skip. Nothing offers removed grammar (D5).
Reads well: the file is never visible, so the grammar cannot be got wrong; `[EVENT:]` sits beside the turn that emitted it, which is the first time it has ever been visible next to its cause. Reads badly: nothing shows you the file you are committing, and a 60-turn walkthrough is 60 cards to scroll.
