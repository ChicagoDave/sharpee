## Decisions for David (ruled at plan approval)

Approving the plan as written takes each recommendation that remains open. Each is a place the code forces a reading of ADR-407 that its accepted text did not spell out. `plan-review` (2026-11-22) found that D-1(a) contradicted ADR-407 D8 and ADR-321 D16, and that D-2, D-3, D-4 and D-6 departed from ADR-407's wording. David ruled "amend", so ADR-407 Amendment 1 now records D-1(b), D-2, D-3, D-4 and D-6 as written below. D-5 was ruled at approval (David, 2026-11-22: "yes, approved — start Phase 1", to the plan with D-5 as a plain dependency pinned to 14.20.0).

- **D-1. Where `tokenizeProse` lives. Settled: (b), ADR-407 Amendment 1.** It moves with the heuristic to `@sharpee/lang-en-us/nouns` and becomes `NounExtractor.tokenize`. ADR-321 D13's unnamed-tool check (`packages/world-index/src/unnamed.ts`) takes the extractor and tokenizes through it, so there is one tokenizer, as ADR-321 D16 requires. Rejected: (a), keeping it in world-index with a copy in lang-en-us, because it gives the heuristic two homes, against ADR-407 D8.
- **D-2. How world-index's tests reach an extractor, and where the corpus pins live.** lang-en-us becomes a devDependency of world-index, for tests only; a test greps `packages/world-index/src` and fails on any lang-en-us import. The `deriveIncomplete` count pins stay in world-index and are re-recorded after the census (ADR-407 Consequences). The extractor-level cases move to lang-en-us. AC-4's unit half ("on the D6b corpus, its output contains every phrase the heuristic alone produces") lives in world-index, because the corpus passages come from world-index's `collectProse`. **Settled: ADR-407 Amendment 1 (D8)** says this. The count pins stay because they test the derivation, not the extractor.
- **D-3. What `analyzeStoryIR` takes.** It takes a lookup from a language code to an extractor (or a refusal), not the extractor itself, and applies it to the IR's `phrases.defaultLocale` once the IR is read. `deriveIncomplete` and the document builder take the extractor, as D8 says. The lookup and its refusal sentence are one pure helper in if-domain beside the contract (the module name for a code, the shape check, the one-line refusal), so the lens, devkit and world-index's `cli.ts` print the same line (AC-2). **Settled: ADR-407 Amendment 1 (D8).** Placement settled by ADR-407 Amendment 2 (Phase 2, session 337133): contract and helper live in `packages/if-domain/src/nouns.ts`, exported from `@sharpee/if-domain/nouns`, with only the types re-exported from the root, because the helper at the root grew the story runtime by 643 bytes. Readers import the lookup from the subpath.
- **D-4. The mismatch case's test.** The lens's guard is a pure function, unit-tested on all three cases (no extractor, mismatch, match). The no-extractor case also runs end to end through the real CLI on an edited IR copy. The mismatch case has no real-path test until a second language exists, and that is recorded as the rule 13a stub justification. **Settled: ADR-407 Amendment 1 (AC-2).**
- **D-5. compromise as a dependency or an optional peer** (ADR-407 D3 leaves it to the language package). **Recommendation: a plain `dependencies` entry pinned exactly to `14.20.0`.** An optional peer would leave a published `sharpee world-index` refusing English, while AC-3 already guarantees the story runtime never carries it.
- **D-6. The Fernhill lens pin is removed from the lens suite in Phase 1 and OB-35 is recorded on orchard** (finding 2; ADR-407 Amendment 1, AC-5). Removing a test block is not a file deletion, but the block is still listed to David before it goes.
