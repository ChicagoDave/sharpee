# Session Plan: Engine-version banner reads stdlib's stamped constant unconditionally; per-story courier route deleted

**Created**: 2026-09-11
**Plan Status**: DONE
**Overall scope**: Every reader of the engine-version banner text (the `version`/`about` actions, the `info` channel/DOM attribute, and the `game.started` opening-banner render) switches from a per-story-stamped `StoryInfoTrait.engineVersion` value to `packages/stdlib/src/actions/standard/version/engine-version.ts`'s `ENGINE_VERSION` constant read unconditionally; the four other stampers of that value (`tools/repokit` story stamper, three `devkit` stampers, three browser-entry templates) and the field itself are deleted from `StoryInfoTrait`, `BrowserBuildEnv`, the story-info projection, and every generated `version.ts`.
**Bounded contexts touched**: `world-model` (StoryInfoTrait), `engine` (story-info projection, game-engine.ts, prose-pipeline banner render, GameStarted event), `stdlib` (version/about actions, info channel), `platform-browser` (info-channel DOM consumer), `devkit` (version-stamp, browser-core, build-browser, publish, entry templates), `tools/repokit` (per-story stamper), `stories/*` (generated `version.ts`, `index.ts` call sites)
**Key domain language**: N/A — this is infrastructure/build-plumbing work, not domain modeling; `StoryInfoTrait` and `storyInfo` capability are pre-existing platform concepts this plan trims, not extends

## Phases

### Phase 1: Repoint every banner/action-report read site to the stamped constant
- **Tier**: Medium
- **Budget**: 250
- **Domain focus**: `stdlib` actions (`version`, `about`), `stdlib` `info` channel, `engine`'s `game.started` banner-render path (`game-engine.ts` → `createGameStartedEvent` → `prose-pipeline/handlers/game.ts`/`banner.ts`)
- **Entry state**: Five stampers write `engineVersion` today; every reader falls back to trait-then-constant (`version.ts`) or trait-then-empty-string (`about.ts`) or trait-then-`undefined` (the banner path via `game-engine.ts:725`) — this last one is the actual behavior gap the goal names: a story whose loader never populates `StoryInfoTrait` (e.g. `story-loader`-based stories, per ADR-334 F1) never shows "Sharpee v..." in its opening banner today.
- **Deliverable**: `packages/stdlib/src/actions/standard/version/version.ts` and `.../about/about.ts` read `ENGINE_VERSION` unconditionally (no `trait?.engineVersion ||` / `storyConfig.engineVersion || ''` fallback chains); `packages/engine/src/game-engine.ts:725` passes the stdlib constant to `createGameStartedEvent` instead of `storyInfoTrait?.engineVersion`, so the `game.banner` `platform-version` block always renders; a decision recorded (in the conversation, not silently coded) on whether `packages/stdlib/src/channels/standard.ts`'s `infoChannel` and `packages/platform-browser/src/channels/info.ts`'s `data-engine-version` DOM attribute keep carrying the value (sourced from the constant, not the capability) or are dropped as redundant with the banner/about text — both call sites read `cap.engineVersion`/`data.engineVersion` today and must not silently start reading `undefined`. Behavior Statements (rule 12) for each changed report/render function; tests derived per rule 13 for the "no trait present → constant still renders" case specifically, since that is the gap being closed.
- **Exit state**: No source file computes engine-version banner text from `StoryInfoTrait`/the `storyInfo` capability; every read site imports or receives the stdlib constant. `StoryInfoTrait.engineVersion` still exists as a field but is dead — nothing reads it. `pnpm --filter '@sharpee/stdlib' test` and `pnpm --filter '@sharpee/engine' test --run` pass.
- **Status**: DONE
