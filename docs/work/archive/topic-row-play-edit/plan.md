# Session Plan: Facts-stamped ask/tell provenance + topic-row play-to-write (ADR-333 amendment)

**Created**: 2026-09-06
**Plan Status**: DONE (2026-09-06 ~02:05 CDT; all three phases DONE)
**Overall scope**: Give an ⌘-clicked "asked about an unknown topic" (or "not interested") reply in Chord Writer's Play pane a narrower fix than today's everywhere-override (ADR-333 D4a): (1) the engine stamps, beside `source.messageId`, the primitive top-level facts an event's data carried (who was asked, about what), so a client can distinguish "the gems stallkeeper, asked about gems" from every other unknown-topic reply in the game; (2) Play-to-write recognizes that specific shape and offers writing a `define topics for <entity>` row (merged into an existing block when the owner already has one) plus a new `phrase` naming the typed text, instead of the story-wide `messageOverrides` entry — with the everywhere override staying available as a secondary, explicit choice, never the bare click's default.
**Bounded contexts touched**: `packages/text-blocks` (the block field), `packages/engine` (the stamp site — `prose-pipeline/phrase-render.ts` and the one caller that holds the event, `handlers/domain-message.ts`), `packages/stdlib` (channel carry, `channels/standard.ts`), `packages/if-domain` (the `ProseEntry.source` wire type), `packages/platform-browser` (DOM attribute, `channels/prose.ts`), `packages/story-loader` (read-only fact-check: entity naming), `packages/chord` (read-only: `IRTopicRow`, the duplicate-topics-block gate) — no Chord grammar or IR change; `tools/ide/SharpeeIDE/Compose` (decoder — additive `hasTopics`/topic-block span on `Entity`), `tools/ide/SharpeeIDE/Play` (bridge — `facts` on the play-edit request), `tools/ide/SharpeeIDE/Play/PlayToWrite.swift` (a new resolver target and its pure helpers), `tools/ide/SharpeeIDE/Play/PlayToWriteCoordinator.swift` (the topic-row commit round), `tools/ide/SharpeeIDE/MainWindow.swift` (context-menu item for the everywhere override).
**Key domain language**: primitive facts (the event data's top-level scalar fields — `targetId`, `targetName`, `topic`, `topicEntityId` — excluding `messageId`/`params`/`message`/`text` and anything non-primitive; additive, absence means "no facts"), topic row (a `define topics for <entity>` block's `about "<topic>": phrase <entity>-on-<topic>` pair — the entity-specific fix), everywhere override (ADR-333 D4a's story-wide `messageOverrides` entry for a platform message id — the fix this plan narrows, kept as a secondary path), block-merge gate (`analysis.duplicate-topics-block`, `packages/chord/src/analyzer.ts:1815` — one `define topics` block per owner; a second commit must merge into the first, never emit a second), asked/told unknown-topic (the `if.action.asking.unknown_topic` / `if.action.telling.not_interested` platform messages this plan's new resolver target is scoped to; every other platform message keeps the D4a fallback unchanged).
