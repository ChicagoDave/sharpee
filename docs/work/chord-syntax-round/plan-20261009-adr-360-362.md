## Sequencing rationale
- Phase 1 holds the two standalone defect gates that exist today (#573, #569) and the plan-document work, so later phases build on a parser that no longer swallows trailing words. ADR-360 D3a says its gate lands "with this ADR or before".
- ADR-361 (Phases 2-4) goes before ADR-360 because it is mostly removal and is independent of the room model. It regenerates the IDE protocol once (hatch fields out); ADR-360 Phase 7 regenerates again and checks 361's removal is intact (both ADRs require this check).
- ADR-360 (Phases 5-9) is split front-end to back-end to corpus: Chord compile first, then the exit table, then de-nesting in world-model/loader/protocol, then the corpus migration, then tooling. Its ACs are unfolded-head, so it does not need ADR-362.
- ADR-362 folds (Phase 10) come after the exit table so the one shared `exit` production exists, and so AC-1's mechanical fold can run over a corpus already migrated. Phases 5-6 and 10 are otherwise independent and could swap if David prefers.
- Independent within the plan: Phases 2-4 (361) and Phases 5-9 (360) share only the protocol regeneration and the story index; the ADR-349 plan rewrite (Phase 1) is independent of everything but must land before ADR-349 Phase 6 resumes.
- Between Phase 5 and Phase 8, Fernhill and the Secret Letter do not compile, because `containing` is a parse error before their migration. That is why the AC-13 baseline is recorded in Phase 1.
