### 2. Phase 1 — Parser (D1/D2)
- `packages/transcript-tester/tests/parse-baseline.test.ts` (new): a per-transcript AST digest snapshot over the whole in-repo corpus, written and captured **before** any parser edit — this is D2's regression safety net and AC3's evidence. Corpus is 182 files (later 183 with the new fixture).
- `src/parser.ts`: fence lexing (open = 3+ backticks, close must match opening length exactly, longer runs inside are literal per markdown's rule); attachment strictly to the line immediately following `[OK]` or a payload-less `[OK: contains]` (no blank line permitted); `readFence`/`skipInvalidFence` helpers; indexed parse loop so a fence consumes following lines; the new payload-less `[OK: contains]` form added to `parseAssertion` (previously this parsed to `null` and was silently dropped — the exact failure mode ADR-287 removes); line-numbered parse-error collection merged into `validateTranscript`'s return; a check in `finalizeCommand` that a fenced assertion doesn't also acquire the implicit-`[OK]` default.

- **Key constraint discovered**: stamping `lineNumber` on every assertion, or attaching `parseErrors: []` unconditionally, changes all 182 digests and breaks D2's regression pin. Both fields are therefore emitted only when actually populated — any future field added to these two types inherits the same rule.

### 3. Phase 2 — Runner + reporter (D1 comparison semantics)
- `src/runner.ts`: `[OK]` + fence → exact match of the fence content against actual output, both normalized through the existing `normalizeOutput` (unchanged). `[OK: contains]` + fence → normalized fragment, case-insensitive. Inline `contains "..."` is deliberately left matching its raw, unnormalized payload — the one place the two forms diverge, pinned by a test, since fact 5 in the plan established the inline path never normalized to begin with.
- `src/reporter.ts`: failing fenced assertions now display `Expected (fenced):`; `formatAssertion` handles the valueless fenced-contains case.
- **Two pre-existing reporter defects found and fixed while building this**: (a) a failing fenced assertion previously printed no expected text at all — the diff was keyed solely off `command.expectedOutput`; (b) the "Output" block dropped blank lines (`if (line.trim())`), and since `normalizeOutput` preserves paragraph breaks, a real exact-match failure could display as two visually identical blocks. Fix (b) is pre-existing and also affects the classic `[OK]` path, not just fenced assertions — **flagged as a judgment call for David**, since blank lines now print for every failing command going forward.
- Tests: `tests/fenced-runner.test.ts` (9), `tests/fenced-reporter.test.ts` (4).

Result: 6 passed + 1 expected failure, identical under `--chain`.
- **Finding for ADR-282**: `>`- and `#`-leading lines (from AC1) cannot come from a real Chord story — the compiler flattens a multi-line description block onto one line (verified in the compiled IR). ## Key Decisions

### 1. ADR-287 chosen as this session's track over resuming ADR-279
ADR-279 Phase 2 needs a Node-vendoring decision from David; ADR-287 has zero dependency on it, needs no Xcode/macOS/credentials, and unblocks ADR-282's D2 serialization contract, so it was the productive parallel work.

### 2. New parser fields are opt-in per-assertion, not universal
`Assertion.lineNumber` and `Transcript.parseErrors` are populated only when a fence or a parse error is actually present, specifically because the pre-change baseline snapshot (182 digests) would otherwise change for every transcript in the repo, breaking D2's "additive" guarantee. This is now the binding rule for any future field added to these two types.

### 3. Fenced `contains` normalizes; inline `contains` does not
Inline `contains "..."` continues matching its raw payload unchanged (pre-existing behavior, pinned by a new test). Fenced `contains` normalizes the fragment the same way actual output is normalized, because a multi-line fence fragment has no realistic chance of matching without it. This is a deliberate, tested divergence between the two forms, not an oversight.
