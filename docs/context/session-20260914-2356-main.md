### 2. D16a's entity-name fallback lives at the consumer, not in `resolve`
`world-model` has no language provider, so it cannot resolve ADR-107's `nameId`. `LocationHeadingBehavior.resolve` returns an empty list when no contributor produced a part, and each consumer (Phase 4's job) falls back to what it renders today. This is a reading of D16a, not a change to it — filed as an owed ADR amendment (issue #470).

### 3. A third analyzer gate beyond D15's named two
`analysis.room-name-variants` rejects `or`-separated variants inside one arm, because D11's contract carries exactly one resolved-prose text per arm and `LocationNameArm.text` is a single string. Filed as an owed amendment (issue #471).
