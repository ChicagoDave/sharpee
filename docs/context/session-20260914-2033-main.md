### Phase 4 — the storage adapter (PASS, with one leg owed)
- The interface works identically in **Edge 153, Safari 26.6.2 and Firefox 155**, and the same compose → play → test call path from Phases 2–3 runs over it unchanged: compose 14.9–19.1 ms, 66 entities and the real opening prose, `runTreeDocument` at 11 lines / 222 commands / 85 authored / all passing — **matching the Node CLI exactly in all three engines**.
- **OPFS proven as a working copy, not a fallback**: a reproducible archive (`sha256 e08c6624…`, 10 entries) wiped-and-imported per-file-identical in every browser; exported back to a 127,511-byte archive (`sha256 103391cb…`, identical across all three), re-opened in the page **and** decoded and unzipped outside the browser in Node, matching the fixture hash for hash.
- **The structural finding**: OPFS and the File System Access API expose the *same* `FileSystemDirectoryHandle`, so read/write/list/delete are one implementation over both. What differs is handle acquisition, `externallyMutable` (which makes `watch` mean two different things — neither route has a change-notification API, so it polls and says so), and whether the store needs an import/export door.
- Selection rule: the author's folder whenever reachable without asking, otherwise OPFS — automatic, author-visible, author-overridable, and a forced-but-unreachable route is **refused, never silently substituted** (proven). Cloud adapters named as cost, not built.
- **Unplanned dividend**: Phase 3's full round trip re-run unchanged in Safari and Firefox reproduces **exactly** — 274 / 263 / 11 / 11, 86→87 cards, 21,412 chars. The 274 arithmetic is not a Chromium artifact; four hosts now agree on this document byte for byte. Added to #462.

## Key Decisions
1. **Phase 3 covers both halves the plan named.** The parity round trip (as the two prior hosts ran it) *and* `runTreeDocument` in-page, because "no CLI to spawn" is the structural difference this shape has to answer for the Run column.
2. **A document-derived prediction was computed before the run**, so the record count is checked against arithmetic rather than judged plausible. The prediction was then reconciled term by term against the surface's actual driver semantics (`replayTree` / `driveFreshBoot`).
3. **The write leg ran on OPFS rather than the author's folder, and the record says so.** Phase 1's stored handle was gone; `showDirectoryPicker()` needs a user gesture, so a self-driving page cannot recover one. Rather than stall on David's click, a two-adapter storage seam was built (Phase 4's own deliverable (1), arriving early because Phase 3 needed somewhere to write) and the round trip ran on OPFS with the route named in every readout. A one-click **Use real folder…** button re-grants it whenever someone is at the keyboard.
4. **Module-resolution shims are named as shims, and refuse rather than fake.** `fs` and `module` throw by name so a reached filesystem path dies loudly; `path` is implemented correctly; the narrow `@sharpee/transcript-tester` barrel re-exports the package's own source. Across 222 commands the `fs` shim was never reached.
5. **Phase 4 ran on OPFS across all three browsers rather than waiting for a click.** That is exactly what the plan asked for in Safari and Firefox (no folder API there at all) and a substitution in Edge. The owed leg is named precisely: `list`/`delete`/an `externallyMutable` watch observing an edit made *outside* the browser — the one behavior OPFS can never demonstrate. `phase4.html?prefer=folder` runs the whole exercise on the real directory after one click.
6. **No screenshot was shipped for Phase 6.** A headless capture races the page's async run and would have shown an empty pane and the pre-flip palette. The pane's rendering is evidenced by a DOM query (`renderedGroups: 7`) and the flip by computed `rgb()` values either side — stronger claims than an image, and the record says why the image is absent.
7. **The plan's hypothesis about `runner.ts` was wrong and is corrected in the record.** `packages/branch-tester/src/` imports no node builtins at all; the barrels, not the logic, are what block a browser build.
