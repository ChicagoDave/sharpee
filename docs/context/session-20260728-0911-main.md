- New `tools/ide/SharpeeIDE/Workspace/StoryHome.swift` owns `~/Documents/Chord` and resolves `<root>/<story-id>/`, reusing `StoryScaffold.storyId(from:)`; root is an injectable defaulted parameter, not global state.
- `AppDelegate.newStory(_:)` no longer forces an `NSSavePanel`; the prompt is Create / Choose Location… / Cancel, with Create going straight to the default home and the picker kept as an opt-in path.
- Mutation-verification finding acted on: the first draft's test-gap note wrongly blamed the whole AppDelegate half on modals. Fixed by splitting presentation from mutation — `scaffoldStory(at:title:templateDirectory:)` and `scaffoldStoryAtDefaultHome(title:in:templateDirectory:)` return the created directory; `loadProject`, `presentScaffoldFailure`, and the button prompt stay thin wrappers. This also removed duplicated create-and-open logic across the two New Story paths.

### Phase 2 — typed-artifact sidebar (implements ADR-280 D1) + Reveal in Finder (Q-3)
- New `tools/ide/SharpeeIDE/Project/ProjectArtifacts.swift` (UI-free) classifies a project into six groups in D1 order: Story, Walkthroughs, Transcript Tests, Assets, Web Template, Other. Web Template is a genuine lens over two on-disk locations (beside `.story` plus `browser/` escapes); Transcript Tests reaches through `tests/` into `tests/transcripts/`.
- `ProjectTreeViewController` renders groups as top-level rows and gained a "Reveal in Finder" context menu (`revealTarget(forRow:)` resolves per row kind, falling back to the project root for scattered groups or empty-space clicks).
- Two rulings made and recorded: (a) mine — a group with nothing on disk yields no row at all, not an empty one; (b) David's, from reviewing the fernhill screenshot — the sidebar opens with every group collapsed except Story, because fernhill's 17 transcript tests pushed later groups below the fold.
- Confirmed by David against the real `stories/fernhill/` project: all six groups render with correct membership (Web Template correctly showing only `browser/index.html`, Assets keeping `audio/`/`images/` expandable, `chatgpt-review.md` surfaced under Other).
- Forward-compatibility for ADR-284/285 discharged by construction: `ProjectArtifacts.groups(for:)` is a programmatic query (not just UI state), and Assets uses the same generic file cell as every other group so a future thumbnail/preview manager can replace the row view without touching the grouping model.

### Side task — SF Mono font (not part of the ADR-280 plan)
- `FontFamily` gained an `sfMono` case, surfaced automatically in the Font menu (`MenuBuilder` iterates `allCases`).
- Verified on this machine that `NSFont(name: "SFMono-Regular")` misses (the face ships inside Terminal.app's Resources, not registered system-wide), so the family resolves via `monospacedSystemFont`, landing on `.AppleSystemUIFontMonospaced-Regular`.

## Key Decisions

### 1. ADR-286 does not go first
David asked whether ADR-286 (Web Template layout DSL) should be implemented before ADR-280. Answer: no — ADR-286's spec (`docs/design/template-dsl/design.md`) is a 36-line sketch, not a frozen grammar, and its Q-5 (slot label delivery) is unresolved and blocks part of D1/D2. Recorded as a prerequisite: ADR-286 needs a grammar-freeze design session with David before any implementation.

### 2. Plan carved into 4 phases to unblock Phase 1 immediately
plan-review surfaced a real CONTRADICTION: `sharpee init`'s Chord path writes `package.json` (`packages/devkit/src/standalone/init.ts:178-181`), the exact divergence ADR-258 D2 names as something that must not happen. Rather than block all work on resolving this in devkit, David asked to carve out the default-folder work (D2) as its own phase — it touches no `packages/` code and doesn't depend on D3/D4 or ADR-286. The planner's original 3-phase plan was amended to 4, inserting the new Phase 1 and renumbering the rest.

### 3. No-group-if-empty vs. always-show-six-groups
Ruled (mine, flagged to David and accepted): a project with nothing on disk for an artifact type shows no row for that type, rather than an empty placeholder row. Phase 3's seed will make new projects show all six regardless; this only affects pre-existing projects like fernhill.

### 4. Collapsed-by-default sidebar groups (David's ruling)
The first draft opened every group. David's review of the fernhill screenshot showed 17 transcript tests pushing Assets/Web Template/Other off-screen, so the sidebar now opens with every group collapsed except Story. Pinned by test, plus a second test proving a collapsed group still holds its members and reveals them on expand.
