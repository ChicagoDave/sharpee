## Key Decisions

### 1. Reclassify mid-phase rather than defer to a later phase
When `chord.ebnf` and `transcript-testing.md` turned out to be load-bearing (a build gate and two published README links respectively), they were pulled out of `docs/unofficial/` and relocated to their correct owning locations within Phase 1, rather than left broken and deferred. Rationale: leaving a broken build gate or a broken published-README link mid-session, even temporarily, is worse than the small scope increase of fixing it in the same phase — and it directly informs Phases 2 and 3, which move much larger sets of files on the same "safe to archive" assumption that just proved wrong twice.

### 2. Fix the website `chord.ebnf` drift but not the underlying duplication
Syncing the stale published grammar file was treated as a same-session correctness fix (a live, user-facing bug), while building a mechanism to keep the two copies in sync was treated as an out-of-scope build-system change requiring separate discussion. The distinction: fixing a discovered bug is in scope for any session; adding a new build step or test is a platform-adjacent change that needs explicit buy-in first.
