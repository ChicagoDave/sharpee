## Key Decisions

### 1. B2a stays open rather than being stubbed
Cold-checkout verification of `./repokit build` (has it ever run from a clean CI tree?) cannot be exercised without a real workflow trigger. Rather than fake it locally, it is deferred to Part D's first dry run — the actual CI environment is the only honest place to test it. **Resolved this session**: D2's clean dry run (`c1f8eeea`) is the verification.

### 2. Code-side staleness found during the README audit was left untouched
Three platform-code issues surfaced while verifying READMEs against source (parser-en-us version metadata, ext-testing stale doc comments, map-editor's dead build-script reference). None were fixed this session: they live under `packages/`, and CLAUDE.md's "Platform changes require discussion first" rule applies. Parked in `docs/work/readme-audit/plan.md` rather than silently patched.

### 3. Hardcoded CI package lists replaced with `./repokit build`, not patched
The structural CI fix (`d6e0ffec`) didn't add `bootstrap` to the missing list — it removed the hand-maintained lists entirely in favor of the same orchestrator already relied on for local builds and the publish workflow. Same reasoning as B2: a human- or hand-maintained list of packages is exactly the failure mode npm-ci.md's §1.3 already diagnosed for the old publish job.

### 4. npm pinned to 11 rather than chasing npm 12 compatibility in-place
When `npm@latest` (12) broke tsf's `pack --json` parsing, the fix was two-sided: pin the workflow's npm version to 11 to restore a known-good baseline, and separately patch tsf (1.0.3) to handle both shapes. Pinning without the tsf fix would have been a permanent workaround; the tsf fix without the pin would have left CI on a moving target. The pin is explicitly temporary — see Open Items.
