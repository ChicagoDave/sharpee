## Completed
- **`PaneRelay`** (`tools/ide/PaneHost/Hosting/PaneRelay.cs`, new): the host half of the
  testing round trip. Queues each turn record the client posts and delivers it back through
  `IPaneDoor.EvaluateAsync` one at a time, in arrival order — the surface folds records by
  ordinal and forks a fresh boot when the sequence does not match, so overlapping deliveries
  make it replay the tree. Names no mechanism; the same relay serves every platform slice.
- **`ShellWindow` carries the panes**, not just a view of them: `OnPaneMessage` routes every
  page→host message (turn records to the relay, others recorded, arrivals counted), and
  `NavigateAsync` waits for the view's own `NavigationCompleted` instead of a fixed 1200 ms
  sleep, so "the pane loaded" is the platform's answer and a failure to load is visible.
- **`--pane-exit-state`**: Phase 4's exit-state run, in the real shell window, reading every
  claim back off the live page.
