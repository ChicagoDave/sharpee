## Key Decisions

### 1. Cross-assemble, don't build a second Windows-native assembler
David's ruling removed the premise ("the assembler runs on Windows") behind the estimate's "second script" conclusion. Steps 1, 2, 2.5, 4, 4.5 stay shared; only target-varying parts branch — one reason to change (rule 7), not two scripts drifting apart.

### 2. Flat pnpm closure via `--config.node-linker=hoisted`, not `cp -RL`
Measured this session: naive dereference of the symlinked closure (`cp -RL`) produced 523 MB against the original 69 MB, because pnpm's `.pnpm` store deduplicates and every consumer symlink expands to its own copy. pnpm's own hoisted linker mode reproduces the same 69 MB with only 3 residual symlinks (all `node_modules/.bin`), and simplifies the graft to one `rm -rf` + one `cp -R` instead of store surgery.

### 3. Ordering: prune the seal before any dereference/hoist
The deploy root's `@sharpee/devkit` self-link reads directly from the live checkout (`/Users/david/repos/sharpee/packages/devkit`). Hoisting or dereferencing before the seal-prune step would ship the developer's working tree inside the toolchain. This is now sequenced correctly in the script (seal prune precedes step 4.5's zero-symlink assertion for win32).

### 4. One layout, platform-specific leaf only
`node/bin/node` (POSIX) vs `node/bin/node.exe` (win32) — even though the official Windows zip puts `node.exe` at the archive root. Keeps the launcher, the seal scan, and PaneHost's resolution differing only by filename, not by path shape.
