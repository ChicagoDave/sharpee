### The finding: bridge vs. headless runner disagreed on paragraph boundaries
Verified in code: headless (`packages/bootstrap/src/index.ts`) joined blocks with `'\n\n'`, or `'\n'` when `tight`; the bridge (`packages/platform-browser/src/BrowserClient.ts`) built its payload from DOM children's `textContent`, always joined with `'\n'`, with no `tight` concept; `normalizeOutput` (`packages/transcript-tester/src/runner.ts:1590`) does not collapse blank lines. A two-paragraph response captured as `para1\npara2` would run headless as `para1\n\npara2` — every blessed verbatim multi-paragraph assertion would fail on first run. This put the bridge on the wrong side of ADR-282 D2's own rule ("DOM `textContent` is never the serialization source"), meaning **ADR-282 contradicted itself**: D2 required a bridge carrying channel-flattened text; Consequences forbade changing the bridge. Work stopped and the contradiction was put to David rather than resolved unilaterally.

### David's ruling: amend the ADR and fix the bridge — DONE
- ADR-282's Consequences amended to authorize two platform changes, with a dated amendment section recording the divergence as evidence and the rejected alternative (reconstructing block boundaries from `main-entry--tight` CSS classes, which would couple transcript serialization to class names).
- New `joinMainEntries` (`packages/channel-service/src/utils/join-main-entries.ts`) — the one definition of how a `main` packet becomes text. Both `bootstrap` (replacing its inline loop) and `platform-browser`'s `main` channel renderer (via a new `onEntriesText` callback) now call it.
- `BrowserClient` no longer reads the DOM for this: packets accumulate into a new `turnMainText` field per turn, joined with `'\n'` across packets — the same two-level rule bootstrap uses.
- `turn-events.test.ts`'s expectation updated (it encoded the old single-newline join) with a comment explaining the blank line is load-bearing, plus a new test pinning the tight case.

## Key Decisions

### 1. Amend ADR-282 rather than work around it
The self-contradiction (D2 vs. Consequences) was real, not a misreading. Fixing the actual serialization bug was the only option consistent with D2's own stated rule; the CSS-class alternative was rejected as coupling test serialization to presentation class names.

### 2. Shared `joinMainEntries` helper over duplicated join logic
Claude initially justified the shared helper via DEVARCH rule 8b (co-located wire-type sharing). David pushed back: "duplication is okay when there are two clear boundaries." Accepted counter: neither package gains a new dependency (both already import `@sharpee/channel-service`), and ADR-282 D2 requires the two outputs to be byte-identical — making this one contract with two copies, not two boundaries free to diverge. Ruling: keep it shared.
