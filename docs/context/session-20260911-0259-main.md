### Phase 1 implemented and landed
- `resolveRoute` extracted from `parseStage` (`packages/engine/src/turn/parse.ts`) so the meta/turn routing rule has one implementation and two callers.
- `executeTurn`'s guard narrowed via a new private `acceptsWhileStopped` (`packages/engine/src/game-engine.ts`): refuses before any stage runs unless the parse resolves to a meta command and no input mode is active.
- **Planned design rejected on evidence**: the plan called for running `SHARED_STAGES` through `parseStage` and refusing at the route switch. `undo-snapshot`, `turn-start`, and `input-mode` all mutate before the route is known — refusing there would overwrite the player's undo state with a snapshot of the dead world. Refusal happens before any stage instead, at the cost of one extra parse on the accepted path.
- `loadSaveData` and `undo()` now return a stopped engine to `playing` over the existing `stopped → playing` back-edge, conditioned on `phase.name === 'stopped'` (D8a's tolerance covers `playing`, not `ready`; 15 tests call restore into an engine never started).

### mutation-verification — three real defects found and fixed
1. The first undo-snapshot test drove `look`, which is in `MetaCommandRegistry`'s non-undoable list (`meta-registry.ts:185-195`) — the stage skips it regardless of this change, so the test could not fail. Rewritten against `north`.
2. An active input mode would still have consumed the line: `input-mode` runs before `parse` and `stop()` never clears the mode, so a meta-shaped line reached the handler before the route was consulted. `acceptsWhileStopped` now refuses outright while a mode is active.
3. **RESTORE at the end-game prompt reproduced GH #414 one level deeper.** `loadSaveData` replaced the world but never touched the phase, so a restore loaded a live save into an engine still refusing every command. Fix initially called `resume()` unconditionally, which broke 15 tests (`resume()` refuses the `ready` phase) — corrected to resume only from `stopped`.

## Key Decisions

### 1. Refuse before any stage, not at the route switch (Phase 1)
The plan's original shape ran shared stages through parse and refused at the route switch. Rejected because `undo-snapshot`/`turn-start`/`input-mode` mutate before the route is known — refusing later would let a dead world clobber undo state. Costs one extra parse on the accepted path; correctness over that cost.

### 2. ADR-347: the ending becomes a domain concept, not a guard
Rather than special-casing the browser's autosave to avoid persisting an ended world, the ending itself becomes representable (`IStoryEnding`, `endStory`, a channel sibling carrying state not prose). This is a larger, four-phase change but eliminates the four-way naming split and lets the restore seam (Phase 4) derive phase from the Ending directly, retiring Phase 1's `stopped`-resume patch rather than accumulating it as permanent lifecycle behavior.

### 3. First-ending-wins rejection rule for `endStory`
Modeled on `killPlayer`'s idempotence precedent (`engine/src/turn/detect-death.ts:26-28`) — pinned in ADR-347 D2d so no later phase re-derives it.
