### Failures exposed and fixed — one root cause, three sites
- `registerBasicCombat(world)` registers an interceptor binding on the world. That binding only becomes a `ResolvedConsultation` on `context.sharedData` when `resolveLifecycle()` runs, and `resolveLifecycle()` is called from exactly one place: `runValidatePhase()` in `packages/stdlib/src/actions/lifecycle/phase-runner.ts:76`. `attackingAction.validate()` reads that consultation at `attacking.ts:185` and returns `violence_not_the_answer` when it's absent.
- Three test files called the raw phases directly, bypassing the runner: `attackingAction.validate(context)` at `melee-villain-blow.test.ts:85`, `takingAction.validate(context)` at `troll-axe-behaviors.test.ts:65`, and the same inside `npc-attack-through-attacking.test.ts`'s `attackOnce`. No consultation existed in any of them, so every blow was refused. The troll-axe case is the same mechanism from the other side: its refusal IS the interceptor, so bypassing the runner returned `{valid:true}` where a refusal was expected.
- **Why they were stale** (the key finding): `phase-runner.ts` was created 2026-09-08 by commit `96aaff544`, "ADR-337 D1 — the interceptor lifecycle has one call site, the executor's phase runner (#379)". That commit migrated 62 test files to the runner across stdlib, story-loader, engine and chord. It touched zero test files in `stories/dungeo` or `packages/extensions/` (only dungeo's version stamp). GH #402's blind spot didn't just hide these failures — it caused them: the refactor updated every test the sweep could see, and the seven invisible packages were left behind. `packages/stdlib/tests/unit/actions/attacking-interceptor.test.ts` is the same test written correctly and passes.
- **Fix**: routed the three test files through the phase runner (`runValidatePhase`/`runExecutePhase`/`runReportPhase`/`runBlockedPhase`), matching what `96aaff544` did to 62 others. No source change in stdlib or world-model — the platform behaved as designed. Each edit carries a one-line comment naming ADR-337 D1. Also moved `npc-attack-through-attacking`'s third test off a bare `attackingAction.validate()` call — it passed either way, but as the "no interceptor → refused" control it's only meaningful on the real path.
