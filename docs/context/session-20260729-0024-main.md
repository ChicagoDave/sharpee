## Key Decisions

### 1. Obstacle check must not perform the mutation it's checking for
The failure view's first cut computed the re-bless refusal reason by calling `rebless` and catching — so merely selecting a failed row would have rewritten the transcript on disk. Fixed: `reblessObstacle` now computes the rewrite and discards it, one code path with no write. Pinned by `testAskingWhetherReblessIsPossibleWritesNothing`, which compares file bytes across every inspection call the pane makes.

### 2. Re-bless must not silently clobber an open editor tab
`openDocument` focuses an existing tab without re-reading disk, so a re-bless writing behind it would lose the author's unsaved edits, and a later save of that tab would lose the re-bless. `TestPanelView.hostReblessObstacle` lets the host refuse (checked at selection AND again at press, since a tab can go dirty while the comparison is on screen), wired via new `EditorViewController.hasUnsavedChanges(at:)`; `onDidRebless` calls new `reloadFromDisk(at:)` so the tab stops showing stale text.

### 3. Three re-bless scope decisions the ADR left implicit, each pinned by a test
Re-bless covers the VERBATIM bless only — `[OK: contains]` is a fragment the author narrowed deliberately, and widening it to the full new response would be the silent weakening D2 forbids. Blank new output is refused (a broken command, not a narrowed assertion). The block search is scoped to the command's own stanza, so a command with no bless can't accidentally match the next command's block.
