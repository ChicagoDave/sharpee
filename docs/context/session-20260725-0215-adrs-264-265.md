## Completed — ADR-264 end to end (Chord language 1.3.0 → 1.4.0)

Counters are **core grammar** (no `use` gate), at **story or entity scope**, stored in the serialized
world-state bag (`chord.counter.*`), so save/restore is free.

### P1 — declarations
`define counter <name> [starts n] [between lo and hi]` (story-global) and `counter …` in a `create`
block (per-entity). AST `DefineCounter`/`CounterDecl`; parser `parseDefineCounter`/`parseCounterLine` +
shared `parseCounterSuffix`; IR `IRCounterDef`/`IRCounterDecl` (`StoryIR.counters`/`IREntity.counters`);
analyzer `resolveCounter` (default-0, clamp starts, `analysis.counter-bounds` on empty range). Loader
seeds initial values via `counterKey`/`CHORD_COUNTER_PREFIX`.

### P2 — mutations
`raise`/`lower <target> by <n>` — bare (story-global) or possessive/`its` (per-entity). `STATEMENT_OPENERS`
+= raise/lower; AST `CounterMutateStmt`; IR raise/lower statement (`counter`, `owner: IRValue|null`,
`amount`). Analyzer builds counter-name registries (`storyCounterNames`, `entityCounterNames`) in the
pre-pass/`collectEntity`, resolves the target, and emits `analysis.unknown-counter`/`duplicate-counter`;
negatives rejected at parse. Runtime `execStatements` case: `counterKey` + `irIdOfValue`, read → ±amount
→ **silent two-sided clamp** (`counterBounds` from the IR) → write.

### P3 — condition reads (both spellings)
The hard part — Chord had no relational operators. Lexer emits a compound `compare` token
(`>=`/`<=`/`>`/`<`); parser recognizes symbolic (a `compare` token after the subject) and word forms
(`is at least`/`is more than`/`is at most`/`is less than`) in `parsePredicate`. AST `compare` Predicate;
IR `compare` IRCondition + a `counter` IRValue operand. Analyzer `resolveValue` reads a bare name in
`storyCounterNames` / a possessive in `entityCounterNames` as a counter operand, and the compare requires
a counter left operand (`analysis.unknown-counter` on a typo). Evaluator: `evalValue` reads the counter
from world state; `evalCondition` does the numeric compare — one choke point, so `when`/`while`/
`kill … when` all light up. Two AST-Predicate walkers gained the `compare` case.

### P4 — EBNF + version + real-path
chord.ebnf productions (`define-counter`, `counter-line`, `raise`/`lower`, `word-compare`/`compare-op`/
`counter-ref`); `CHORD_LANGUAGE_VERSION` **1.4.0** + re-pinned SHA (`57469cd7…`) + doc headers.
REAL-PATH: new `stories/counter-demo` (`define counter dread`, `raise dread by 20` in `on every turn`,
`kill the player when dread is at least 100`) — transcript **7/7** through `dist/cli/sharpee.js`: dread
rises, `$save`/`$restore` preserves the counter (death fires at the exact post-restore turn), the
comparison gates the death event.

## Key Decisions
1. Comparison syntax: **both** word and symbolic spellings (owner) → one IR `compare` node.
2. Counter storage: the serialized world-state bag, uniform for both scopes (no trait-attachment) —
   save/restore is free. Per-entity keyed by IR entity id (`chord.counter.<id>.<name>`).
3. A comparison's left operand must be a counter (the only numeric value a condition reads) — an
   undeclared name there is `analysis.unknown-counter`, not a silent symbol.
4. Per ADR-262 D8, per-entity **banding** stays out of scope — counters serve logic/conditions, not
   banded narration.
