Syntax-checked and dry-exercised as non-root; not yet covered by an automated test (see Mutation Audit).

### 5. Diagnosed the broken playground — and found `/play` is broken too
Ruled out, in order:
- **Stale artifacts on plover** (GH #358 / I-31861b-2) — the deployed Chord compiler reported current at 3.6.0 and the guard passed; **[reported by session, unverified]** — not independently re-checked during this write-up, and this is the one claim in this summary that future work should re-verify rather than take on faith.
- **The Next bump** — ruled out by timing and by the error signature (a missing engine method, not a Next/React runtime error).
- **A Malwarebytes Browser Guard `shell.js` ReferenceError** — a decoy; that extension reports `excluded:true` for sharpee.net, and the error is internal to the extension's own init path.

**Root cause (the deliverable), independently verified during this write-up** by reading both sides: `packages/engine/src/game-engine.ts:383` defines `installStory(story: Story): void` — there is no `setStory` method anywhere in `packages/engine/src/`. Three browser entry templates still call the retired name:
- `packages/devkit/templates/browser/playground-entry.ts.template:137` — `engine.setStory(story);` (serves `/playground`)
- `packages/devkit/templates/browser/browser-entry.ts.template:122` — `engine.setStory(story);` (serves `/play`, Fernhill)
- `packages/devkit/templates/browser/chord-browser-entry.ts.template:197` — `engine.setStory(story);` (Chord browser builds)

Browser symptom: `TypeError: l.setStory is not a function` in the bundled `game.js`. Both deployed bundles (`/playground` and `/play`) carry the engine's `installStory` but still call `setStory`.

**Why nothing caught it**: `.template` files are invisible to `tsc` — the rename compiled clean across all 31 packages when it landed, every gate passed, the engine suite was green, and `./repokit build` reported success. `esbuild` only inlines a template's content at bundle time, so the break is observable only in a browser. The playground's "4 examples compile clean" self-check exercises the Chord compiler, which runs before the engine is ever constructed — it never reaches the `setStory` call.

**Fix not applied.** `packages/` changes require discussion first (CLAUDE.md), and David is moving the fix to his laptop session, where it will land alongside two other major issues.
