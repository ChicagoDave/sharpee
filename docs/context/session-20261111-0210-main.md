## Key Decisions

### 1. Flag-entity references count over the whole IR, skipping `identity`
Counting every id-equal string can only withhold the warning, never add one; the save manifest had to be skipped because it names every entity.

### 2. A thing nothing references is not a flag entity
The rule needs at least one `change … to` or `is` use, so the warning does not double as an unused-entity lint.

### 3. Declare out-of-package reads per package, not as global dependencies
A `globalDependency` would invalidate all 33 test tasks on every story edit; per-package `inputs` keep invalidation narrow (a thealderman edit re-tests 3 packages, not 33).

### 4. Name gitignored build outputs as inputs, and exclude build trees from story globs
turbo hashes a gitignored file that `inputs` names, so a rebuilt bundle re-tests its readers; an unexcluded glob would hash every `dist/` and `node_modules/` under a story.

### 5. A story action's clause rule is stated at compile, not only at load (ADR-394 D9)
David's "A": a fix-it must name a form that loads, and a fact of the finished IR belongs in `validate-ir.ts` (ADR-389 D4) so compile and load agree. The standard-name exemption stays with the loader, which alone knows which standard actions consult clauses.

### 6. The test stories keep every obligation exactly and grow none (small-test-stories plan)
New tests pin new concrete values on the test stories; shapes no current test covers are listed, not added. OB-D1, ADR-365 AC-2's scale check, is the one obligation the gate drops. David ruled first to keep it on demand, then to let it go (Key Decision 11).

### 7. Phase 5 does not demand a green `pnpm test:scripts`
This was plan-review's contradiction: the suite is red today (587, 627). Before Phase 5 starts, David rules on each failure Phase 1 sorted as "not the story", and a fix that reaches a package's `src/` is not this plan's to make.

### 8. Four test stories, not fewer (small-test-stories Phase 2)
Sets A and C both hold claims, but different packages pin them for different facts (A the walk, C what `sharpee test` prints), so one story would let an edit for either package move the other's pins. B pads its set with wares that cannot matter, which would add an inert finding to every claim in A. D needs rules, endings and a fork, and no claims.

### 9. ADR-395: exploring tests run on test stories (process, ACCEPTED)
The rule, the location, the regeneration rule and the content grant are one record, so later plans' Demonstrations stop citing `./sharpee test` on a real story as a floor.

### 10. The claims file runs in branch-tester's one vitest pass (Phase 3)
`package.json` no longer runs the claims file as a second pass after the suite. Its 10 s bound is fifty times its measured 0.2 s walk, so it cannot starve the rest of the suite.

### 11. The scale check is let go (ADR-395 D8, amended on David's ruling)
Ruling 5 kept the Fernhill walk on demand. Its one run failed the 120 s bound, and David then removed Fernhill from testing: the test is deleted and nothing replaces it. Speed at scale is now something an author running `sharpee test` on a large story would notice, not something a test here watches.

### 12. branch-tester's turbo inputs name only what its tests read
`branch-stories/**` gave way to `test-stories/**` plus the two fragments `claim-fragment-gate.test.ts` reads, so editing a real story no longer re-tests branch-tester.

### 13. The breaking edit reaches its budget stop through an edible's servings (Phase 4)
The walk tells states apart only by what `necessaryIdentity` hashes, and a counter is not in it, so a hundred-serving biscuit stands in for Phase 2's unbounded counter; the stop lands at depth, in about half a second, where UPPS's spent 120 s.

### 14. devkit's turbo inputs follow the same rule as branch-tester's
`branch-stories/upps/**` gave way to `test-stories/ferry/**`; `branch-stories/fernhill/**` stays only because `browser-core-build.test.ts`, a structural reader, still reads it.

### 15. The narrative suites hold to orchard by default, and Fernhill stays only for the structural suite (Phase 5)
`narrative-holds` always runs orchard and runs a second story only when `NARRATIVE_STORY` names one; `narrative-world-tab` analyses Fernhill's source without walking it, so it stays, and `story-run.ts` keeps `FERNHILL_STORY` for it alone.

### 16. #587's stderr cause is recorded, not fixed (Phase 5)
Removing the wall-clock line from the claims report is a change to `packages/branch-tester/src/`, which this plan does not make, and orchard prints no claims report, so the cause is dormant rather than gone.

### 17. The explorer lens pin stays where it is until the lens works (Phase 6, ruling 7 rewritten, David's "A")
A pin re-recorded on the orchard would capture a broken tool's empty output, and that is not a regression record. So OB-35 is the one obligation with no test-story home, and its move waits on 583. Repairing the lens is not this plan's work.
