## Key Decisions
- Play-to-write is ⌘-click, not click: a plain click on prose is reading/selecting/refocusing the input today and stays so.
- The history is captured off the page's command echoes at the click and held in Swift memory only (D4b); the reload after the build replays it through the client's own input.
- Description ids resolve to the RAW template (`getTemplate`), not the substituted message: descriptions are author prose bound verbatim, and `getMessage` conjugates any single braced word (`{trapdoor}`). This changes the room handler's pre-existing ADR-107 path for every story; no in-repo TypeScript story uses `descriptionId` (Dungeo: 0), so nothing in the repo is affected. A future TS story with `{You}` in an id-mode description sees it verbatim — the same as the literal path.
- The snippet marker rewrite lives on the registered template and is computed from the IR alone, so it holds in either order of `extendLanguage` / `initializeWorld` (bootstrap runs language first; bridge/runtime too).
- No dedicated examining handler existed; `tryProcessExamined` is consulted before the domain-message path for `if.event.examined` only — no generic "any `xId` param resolves" magic.
