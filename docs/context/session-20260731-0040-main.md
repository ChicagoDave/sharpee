## Completed — Part 2: the two amendments

### ADR-178 Amendment 1 — baseline v2 adds `@sharpee/helpers`

The Invariant-4 justification is a contradiction in the accepted record, not a
preference: ADR-237 D1 makes story authors helpers' *exclusive* audience
("platform packages must not depend on it"), while ADR-178 Invariant 2 forbade
stories from importing anything off the baseline — and helpers was off it. Every
consumer that used it was in violation. `BASELINE_VERSION` 1 → 2; add-only, so
Invariant 3 holds. The amendment records explicitly that the baseline governs
*what stories may import*, never what platform packages may depend on, so
ADR-237 D1 stands unamended.

### ADR-140 Amendment 1 — the prototype augmentation is retired

`createHelpers(world)` becomes the only entry form. The mechanism is unsound
across module-graph boundaries: the patch mutates whichever `WorldModel` class
object the *importer* resolved, so wherever the engine and the story resolve
separate copies the patched class and the instantiated class are different
objects. The browser build worked only because it is a single module graph — a
coincidence of that target, not a property of the design.

This is a removal of dead code rather than a reversal of a live mechanism, and it
is what ADR-140's own Design Principle 3 asks for ("No hidden magic … syntactic
sugar, not a new abstraction layer").

## Key Decisions

### 1. Both amendments, because the blocker's "mutually exclusive" framing was wrong
Baseline promotion alone leaves a mechanism that breaks across every bundle
boundary, still taught by the README. Retirement alone leaves helpers unusable by
any Zifmia story, ADR-178 and ADR-237 still contradicting. They answer different
questions; #146 needed both.

### 2. The REAL-PATH test is a standing gate, not a scratchpad run
First pass verified the Done-when with a throwaway external fixture. That is
one-shot proof, and rule 13a says fix the harness rather than accept a weak gate.
`external-story-boundary.test.ts` now materializes the fixture into a temp dir at
run time — `dist/index.js` plus a `node_modules` symlinking the workspace
packages — and spawns the production bundle against it. Symlinks rather than
copies so it always runs against the current build.

### 3. The fixture reports its own boundary state
A "it ran and printed the room" test would pass vacuously if the fixture ever
stopped straddling two module graphs. The fixture emits `[boundary]` diagnostics
and the test asserts on them, so the precondition is part of the gate.

### 4. Do not touch ADR-150 or the v1.5.0 tutorial edition
ADR-150 carries an incidental `import '@sharpee/helpers'` in an example; it is
outside the ruling's scope and flagged rather than edited. The v1.5.0 edition
correctly documents its own platform version and pins the published 1.5.0
package.
