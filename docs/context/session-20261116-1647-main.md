## Key Decisions

### 1. The reads table is a pure module on its own subpath
The browser-bundled assertion core cannot import `platform-state-writes.ts`, which pulls world-model in at runtime. A dependency-free module, published as `@sharpee/story-loader/platform-state-reads`, serves the assertion core, the derived runner, `arrange()` and the evaluator from one table.

### 2. Arranging a platform word on a switchable light moves the switch and the flame together
Before, arranging `on` wrote only the switch. `arrange()` now writes the `change` statement's own rows, so arranging `on`, `off`, `lit` or `unlit` matches what `change` does.

### 3. A claim's `lit` reads the flame's own flag
The table reads `isLit`, while the story's `is lit` still asks `LightSourceBehavior.givesLight`, which also needs power. For an unpowered switchable light the two can disagree. The module header states this as an invariant, and #735's original fix note asked for the `givesLight` reading instead. David has not ruled on it; the comment on #735 records the question.

### 4. Every answering trait runs, refusals are settled before any body, and firings are recorded after the whole command passes
David approved this mid-session, after the session stopped and reported the finding. The session first recommended option A (sibling guards alone) on a wrong premise. It corrected that after playing the fixture by hand, and the final shape is parts 4 and 5 together. The change may be ADR-worthy; David has not been asked.

### 5. Chapter 24 was rewritten now, on an ambiguous "yes"
David answered "yes" to an either/or question about chapter 24, and the session read it as "rewrite now". The edition is still pinned to published 4.0.2, which runs only the first trait's clause. Chapter 24 therefore describes in-repo behaviour ahead of its pin (#755).
