## Completed

### 1. Ruled B3 and B4, folded as ADR-291 Amendment A2
- **B3** (story stream access): ruled *derived from the registration identity, never named by the story*. The ruling came from applying David's elegance constraint — the rule must hold for Chord as well as TypeScript. Chord's entire randomness surface is three constructs (`one chance in <n>`, `select … randomly`, `move-chance`), none of which names an entropy source, and Chord has no setup block, lifecycle hook, or factory. A rule only a TypeScript story could obey would have been one contract on paper and two in practice.
- **B4** (id determinism): restated as a containment invariant — an id holds a static prefix and a per-session counter, nothing else — after finding ~49 clock-only id sites that a `Math.random()`-derived enumeration could not see.
- Count correction: 30 platform + 2 dungeo = 32, not "32 platform plus 2".

### 7. Confidence laundering — the finding worth keeping
The review caught ADR-293 asserting "event ids and timestamps never appear in prose output" as established fact. ADR-291's Context had said the same claim was *"not established; it is assumed not to, which is not the same thing."* Tracing it: the sentence originated in Fable's round-2 response, written without a check; ADR-293 inherited it, briefly re-hedged, then reverted to the confident form. Each hop dropped the hedge and kept the prose.

The claim turned out to be true — verified independently this session (zero `.timestamp` in `lang-en-us/src`, `text-blocks/src`, `channel-service/src`; prose-pipeline's `.id` uses at `pipeline.ts:152,163,194` are entity ids for scope filtering; walkthrough saves use authored directives). The defect was stating as established what had only been repeated.

Saved as a working rule: **a claim that gates an acceptance criterion carries its evidence inline — the command and its result, dated — never a citation to a prior document's assertion.**

## Key Decisions

1. **ADR-293 ACCEPTED**, superseding ADR-291 (ACCEPTED) and ADR-292 (DRAFT). Neither predecessor was ever implemented.
2. **Per-point streams over per-domain.** Draw-count coupling becomes internal to a point, which is what makes zero-draw class forcing coherent.
3. **Declaration is the capability to draw.** The draw API accepts only handles, so the catalog is complete by construction and the never-fired column works without a static scan.
4. **Forcing is the primary author instrument**, with per-point seed override as the pure-replay middle rung and search as a budgeted first-firing fallback. Grounded in the measured ≈623 nodes/second.
5. **`RandomService` interface in core, instance in engine** — forced by the verified fact that no drawing package can import engine.
6. **The acceptance bar is byte-identical rendered text.** Byte-identical event streams and saves are deferred as an optional track.
7. **Acceptance approves the design, not the build.** Phase A is a platform change across ten packages and still requires its own discussion.
