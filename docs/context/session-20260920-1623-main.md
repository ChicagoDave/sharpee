## Key Decisions

### 1. Location is not a valid state-equivalence key (correction 1, withdrawn)
Room-scoped and subtree-scoped invariants were proposed, then withdrawn on David's correction that a branch at a location can recur since world-model state and story progression decide it, not the room. The only sound equivalence by path remains identical command prefix at the pinned seed — which is what replay already rests on.

### 2. Memory is tracked but monotone (correction 2, confirmed in code)
David flagged that Sharpee tracks memory, so wandering isn't state-neutral. Confirmed: `RoomTrait.visited` (`packages/world-model/src/traits/room/roomTrait.ts:33,128`) flips once behind an idempotent guard in `RoomBehavior` (`roomBehavior.ts:160,164`); `CharacterModelTrait` carries told-records and per-pair conversation memory (`characterModelTrait.ts:109,257,277`, ADR-320 D4/D6/D9, ADR-310 D17); `examining.execute` is empty/read-only by construction (ADR-228 interceptors are the escape hatch). Because the memory is monotone (flags one-way, records only grow), it partitions the hash space into a few forward-only classes rather than scattering it — turning the "catch" into an argument *for* hashing rather than against it. Cost: probe purity degrades from a per-verb guarantee to a per-probe measured fact, with an order-independence check (probe set forward then reversed from one restore) as the honest replacement.

### 3. Two hashes, not one
The state hash (over the save payload, excluding `turnCount`/`playTime`/`description` per `packages/core/src/types/save-data.ts:28-43`, hashed pre-gzip with key-order canonicalization) answers "can I restore instead of replay" — a performance key. A separate observation hash (over responses at a node, relative to a probe set) answers "have I already tested this situation" — the coverage key David's wandering case actually needs. Conflating them was the first framing's mistake.
