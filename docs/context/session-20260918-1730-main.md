## Completed

### Defect fixes (wave 1, all against the shipped Avalonia app)
- **(1) Rail glyphs follow the palette.** `ProjectToggle`/`BottomToggle` are plain
  `Button`s and never had a `Foreground`, so they kept FluentTheme's own ink — which
  tracks the *system* variant — while the shell forces its palette dark at startup.
  `PaintChrome` now assigns `ThemeTokens.Foreground` to both, so they flip with the rail.
- **(2) The project pane collapses.** The toggle set `ProjectPane.IsVisible` while the
  pane's grid column stayed a fixed 220 px, so the pane blanked and the hole remained.
  New `SetProjectPaneVisible` drives the column (and its splitter) to 0 and restores the
  remembered width on reopen — the same move the shipping app makes
  (`SharpeeIDE/MainWindow.swift`, `applyProjectPaneVisible`). The show/hide decision moved
  to a pure rule, `Shell/ProjectPaneLayout.cs`, with 5 tests — mutation-verification
  flagged that the original probe only logged the state, never asserted on it.
- **(4) The relay delivers a batch, not a record.** `PaneRelay.DrainAsync` awaited one
  `EvaluateAsync` per record; the shipping Swift app posts each without awaiting and
  WebKit coalesces them. Per-record delivery was not just paint cost — it kept tripping
  the testing surface's own ordinal-mismatch guard, forking a fresh boot and replaying the
  whole tree each time. It now drains the whole queue into one script. Measured, two runs
  per arm: per-record 37.4s/37.4s, 1081/1079 boot records, 720 cards, 4579/4567 anchors;
  batched 4.1s/4.5s, 17/28 boot records, 169 cards, 364 anchors — batching is ~9x faster
  because it removes a replay storm, not because it paints less.
- **(5) The splitter grips reach past the gap they sit in.** First attempt (a
  `Margin="-4,0"` reach past a 4px track) was **wrong and is backed out**: a negative
  margin moves where the Grid *arranges* the splitter, so every drag started from an
  offset position (David: "panel sizes jump") and the reach only won hit-testing on one
  side (David: "the grabber shows moving right but not left"). The track itself is 10px
  now, the grip is the track, and `ResizeDirection` is stated rather than inferred. The
  bottom splitter is shown/hidden with the panel it resizes, so it no longer overhangs
  the editor's edge with nothing below it to drag.
- **(6) The run bridge was never implemented in this head.** The testing surface's Run
  button posts `{run:true}` on the `testingSurface` handler; `OnPaneMessage` filed that
  under "last post" and did nothing, and there was no `runLine`/`runExit` relay back — so
  the button could only ever hang. It now runs the shipping app's own arguments
  (`test <story> --tree --capture-output --capture-world --json`), streams the NDJSON into
  the run column through a second `PaneRelay`, and always closes with `runExit` —
  including for the three refusals (no story, no toolchain, already running), because
  silence was the defect. Verified by clicking the real element in the packaged bundle
  against secret-letter: `Run` → `Running…` → 690 NDJSON lines relayed → back to `Run` in
  ~6s, run column rendering PASS with per-assertion verdicts, 1217 rows — a real subprocess
  integration with a genuine real-path test, not a stub.
- **(7) Word wrap on by default**, since story prose lines run long. View ▸ Word Wrap
  still turns it off.
- **Two probe defects found by (6)'s real-path test.** `--app-exit-state`'s save step wrote
  its marker as `// …`, which Chord rejects as an unknown declaration, and it restored the
  file afterwards but not the editor buffer — so anything that saved later wrote the bad
  line back. Both fixed; the marker is now a `##` comment with the blank lines Chord
  requires either side of it.
- **(8) The build report.** The CLI's `build` output stops at `npx serve`; the closing
  banner is the app's own. `Shell/StoryBuildReport.cs` derives the same from the IR the
  build emits, with the same counting rules (an entity counts once in the first bucket it
  matches, a dotted phrase key is a platform id and is not counted, a zero count is
  omitted). Against secret-letter it reproduces David's pasted banner exactly —
  `21 rooms · 2 regions · 121 things` / `14 people · 9 actions · 223 phrases`. The build
  also now drains the output queue before appending, since the CLI's last lines are still
  in flight at process exit.

## Key Decisions

### 1. The stutter was a replay storm, not paint cost
Per-record delivery gave each record its own dispatcher turn, so the surface kept tripping
its own ordinal-mismatch guard and forking a fresh boot, replaying the whole tree each
time. 720 cards against a settled 169 is the tree replayed about four times over. Batching
removes the storm, which is why it is nine times faster rather than marginally smoother.

### 2. The splitter fix was reverted mid-session, and the revert is the recorded decision
A negative-margin "reach" past the visual track changes where the Grid arranges the
element, producing exactly the two symptoms David reported (jump on drag, one-sided
hit-testing). The fix is a wider real track with a stated `ResizeDirection`, not a wider
hit-test region layered on a narrow one.
