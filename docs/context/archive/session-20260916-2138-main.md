## Key Decisions

### 1. David: don't sign before there's an actual app
Phase 5 was building toward re-notarizing a payload that wasn't yet a working application. ADR-351 Q-5 already proved macOS notarization on a real bundle (submission `cbcd0706-f65c-4f13-9460-e9be833044ca`, Accepted, stapled) — re-proving it against a non-product payload buys nothing and would need redoing once the payload is real. Phase 5 was stopped with nothing notarized.

### 2. David: build one platform slice at a time, not one concern across three platforms
The plan gained a "Slice ordering" section (`docs/work/chord-writer-avalonia-production/plan.md:17-53`) that **supersedes the phase numbering** — phase numbers are now a work inventory, not an execution order. Order is macOS, then Linux, then Windows, each slice done only when that platform has an app a person can install, open, and use. Phase 4 splits across slices (contract + one backend per slice); Phase 5/6/7 (installers) come after their slice's app opens, not before.

### 3. Root cause worth carrying forward: Phase 5's exit state was entirely bytes, signatures, and a subprocess
"The app launches and stays open" was not in the original exit-state criteria, so the phase ran a full evening green while the artifact was unopenable — this is GH #435's shape (green without exercising the real thing) applied to the app instead of the toolchain. Phase 5's exit state now carries a launch check ahead of the signing checks (plan.md:279-285). Recurrence Check below confirms this shape has appeared multiple times in this project's history.
