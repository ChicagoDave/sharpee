## Key Decisions

### 1. Pane collapse by divider manipulation, not `NSSplitViewItem.isCollapsed`
`isCollapsed` does not work in this window: setting it flips the property but the pane keeps its full 259pt width, because `MainSplitViewController` pins pane widths by hand (the documented divider-bounce machinery in `SplitDividerTests`). Hiding is done by moving divider 1 with `minimumThickness` dropped to 0, tracked by an explicit `projectPaneVisible` flag rather than read back from `isCollapsed`. `persistDividerPositions` declines to persist the collapsed 0 so the dragged width survives a hide/show cycle.

### 2. Title centering lives in the chrome, not an accessory view
First attempt used a `.bottom NSTitlebarAccessoryViewController`, which centered the title but added a visible row. David asked whether the chrome itself could center it; the transparent full-size-content-view approach (Decision — Completed #2 above) does, with no extra row.

### 3. Settings snap-to-50% listens on the window, not the split view
`NSSplitView`'s own resize notification also fires for divider drags, which would fight the user's drag. Listening on `NSWindow.didResizeNotification` instead limits the snap to actual window resizes plus the explicit trigger points (pane toggle, checkbox tick).

### 4. Go-live modal landing page drops the "home folder" concept entirely
No `Chord/` folder, no required home folder — an author keeps stories wherever they like, which is what source control demands. David read this as consistent with Inform 7's own retreat from a forced `Inform/` folder. Create Story's location field mirrors the title into `~/Documents/{title}/` until the author edits the location, then mirroring stops permanently. Modal lists the 5 most recent projects (of `RecentProjectsStore`'s existing 10-cap); dismissed once, gone until next launch, no summon-back shortcut — Inform's Cmd-L is deliberately not copied.

### 5. Fernhill transcript rewrite runs in two passes, discovery before the editor
Pass 1 (discovery) rewrites Fernhill's 22 transcripts with today's tooling, before the editor is built, because that friction is what should drive the editor's design — building the editor first would mean designing from a blank page. Pass 2 (acceptance) rewrites them again through the finished editor as the real test of whether it's usable. The moved originals must not be read before pass 1, or the exercise degrades into transcription.

### 6. Documentation tab reuses the Testing tab's scheme-handler machinery
ADR-301's Testing tab already renders local web content in a right-panel tab via a custom URL scheme handler (`TestingTabSchemeHandler`, `TestingTabWebRoot`, `Resources/testing-tab/`, `build-testing-tab.sh`). A Documentation tab is judged to be the same machinery pointed at a different bundle — but is gated behind a documentation-audit phase first, since `docs/reference/chord-language.md` claims Chord 1.4.0 while the IDE status bar reports 3.0.0, and shipping a stale corpus is worse than shipping none.
