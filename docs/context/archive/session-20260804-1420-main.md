## Key Decisions

### 1. Standalone CLI + web tool, not an IDE panel (ADR-300 D0)
An IDE-hosted editor reaches only Chord stories (46/183 transcripts); Dungeo's 134 files, including the walkthrough regression baseline, would be excluded. `@sharpee/transcript-tester` is already standalone and `TestRunner.swift` already shells out to `sharpee test --json`, so a CLI-hosted tool with a framework-free web interface reuses existing seams instead of adding an IDE-only path.

### 2. Play is play; transcripts are promoted, not recorded (ADR-300 D12)
Dissolves the separate "record mode" concept entirely — an author plays, marks turns as a transcript, edits, and signs off. This supersedes ADR-290's D1–D4 and ADR-299's capture model. Per-turn engine saves become an authoring cache only; verification is always from turn 1, because per-turn restores can't roll back occurrence counters.

### 3. Model editor with canonical serializer (ADR-300 D11)
The source pane becomes a generated read-only view rather than a hand-edited text file, once backward compatibility with the current free-text grammar was ruled out as a constraint. D17 fixes the canonical form itself from majority-usage measurements across the 185-file corpus.
