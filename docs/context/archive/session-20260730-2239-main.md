## Completed — Phase 2 (P-2, #142)

### The bug was one layer below where the plan placed it

The phase's entry state said `CheckpointStore` has no concrete implementation and no
version check runs at load. Both readings were off:

- `src/checkpoints/store.ts` ships three implementations (`createFileStore`,
  `createMemoryStore`, `createLocalStorageStore`).
- `deserializeCheckpoint` *did* already check the version — but the file and localStorage
  stores call `validateCheckpoint()` first, and that returned `false` for any version
  other than `'1.0.0'`. A store returning `false` returns `undefined`, and
  `restoreCheckpoint` reads `undefined` as **"checkpoint not found"** and answers `false`.

So a checkpoint written by a newer format didn't fail loudly — it reported as *missing*,
behind a `console.warn`. Conflating "is this shaped like a checkpoint?" with "can I read
this version?" is what produced that.

### Changes

- **`types.ts`** — `CheckpointData.version` is `string`, documented as validated at read
  time rather than by the type.
- **`checkpoints/serializer.ts`** — now the sole authority on version support:
  - `CHECKPOINT_FORMAT_VERSION` (what this build writes) and
    `SUPPORTED_CHECKPOINT_VERSIONS` (what it reads) exported as named constants;
    `serializeCheckpoint` stamps the former.
  - `isSupportedCheckpointVersion(version)` — the predicate.
  - `deserializeCheckpoint` throws an error naming both the offending version and the
    readable list, **before** `world.loadJSON` — a refused checkpoint beats a
    half-applied one.
  - `validateCheckpoint` reduced to structural checking (version must be a non-empty
    string). This is the change that makes an unreadable checkpoint *present* rather than
    missing at the store layer.
- **`extension.ts` / `types.ts`** — `restoreCheckpoint`'s contract documented: `false`
  now means only "not stored"; an unreadable version propagates as a distinct throw.
- **`index.ts`, `checkpoints/index.ts`** — new symbols exported.

## Completed — Phase 3 (P-5, #81)

### Eleven `trace` patterns → two

`packages/parser-en-us/src/platform-grammar.ts` registered eleven literal
`define('trace …')` calls. Now:

```ts
grammar.define('trace [on|off]').mapsTo('author.trace').build();
grammar.define('trace parser|validation|system|all on|off').mapsTo('author.trace').build();
```

**Two, not one — a syntax limit, not a shortcut.** `EnglishPatternCompiler`'s
`expandOptionalElements` rewrites `[x]` to `[optional] x`, marking exactly the *next word*
optional; there is no optional *group*. So `trace [parser|validation|system|all] [on|off]`
cannot express "a category only ever arrives with a state" — written as one pattern it
also accepts `trace parser`, `trace all`, and friends. That would widen the accepted
language and turn what is currently a parse failure into a `TraceAction` `invalid_state`
error. The two patterns accept exactly the eleven original phrasings, no more, no less.

**Literal alternates, not slots.** `TraceAction` (`stdlib/src/actions/author/trace.ts`)
reads `command.parsed.tokens` and validates the category/state itself — it binds no slots.
Using `:category`/`:state` slots would additionally have sent `parser`/`all` through
entity scope resolution, which has nothing to resolve them to. No stdlib change was
needed, as the phase required.

## Key Decisions

### 1. The version gate lives in the reader, not in `restoreCheckpoint`
The plan's deliverable named `extension.ts:restoreCheckpoint` as the validation point.
Putting it there would duplicate a check `deserializeCheckpoint` already owns and split
format knowledge across two modules. `restoreCheckpoint` calls the reader, so the
behavior the plan asked for holds; the format module stays the single place a version
bump is edited.

### 2. Unreadable version throws; not-found returns false
Two different facts deserve two different signals. Returning `false` for both is exactly
the conflation that hid this.

### 3. `SUPPORTED_CHECKPOINT_VERSIONS` is a list, not a comparison
A range check (`>=`) would silently claim readability of formats that don't exist yet.
Adding a version to the list is the deliberate act of promising to deserialize it.

### 4. `trace` collapses to two patterns, and the accepted language does not move
The phase asked for one pattern. One pattern is expressible, but only by accepting
phrasings the eleven literals rejected. Preserving the language won over hitting the
literal count; the reason (no optional *groups* in the pattern syntax) is recorded in the
code and the plan so it isn't rediscovered.
