## Completed

### D8 shipping list — six code items plus the misparse hint

- **L1** `recoverToTopLevel` learns `extend`/`remove`. Without them, one parse
  error anywhere above an `extend action` block made recovery skip the whole
  block: the grammar lines vanished while the story still "compiled," carrying
  only the unrelated error.
- **L2** `lex()`'s doc claimed it diagnoses unterminated strings. It never did,
  deliberately — a lone quote is prose punctuation. The comment now says so,
  and a test pins the documented behaviour.
- **L5** `applyTraitAdjectives` guarded `scenery`/`openable`/`lockable` against
  a double-add but not `wearable`/`readable`. `IFEntity.add` is a `Map.set`, so
  the second add **replaced** the first — `readable with text "…", readable`
  silently lost its text. First add wins, uniformly.
- **L7** two hunger gates: duplicate band **ids** (the threshold gate only
  caught duplicate thresholds, and the id is what the narrator and
  `band_crossed` carry), and a band above `fatal` that can never narrate. A
  band exactly at `fatal` stays legal — that is the dying band.
- **L8** `registerPresentEntries`' gate compared `getContainingRoom(owner)`,
  which walks **upward** and is `undefined` when the owner IS the room — so a
  room's own conditional `present` entry could never fire.
- **`Evaluator.isWithin`** gains a visited set. A containment cycle is rogue
  state, but `AuthorModel.moveEntity` writes the spatial index with no cycle
  check, and the loop was **synchronous** — the worst failure shape, because a
  sync infinite loop cannot be interrupted by a test timeout or a turn budget.
  Discovered the hard way: the test hung the runner before the guard existed.
- **§3.1 misparse hint (AC21)** — the prose/statement fork now records which
  line sat in prose position, so only that line's diagnostic gains "capitalize
  the first word or quote the paragraph." A genuine `set the flag` error keeps
  its plain message. Three codes can carry it (`parse.unknown-statement`,
  `parse.set-to`, `parse.move-to`) because the four openers the review named
  produce three different errors — and `clear`, the fourth, is not a statement
  opener at all and correctly stays prose.
