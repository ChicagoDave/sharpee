## Key Decisions

### 1. Bundle the toolchain in the DMG (ADR-279 D4, amended)
Requiring a global `@sharpee/devkit` npm install before Cmd-B works loses first-time authors at minute one; a ~50-80MB heavier DMG loses no one. Directly motivated by David's own reproduction of the failure.

### 2. Chord Writer stays in-repo at `tools/ide/` (ADR-279 D5, new)
The IDE's contract surface with the platform (compose JSON, build/test CLI, version pairing) is still actively evolving; co-location keeps contract and consumer changes in one commit. Extraction is cheap later if the license or contributor base diverges.

### 3. Full Sparkle 2 auto-update from v1, not a stopgap (ADR-279 D7, new)
David's explicit ruling overriding Claude's more conservative default — bundling (D4) means an author on an old app is also on an old toolchain, so silent-update reach matters from the first release.

### 4. Distribution: GitHub Releases + sharpee.net front door (ADR-279 D6, new)
Zero-VPS-cost versioned artifact hosting via tagged Releases (`chord-writer-v*`), with sharpee.net presenting a product download page rather than a raw GitHub UI.

See `docs/architecture/adrs/adr-279-chord-writer-packaging.md` for full text of D1-D7, the corrected Context, and the reworked Acceptance/Implementation-touchpoints sections.
