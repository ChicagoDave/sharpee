### 5. Play-pane text selection has never worked — root-caused and fixed

David: "the Play web page does not let you select anything … it's never
worked, so maybe the control?" It is not the control.

`packages/platform-browser/src/managers/InputManager.ts:49` registered a
document-level `click` listener that refocused the command input on every
click outside a dialog — a convenience so an author can type without clicking
the box first. A drag that selects prose **ends in a click**, and focusing an
`<input>` collapses the document selection. The selection was destroyed at the
instant it was made.

This also explains David's other report ("I tried the bless thing and not sure
if it works"): `PlayViewController.blessLatestTurn()` samples
`window.getSelection().toString()` from the live page
(`PlayViewController.swift:263`), so it read `""` on every bless. One cause,
two symptoms.

Fixed: the handler returns early when the selection is non-collapsed.
New `packages/platform-browser/tests/input-focus-selection.test.ts` pins the
guard (including that `getSelection().toString()` still reads the prose — the
state bless actually samples), the surviving convenience, and the
disabled-input case. Full `platform-browser` suite: **105 passing**.

**Not verified in the real app.** The tests run under happy-dom, which is not
WebKit. Drag-selecting in the Play pane is the real check and is the first
thing to do next session.

### 10. Save location — D8, and a silent fallback (11:30–12:00)

David, after saving the two fernhill recordings: "Chord Writer didn't default to

**Diagnosed**: `saveSingleTranscript` sets the panel's default directory
conditionally (`if let dir = transcriptsSaveDirectory`), and that is nil whenever
`storyDirectory` is — which is whenever `StoryTarget.storyFile(in:)` finds no
`.story` **directly inside** the opened folder (non-recursive
`contentsOfDirectory`). In that case no `directoryURL` is set, nothing warns, and
the panel opens wherever it last was. The chain path, given the identical nil,
fails loudly with `RecordingSaveError.noStoryDirectory` — same missing value, one
path names it, the other shrugs.

Two hypotheses checked and discarded before landing on that: the app is **not**
sandboxed (only `bundled-node.entitlements` exists), so silent
`createDirectory` failure is out; and `File → Open Project` sets
`canChooseFiles = false`, so the `.story`-file-as-project path was not what bit
him. That path is still a latent inconsistency — `isStoryProject` accepts a bare
`.story` file that `loadProject(at:)` cannot handle — recorded in #198.

**ADR-290 gained D8**: no file panel; the author names the test, the flow owns
where it lands. The location was never a real choice — ADR-280's classifier looks
for exactly two paths, so a browsable panel offers one correct answer and an
unbounded set of silently-wrong ones. `saveChain` already modelled this.

**Caveat recorded in both ADR and issue**: removing the panel *relocates* the
hole rather than closing it. An unresolved story directory must become a loud,
named failure **before capture begins**, not at save time after the author has
played and blessed. Silent inference of the wrong place would be worse than
asking.

Filed as #198.
