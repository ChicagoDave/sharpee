### 4a. Regression introduced and fixed in-session: the config must not sit at the repo root
- The config was **first written to `vitest.config.ts` at the repository root**, and that broke the workspace test gate. Caught by the `commit-local` agent, which ran `pnpm exec turbo run test:ci` (the gate `project-profile.md` designates) as its pre-commit check and refused to commit: `Failed: @sharpee/repokit#test:ci`.
- Mechanism: vitest resolves a missing config by searching **upward** from its working directory, so a root config is on the search path of every workspace member. `tools/repokit` has no vitest config of its own — it had been relying on vitest's zero-config default include against `src/**/*.test.ts`. It adopted the new root config instead and collected 0 files: `No test files found, exiting with code 1`, turning 80 passing tests into a hard failure.
- Blast radius audited rather than assumed: exactly two workspace members run vitest with no local config — `tools/repokit` and `packages/devkit` (enumerated across all of `packages/*` and `tools/*`). Both were confirmed broken by direct runs. `devkit` was **not** caught by the turbo gate, because its `test` script is not wired into `test:ci`; only running `npx vitest run` inside the package surfaced it.
- Fix: the config lives at **`scripts/vitest.config.ts`**, not the repo root, and `test:scripts` names it explicitly via `--config`. `scripts/` is nobody's ancestor, so no member's upward search can reach it. `root` is pinned to the repo root inside the config so the include pattern does not depend on the caller's cwd. The reasoning is recorded in the config's own header comment so a future session does not "simplify" it back to the root.
- Post-fix verification, all four paths run directly: `pnpm test:scripts` → 11 passed; `tools/repokit` → 80 passed | 1 skipped; `packages/devkit` → 167 passed | 1 skipped; full `pnpm exec turbo run test:ci` → **57 successful, 57 total**; `npx tsc --noEmit` → exit 0.
- **Lesson worth carrying**: this session's own verification (`tsc`, the one package suite, `pnpm test:scripts`) all passed while the workspace gate was red — none of the three exercised the full-workspace path. A green check on the thing you changed is not evidence about the things you did not.

## Key Decisions

### 1. Relocate, don't delete, the orphaned test files
Running the suite before deleting revealed genuine rule-13a real-path coverage (ADR-178 §AC-5, ADR-293 D1/D7/D12) rather than dead code — deletion would have silently dropped acceptance tests for two live ADRs. Relocated the package-scoped one into `packages/story-runtime-baseline/__tests__/` and left the CLI-scoped ones in place under a new root runner.

### 2. The scripts vitest config lives outside the repo root, and is named explicitly
Two constraints, learned the hard way (see 4a). `include` is scoped to exactly `scripts/__tests__/**/*.test.ts`, so it never re-collects the 20 package suites under the wrong config or drops their per-package env vars. And the file sits at `scripts/vitest.config.ts` rather than the repository root, because vitest's upward config search makes any root config the implicit config of every workspace member that lacks its own — which broke `tools/repokit` and `packages/devkit` outright. A config that only `--config` can reach cannot be adopted by accident.

### 3. A missing `test:ci` script is a silent gate opt-out, not a configuration detail
Turbo skips packages that do not define the script it is asked to run, without diagnostic. That makes "the gate passed" a claim about an unstated subset rather than about the workspace — 996 tests in 8 packages sat outside it. Adding the script to all eight makes the gate mean what its output implies. The general lesson, and the reason this is recorded as a decision rather than a chore: **a green result is evidence only about what actually ran**, and nothing in turbo's output distinguishes "57 tasks passed" from "57 tasks passed and 8 were never asked."
