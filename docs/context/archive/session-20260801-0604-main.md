## Key Decisions

### 1. Split the D6 verify gate rather than weaken it
A single `Math.random`/`createSeededRandom` grep gate can't distinguish the ~35 pre-existing, deliberately-deferred id-generation idiom from real determinism violations. Splitting into a strict path check (few sites, all Phase-A-resolved) plus a checked-in allowlist keeps the gate meaningful without blocking Phase A on unrelated D13-deferred cleanup.

### 2. `resolve()` moves from Phase C to Phase A (A1 ruling 5)
Multi-draw callers need a real stream-yielding API on day one; shipping a class-labeled `resolve()` now (with `materialize` typed but unused) avoids inventing a throwaway interim API just to delete it in Phase C.

### 3. Save format bumps to 3.0.0 with a version reader, not a hard break
Consistent with the standing post-v3→v4 ruling (`feedback_save_format_versioning.md`): this is the first save-format change since that ruling, and it establishes the version-reader pattern going forward instead of repeating the auto-delete cutover.

### 4. Phases 4–6 treated as one non-mergeable arc, verified package-scoped
TypeScript's composite project references mean the `ActionContext.random` retype cannot have an honest green boundary partway through its blast radius. The plan requires doing Phases 4–6 back-to-back on a dedicated branch/worktree, verifying with package-scoped build/test rather than `./repokit build dungeo`, and only requiring the full platform build to pass again at Phase 6's exit — never merging to `main` mid-arc.
