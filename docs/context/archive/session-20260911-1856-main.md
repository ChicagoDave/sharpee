## Completed

### #426 — ADR-348 AC-4: seam-only ending derivation is unpinned
Added a two-test suite to `packages/engine/tests/unit/engine-lifecycle-phase.test.ts` (describe block "the derivation is a seam, not a per-turn poll (ADR-348 D3, AC-4)"), using a local `revivedOverEndedWorld()` helper that reproduces the branch-tester's shape (start, `endStory(world,'victory',...)`, `stop('victory')`, `resume()`) so the world carries an Ending while the phase reads `playing`. Test 1 asserts a full regular turn (`look`) runs and resolves before the engine is stopped again by `endingStage` at turn end. Test 2 spies on `engine['derivePhaseFromEnding']`, asserts zero calls across a whole turn, then a positive control (`loadSaveData`) drives the count to 1.

Found AC-4's own suggested wording ("an engine stays `playing` for a full turn while the world carries an Ending") false against current code — `endingStage` (`packages/engine/src/turn/ending.ts`) stops the engine at every turn end where the world carries an Ending. The property that actually distinguishes a seam from a poll is that the turn *runs*, not that the phase never changes; the tests were written to that property instead. Probed both directions against real source (a `derivePhaseFromEnding()` call at the top of `executeTurn` fails both new tests plus four pre-existing D15 tests; one added after the phase guard fails only test 2) — probes reverted, `git diff --stat packages/engine/src/game-engine.ts` empty.

ADR-348 AC-4 flipped NOT DISCHARGED → DISCHARGED with the probe record; preamble updated to "All five are discharged."

### #429 — ADR-110 $save/$restore investigation and checkpoint deletion
Investigation posted as a GitHub comment first: the issue's premise was half wrong. `$save`/`$restore` already exist as transcript-tester *directives* (`packages/transcript-tester/src/parser.ts:811-820`), going through the platform engine's real save seam (`engine.save()`/`restore()`), 26 uses each across 10 story transcripts — ADR-110's table row was stale, not the feature. This already answers ADR-348 D5's deferred question: `$restore` reaches `loadSaveData()` → `derivePhaseFromEnding()`, a real derive-at-the-seam restore. `$saves`/SL was found to be a circular stub (`cmdListSaves` pointed back at itself), confirmed by a scratch transcript probe against the bundle. The extension's checkpoint store was write-only in production: `$bookmark` wrote on every use (swallowing errors), `restoreCheckpoint` had zero production callers.

After David approved the delete list: removed `packages/extensions/testing/src/checkpoints/` (serializer.ts, store.ts, index.ts), `saveCheckpoint`/`restoreCheckpoint`, the `checkpoints` config key and its default, the `readonly checkpoints` member, the whole "Checkpoint System" type block, twelve public exports from `@sharpee/ext-testing`, the SL/`$saves` command, and `$bookmark`'s checkpoint write (the bookmark annotation itself is untouched). `$delete-save` was never written, so needed no removal. Also deleted `packages/extensions/testing/tests/checkpoint-version.test.ts` (252 lines, 17 tests, all exercising deleted API only) — flagged to David as not on the original delete list. That file was the package's only test file, so `--passWithNoTests` was added to `package.json`'s `test`/`test:ci` scripts.
