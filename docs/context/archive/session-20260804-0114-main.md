  unblessed. Only the *scope* keeps words ("all paths"), because a colour cannot

### Bugs found and fixed

- **`reload()` dropped every expansion below the first level** — restored from
  an unordered `Set`, and expanding an item whose parent is collapsed is a
  silent no-op. Its own doc promised the opposite. Pre-existing.
- **Unbless was impossible, for two separate reasons.** (1) The two halves
  carried independent selections, so Bless/Unbless read a selection the author
  had not made. (2) Every action guarded on `play.skein`, nil for a file-opened
  skein — silent no-ops on a fully populated tab. Now `activeSkein`.
- **An all-paths objection could not be withdrawn where it appears.** The claim
  is declared at one node and enforced at every node sharing its command, so the
  red rows never hold the blessing. `revocableBlessingNode` follows
  `blessedNodeId` back; the button retitles to "Unbless All Paths".
- **`> >` rows** — we drew a `> ` prompt on top of AppKit's disclosure chevron.
- **Selected blocks were unreadable** — AppKit painted saturated blue behind
  text carrying its own colours. Selection highlight off; cards draw their own.
- **Infinite recursion (mine):** rebuilding cards on selection change re-fired
  the selection delegate. The test runner crash-looped rather than reporting
  failures — 18 tests "passed" instead of 508. Guarded.

### The evidence that decided it

Anchored counts over 183 real transcript files, 3144 assertions:

| Form | Uses | Share |
| --- | ---: | ---: |
| `[OK: contains "…"]` | 2822 | 89.8 % |
| `[EVENT: …]` | 209 | 6.7 % |
| `[OK: not contains "…"]` | 87 | 2.8 % |
| `[OK]` verbatim | **5** | 0.16 % |
| `[SKIP]` | 4 | 0.13 % |
| `[EVENTS: N]`, `[TODO: …]` | **0** | — |

`SkeinExporter` emits **only** `[OK]` + literal block and `[SKIP]` — the two
rarest forms. The assertion authors write 92.6 % of the time is unreachable
from the skein, because "which fragment do I care about" is a judgment it has
nowhere to record. Export is a one-way door out of the tool.

Two further findings: `.golden` recordings carry **provenance** (derivation,
save-format, locale, channels, forces) so a mismatch reports as *"stale
recording — re-bless"* rather than a diff — `.skein` has none of it and cannot
tell a regression from a seed-derivation bump. And `Rebless.swift` already
implements the drift lifecycle, including the refusal to widen a `contains`
claim, which the skein's blessing cannot even express.
