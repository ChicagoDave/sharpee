## Completed — ADR-265 end to end

The core stdlib is now rendered as a **generated, reference-only** Chord artifact. The real
implementation stays TypeScript — a projection, not a port (D5).

### P1 — the enforced marker (D2)
`ChordStory` constructor (`story-loader/src/loader.ts`) throws a `LoadError` naming the marker when
`ir.meta.fields['reference-only'] === 'true'`, before any world build — every CLI path funnels through
`createStory`, so a reference artifact can never be loaded/played. No grammar/version change (a header
field, promoted off the IR). `reference-only.test.ts`: a reference compiles + is refused; a normal
story is unaffected.

### P2 — the generator (D1/D3)
`scripts/generate-stdlib-chord.js` reads the platform's OWN built metadata — `standardActions`,
`actionLifecycleDescriptors`, `standardActionLanguage`, `MESSAGE_ALIAS_TO_ACTION_ID` — and regex-scans
event ids, then renders each of 56 standard actions to a **compiling** reference-only `.story` under
`docs/reference/stdlib-chord/<name>.story`: banner + `reference-only: true` + the action surface (verbs,
group, objects, consulted slots, emitted events, the message→override-alias table, the three D4 change
seams) as `##` comment blocks around a minimal room. Plus a generated README. Exports pure
`renderAll()`/`renderWebsiteMdx()` for the drift test.

### P3 — drift + validity + build wiring
`stdlib-chord-reference.test.ts`: completeness (one reference per standard action), validity+enforcement
(every reference compiles, carries the marker, and the loader **refuses** it — AC-6), and drift
(regenerating reproduces the committed tree byte-for-byte — AC-4, so a stale tree or a missing marker
fails the build). Registered in `repokit` build (`generateStdlibChord`, `--no-genai`-gated) so it
regenerates with the platform.

### P4 — website integration (the intended end result)
The generator also emits ONE website page: `website/src/app/chord/stdlib/reference/content.mdx` — every
action as an anchored section (surface + the message table in a fenced block so `{You}` templates stay
literal/MDX-safe + the change seams). Stable route wrapper `page.tsx` (`<DocPage title="Chord
reference">`); nav entry under **Chord → Standard Library → Chord reference** (`website/src/lib/nav.ts`).
Rides the existing search index (regenerated: 144 pages, the reference indexed as "Chord reference").
The drift test also asserts the MDX is fresh.

## Key Decisions
1. Marker = a header field `reference-only: true` (no new grammar keyword → no Chord version bump);
   loader reads `ir.meta.fields` and refuses. Zero snapshot churn.
2. Rendering = compiling reference-only `.story` files (the surface as `##` comments around a minimal
   room), so `sharpee --play` reaches the loader refusal; genuinely Chord-shaped, never the impl.
3. Website: ONE generated reference page (owner's call), added to the Standard Library section — it
   complements the existing hand-authored task-grouped tutorials (which were already Chord-framed;
   there was no separate "Platform view" to split against). The render-site.mjs/`site/` pipeline is
   dead for the website — the site is hand-authored MDX; the generator emits MDX directly.
