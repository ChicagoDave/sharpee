## Key Decisions

### 1. Cost decided pre-validation from the action id (ADR-315)
Sharpee decides a command's time cost from the action id before running validate/execute, in contrast to Inform 7 deciding mid-sequence. Superseded in its Decision section by ADR-317, which folds the same conclusion into the declared-stage model; Context is retained because it is ADR-317's motivating case.

### 2. Declared stages over a hand-maintained immovable flag (ADR-317)
The existing 13-stage turn pipeline already has one extension point; rather than adding an ad hoc "this stage cannot move" flag per future need, stage mobility is proposed as emergent from `requires`/`precedes` constraints declared per stage. This is scoped as DRAFT — five decisions (D1-D5) recorded, none implemented.

### 3. Roadmap status is evidence-based, not ADR-header-based
The roadmap schema deliberately carries two status fields (ADR header status and a separately verified `Built?` field) because prior sessions established that ADR Status lines are unreliable (e.g. ADR-100 reads ACCEPTED but has no implementing package — only a single `aria-live` attribute in `platform-browser/src/channels/layout.ts` was found repo-wide).

### 4. Roadmap content is derived, not hand-authored
Phase 2 left the hand-authored-vs-derived choice open; the session chose derived (`sync-roadmap.mjs` parsing `docs/roadmap/roadmap-*.md`) to match the site's existing `sync-chord-ebnf.mjs` precedent and avoid a second copy of roadmap content drifting from the first.
