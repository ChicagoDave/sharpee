## Key Decisions

### 1. The landing page is a sheet on the main window, not a standalone modal
The recorded reasoning for "no summon-back shortcut" leans on
`applicationShouldTerminateAfterLastWindowClosed` returning true — which only holds if there is a
main window behind the launcher. A sheet is modal, dismisses with a response, and does not spin a
nested modal run loop that would deadlock a headless test.

### 2. Backing out returns to the landing page
Cancelling Open or Create Story re-presents it (deferred a run-loop turn — AppKit will not present
a sheet while the previous one is dismissing). Without this, "dismissed once, gone until next
launch" would strand an author on an empty window. "Dismissed" now means *a project was opened*.

### 3. `~/Documents/<Story Title>/` — supersedes ADR-280 D2
`StoryHome.defaultRoot` moved from `~/Documents/Chord` to `~/Documents`, and the folder is named
from the title rather than the kebab story id. The `.story` file inside keeps its kebab id. There
is exactly **one** folder-naming rule (`StoryLocationMirror.folderName`) and `StoryHome` delegates
to it, so the "one slug rule" `StoryHomeTests` pins cannot fork. ADR-280 Acceptance 6 (refuse an
occupied target, naming the full path) stands and is still tested.
**ADR-280 has NOT been amended — that is David's call** (per the IDE-primacy directive: build
first, amend after).

### 4. Sanitising rules (the item's one Undecided, now decided)
Recorded in full under item 6 in `todo-list.md`. The one that is a judgement call rather than a
constraint: **no title at all shows the bare root**, not `~/Documents/My Story` — proposing a
folder for a story the author has not named reads as a story they did not ask for. The `My Story`
fallback is only for a title that sanitises away to nothing.
