### Phase 1 — canonical serializer, blocked twice by parser defects found before any serializer code existed
- **Folded header values were discarded.** ADR-300 D17 claims the parser joins continuation lines; it did not — an indented continuation matched no branch and fell out of the loop. 176 lines across 41 files (all `description:`) silently truncated with no parse error; when a continuation contained a colon it became a phantom header key (4 in `article-rendering.transcript` alone: "locks in adr-158", "formatter chain (`{the", "see", "- original bug report"). Fixed by holding a header field open until the next field, `---`, or EOF. Also strips a lone `|` YAML block-scalar marker left over from before continuations joined (5 files).
- **Comment order did not survive a save.** Commands were recorded in `items[]` at finalize time (the *next* command), comments immediately — so a comment written under a command filed ahead of it, and each save/reparse moved it one command further. Non-convergent: AC-3 and AC-4 both failed on 172 of 185 files. Fixed by recording a command where it is read.
- Deliverable: `packages/transcript-tester/src/serializer.ts` (`serializeTranscript`, exported from the root barrel) + `tests/serializer-roundtrip.test.ts` (13 tests: AC-3/AC-4 over all 185 files plus each D17 form rule individually) + `tests/header-folding.test.ts` (10 tests incl. a whole-corpus sweep asserting no header key falls outside the grammar).
- Two D17 gaps settled by measurement: classic expected-output is down to ONE command corpus-wide with its assertion preceding its output; bare `[FAIL]` has 1 use vs. 10 reasoned `[FAIL: reason]`, and the model can't distinguish `[FAIL]` from `[FAIL: Expected failure]`, so emitting the bare form for the sentinel preserves all 11 byte-identically.

## Key Decisions

### 1. Serializer defects are fixed in the parser, not worked around in the serializer
Both the header-folding loss and the comment-ordering loss were pre-existing parser bugs, invisible because nothing had ever round-tripped a transcript before. Fixing them upstream (rather than compensating in the serializer) means the model itself is now correct for every future consumer, not just this one.

### 2. `main` channel dissolution (ADR-301 D7) deferred to its own ADR-302
The decision was made this session but its 2921-contains-assertion / 21-golden blast radius is large enough that David wants it executed as separately planned work rather than folded into the transcript-tool plan already in flight.

### 3. Banner is structured JSON, not a text blob
Follows David's fyrevm rule that a channel is text, number, or json, and json means real structure (title/storyVersion/platformVersion/subtitle/credits[]/tail[]) — not a formatted string the assertion tier has to pattern-match.
