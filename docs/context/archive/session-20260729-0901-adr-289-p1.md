### Phase 2 — D1, implemented twice (`c3a6bc91`, then `c118ba1a`)

**First implementation followed D1's letter and was wrong.** A pre-mutation
snapshot taken at `postValidate` regressed `stories/fernhill` from 495/495 to
567/683 (116 failures). Cause at `fernhill.story:663`: `change it to softened when
it has the sherry bottle` is true only *after* the standard `giving` action
transfers the bottle, which happens between `postValidate` and `postExecute`.

Stopped and reported rather than patching. David ruled the redesign.

**The apparent AC7-vs-fernhill conflict was not real.** AC7 wants a suffix to see
state before a *later* mutation; fernhill wants one to see an *earlier* one. Read
as a straight-line program these are one rule — each suffix evaluated at its own
position. "Pre-mutation" is not a global property to choose; it is positional.

Amended design: **the mutations pass IS the decision pass.** `DecisionLedger` has
three modes (record / replay / live); `snapshotDecisions` was deleted, not
extended. Smaller than what it replaced: the duplicate walker is gone (the
pre-walk mirrored `execStatements`' branch logic — the exact leaky abstraction the
ADR exists to close, reproduced inside its own fix), three traversals became two,
single-pass contexts build no record, and the vetoed-firing counter anomaly
disappeared rather than being documented.

Harness gained the fernhill shape, so the pair now pins both directions.

## Key Decisions

### 1. D1 amended — "once" is positional (David's ruling, this session)

Recorded as a D1 amendment in the ADR rather than landed quietly. The fernhill
episode established the rule that governed the rest of the session: **a change to
a decision's letter goes on the record, not into implementation.**

### 2. Three D2 calls, all confirmed by David with riders

- `select-strategy` only, not `select-on` — the id names persisted state and
  `select-on` has none. Narrows D2's letter, so it joined the amendment.
- Per-entity keying composed at runtime, not baked into the compiler id — the
  compiler cannot name composing entities. Preserves the strict-prefix property
  (documented at the call site, pinned by a test).
- `<clauseKind>-<action>-<index>` over a bare index — the index is required for
  correctness (`analysis.duplicate-clause` skips `every-turn` and separates event
  verbs only by condition fingerprint), the readable prefix keeps faith with D2's
  own debuggability argument.

Plus a written consequence: both the clause key and the statement path are
positional, so source edits re-key a select and reset its counter.

### 3. Platform-change set extended to `packages/engine` (David's approval)

AC4/AC5 were never dischargeable inside the ADR's declared scope. Two workarounds
rejected and recorded: the plugin `setStates` hook (invents a plugin whose purpose
is key hygiene) and a lazy sweep inside `decideStrategy` (hides a lifecycle fact
inside a routing decision).

### 4. The rubric gap this exposed, fixed in the harness

Three `adr-review` passes (11/14, 13/14, 14/14) shipped acceptance criteria that
could not be discharged within the ADR's own scope. `.claude/skills/adr-review/SKILL.md`
gained a BLOCKER item: *every acceptance criterion must be dischargeable within the
packages the platform-change line names.* Mechanical, with the ADR-289 provenance
attached.

clean runs followed immediately. Saved to memory. Notably the rule was quoted from
ADR-228 §Consequences earlier in the same session and still not applied.
