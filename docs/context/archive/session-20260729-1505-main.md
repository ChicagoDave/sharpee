## Key Decisions

### 1. The npm-pack breakage is filed, not fixed (David's ruling)

`./repokit test:npm --local` is broken for **every** story: `consumer-gen.ts:133`
reads `JSON.parse(out)[0].filename`, but npm 12.0.1 returns `npm pack --json` as
an **object keyed by package name**, so `[0]` is `undefined`. Reproduced directly
against `~/.tsf-publish/sharpee/core`. Filed as **#199** with the repro and a
shape-tolerant fix sketch; not fixed, to keep the triage pass pure.

### 3. ADR-290's six open questions block six issues

implement"**. Verified their code claims still hold, then stopped: their blocker
is a decision, not investigation. The unblock is the open-questions interview.

### 4. #187 design amended live (David's rulings)

Five rulings recorded on the issue during triage:

- Generated metadata (`story-build`, `chord-version`, `sharpee-version`) leaves
  the story block and is **emitted in the build log** instead. This preserves IR
  determinism — a build timestamp in `meta.fields` would churn all 7 snapshot
  files and destroy the ADR-289 Phase 6 property ("diff is exactly four
  `languageVersion` lines").
- `blurb` **==** `description` — one metadata field, not an emission. This is the
  status quo made explicit: `loader.ts:264` already maps blurb → description.
- `prologue:` stays as the one genuinely new field, naming pre-banner text.
- The story block is expanded to allow **text** for both `blurb` and `prologue`.
- Both may take **either literal text or a phrase**.
