Indentation was rejected on evidence: the reader must dedent by the block's minimum indent, recoverable only when some line starts at column 0 — a bless of the leaflet's centred `WELCOME TO DUNGEON` line (indent 25) loses its indentation silently, since `normalizeOutput` trims before comparing, so the assertion still passes while Acceptance 5's "identical to the captured response" quietly stops being true. ## Key Decisions

### 1. Bridge fix is amend-and-fix, not work-around (carried into this session's proof)
Phase 1's capture-parity proof is the end-to-end evidence that the previous session's `joinMainEntries` fix actually holds, rather than an argument from shared construction — the test is mutation-checked to fail if the fix regresses.

### 2. Capture-parity proof runs against happy-dom, not a real WKWebView
The plan offered either form. Happy-dom was chosen because after the ADR-282 amendment the capture path no longer touches the DOM at all (packets accumulate through `onEntriesText`), so WebKit-vs-happy-dom fidelity isn't on the tested axis; the one thing that does need real WebKit (`window.getSelection()`) is covered separately by `PlaySelectionCaptureTests`.

### 3. `writeRecording(to:)` throws the zero-bless refusal itself
Rather than checking in the panel/UI flow, the refusal lives in the write path so no caller can route around Acceptance 3.

### 4. Every saved transcript opens with a synthetic `> look` turn
Fixes a class of bug an author could never diagnose (banner-vs-no-banner mismatch on a session's first recorded turn) rather than special-casing the comparison logic.

### 5. ADR-287 delimiter: `text`/`end text` at column 0, reserved, no escape
Indentation was rejected on concrete evidence (silent, unrecoverable data loss on the leaflet fixture); backtick fences were reopened because they read as a developer convention, not an author one. The no-escape ruling was accepted only after verifying the collision degrades to a normal validation error in every arrangement, never a silent one.
