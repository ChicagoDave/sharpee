## Completed

### Root-cause diagnosis (the trigger)
- `ENGINE_VERSION` was not stale, it was two different computations sharing a name: devkit's author-side stampers (`version-stamp.ts`, `stampBrowserVersion`, `build-browser.ts`, `publish.ts`) computed it as `platformRanges().sharpeeRange.replace(/^[\^~]/, '')` — the `^5.0.0` dependency-range floor with the caret stripped — so every 5.x author build stamped "5.0.0" regardless of the actual engine version. The in-repo stampers (`repokit` → stdlib's `engine-version.ts`, `repokit` → `stories/<name>`) used the exact version and were correct. The value is player-visible via `StoryInfoTrait` → the `version`/`about` actions.

### First fix, then superseded
- Three devkit call sites were initially switched to `platformVersion()` with a new test file. David then asked what the field was actually *for*: banner text only, produced by five stampers and couriered through `version.ts` → generated entry → `storyInfo` → `StoryInfoTrait` → action. He approved deleting the courier route instead of patching its endpoints.

### The redesign — single source of truth
- Every read site now reads stdlib's stamped `ENGINE_VERSION` constant unconditionally, no trait fallback chain: `packages/stdlib/src/actions/standard/version/version.ts`, `.../about/about.ts`, `packages/stdlib/src/channels/standard.ts`'s `infoChannel` (always sets it now, not from the capability), and `packages/engine/src/game-engine.ts`'s `game.started` banner path.
- `engineVersion` deleted from: `StoryInfoTrait` (world-model), the story-info projection (`STORY_INFO_SCHEMA`, projection type, trait-wins copy line, and the "build-pipeline fields" doc comment — this is ADR-334 F1's centralization point), `platform-browser`'s `StoryInfo` config type, the three devkit browser-entry templates, `BrowserBuildEnv`, and all four stampers that wrote it (repokit's per-story stamper, devkit's `version-stamp.ts` / `stampBrowserVersion` / `build-browser.ts` / `publish.ts`).
- `PlaygroundBuildEnv.engineVersion` renamed to `version` — it was the playground app's own version pin, never an engine version.
- `stories/dungeo/src/index.ts`, its `browser-entry.ts`, and `stories/armoured/src/browser-entry.ts` stopped passing the field.

### Real bug fixed as a side effect
- `start()` previously read the engine version off `StoryInfoTrait`, which only a build pipeline populates, so Chord/story-loader stories emitted `game.started` with no `engineVersion` and `handleGameStarted` silently dropped the `platform-version` banner block. Confirmed fixed by direct probe: `node dist/cli/sharpee.js --story branch-stories/fernhill/fernhill.story --exec "look"` now shows "Sharpee v5.4.0" where it previously showed no engine line at all.

### `info-channel-baseline` transcript removed

A fix attempt (asserting the channel's shape via fenced-literal contains-blocks) failed: transcript text assertions only see rendered prose, the `◦ info {...}` line lives only in the recording, not the checked transcript output. The only assertion form over a channel payload is a golden, and a golden necessarily pins `version`/`buildDate`/`engineVersion` — all of which move every release; this one had already rotted (recorded at 4.3.0 / 2026-08-04). Both files removed; coverage is duplicated in `stdlib`'s `channels/standard.test.ts` (including ADR-298's authors-as-array case) and `engine`'s `channel-bootstrap.test.ts`. Recoverable at `4f8a8e7e0`.

## Key Decisions

### 1. Delete the courier route rather than patch its endpoints
Patching the three wrong-read devkit call sites would have left two computations of the same banner text permanently coexisting. David chose to delete `engineVersion` from every carrier (trait, projection, config type, templates, four stampers) and make every reader import stdlib's stamped constant directly, closing the class of bug rather than one instance of it.

### 2. Golden-based channel test removed, not repaired
A transcript-format test cannot assert on channel payloads (they render only into the recording, not checked output), and a golden necessarily pins per-release values that rot every version bump. Removed rather than re-pinned; equivalent coverage already exists in two other suites.

### 3. Plan superseded by "just do it"
`session-planner` wrote a 4-phase plan; David told it to proceed without phase gating. All four phases' deliverables were completed in this single session, so the plan is marked DONE and archived rather than left CURRENT-on-Phase-1 while the work outran it.
