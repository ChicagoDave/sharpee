## Completed

### Root-cause diagnosis (the trigger)
- `ENGINE_VERSION` was not stale, it was two different computations sharing a name: devkit's author-side stampers (`version-stamp.ts`, `stampBrowserVersion`, `build-browser.ts`, `publish.ts`) computed it as `platformRanges().sharpeeRange.replace(/^[\^~]/, '')` — the `^5.0.0` dependency-range floor with the caret stripped — so every 5.x author build stamped "5.0.0" regardless of the actual engine version. The in-repo stampers (`repokit` → stdlib's `engine-version.ts`, `repokit` → `stories/<name>`) used the exact version and were correct. The value is player-visible via `StoryInfoTrait` → the `version`/`about` actions.

### First fix, then superseded
- Three devkit call sites were initially switched to `platformVersion()` with a new test file. David then asked what the field was actually *for*: banner text only, produced by five stampers and couriered through `version.ts` → generated entry → `storyInfo` → `StoryInfoTrait` → action. He approved deleting the courier route instead of patching its endpoints.

### The redesign — single source of truth
- Every read site now reads stdlib's stamped `ENGINE_VERSION` constant unconditionally, no trait fallback chain: `packages/stdlib/src/actions/standard/version/version.ts`, `.../about/about.ts`, `packages/stdlib/src/channels/standard.ts`'s `infoChannel` (always sets it now, not from the capability), and `packages/engine/src/game-engine.ts`'s `game.started` banner path.
- `engineVersion` deleted from: `StoryInfoTrait` (world-model), the story-info projection (`STORY_INFO_SCHEMA`, projection type, trait-wins copy line, and the "build-pipeline fields" doc comment — this is ADR-334 F1's centralization point), `platform-browser`'s `StoryInfo` config type, the three devkit browser-entry templates, `BrowserBuildEnv`, and all four stampers that wrote it (repokit's per-story stamper, devkit's `version-stamp.ts` / `stampBrowserVersion` / `build-browser.ts` / `publish.ts`).
- `PlaygroundBuildEnv.engineVersion` renamed to `version` — it was the playground app's own version pin, never an engine version.
- `stories/dungeo/src/index.ts`, its `browser-entry.ts`, and `stories/armoured/src/browser-entry.ts` stopped passing the field.

### Real bug fixed as a side effect
