## Key Decisions

### 1. `BannerData` is imported from `@sharpee/stdlib`, not redeclared
Rule 8b: the banner record is a shared wire shape, so devkit takes a new workspace dependency (David's choice "a") rather than a hand-kept copy that could drift.

### 2. The opening is read after the first command and printed before its output
The prologue and banner ride their own channels and are captured by the first `executeCommand('look')`, so the REPL prints prologue, banner, then the room from one call.

### 3. After an ending, the player reads the language layer's ended line, never the engine's error
A pipe has no prompt, so it is told once on the ending turn; a TTY reads it off the prompt; undo or restart returns the playing prompt because `ended` is recomputed from `world.getEnding()` every turn.
