## Completed

### Vendoring decision and artifact
David decided to vendor **Node 22 as a committed binary**, refined during the session to the official nodejs.org `.tar.xz` (25.9 MB) rather than the raw 112.9 MB binary, which exceeds GitHub's 100 MB hard per-file limit; no Git LFS, since that would break the fresh-clone bootstrap fixed in the prior session. ### arm64-only toolchain
`tools/ide/project.yml` now pins `ARCHS: arm64`. Decided after establishing Apple's last Intel Mac shipped August 2020 (27" iMac) and that macOS 26 Tahoe is the final OS with Intel support across only four models — the app should not ship a slice with no toolchain behind it.

### Vendoring script and assembly
`tools/ide/vendor-toolchain.sh` (new) assembles `Contents/Resources/toolchain/{bin/sharpee, node/bin/node, devkit/}`: verifies the Node tarball's checksum on every run, extracts only `bin/node` from it (npm/npx deliberately excluded), runs `pnpm deploy --prod --legacy` for the devkit dependency closure, separately deploys and grafts in `@sharpee/platform-browser` (not a devkit dependency, but the browser build path needs its styles/engine.css and esbuild resolution), writes the `sh` shim, and installs atomically (stage + swap) with post-condition assertions so a half-assembled toolchain can't report success. Incremental via a `.stamp` fingerprint plus an mtime sweep over `packages/*/dist`. `tools/ide/project.yml` gained an opt-in `postBuildScript` (`SHARPEE_VENDOR_TOOLCHAIN=1`) so a normal dev-loop `xcodebuild` is unaffected (ADR-279 Acceptance 5) — vendoring is a ~1-2 minute step that must not run on every build.

### Swift-side resolution and coupling note (written, uncompiled)
- New `tools/ide/SharpeeIDE/Compose/BundledToolchain.swift`: locates `Resources/toolchain/bin/sharpee`; a present-but-non-executable shim is treated as absent so callers see "not found" instead of an opaque launch failure.
- `tools/ide/SharpeeIDE/Compose/ComposeRunner.swift`: `resolveSharpee` gains tier 3 (shim → PATH → bundled, ADR-279 D4); extracted a pure `resolve(near:searchPATH:bundledResources:)` seam specifically so the fallback order is assertable (AC6 requires a test pinning it).
- New `tools/ide/SharpeeIDE/Test/ToolchainFenceNote.swift`, wired into `TestController.didExit`: the ADR-279 D4 / ADR-287 fence-grammar coupling note. Deliberately behavioral, not version-gated — fenced-transcript support landed after the 4.2.0 version stamp, so a version string can't distinguish a fence-capable toolchain from one that isn't. Fires only when a fenced transcript fails on a non-bundled toolchain.
- New tests (written, **not run** — no Swift toolchain on this box): `BundledToolchainTests.swift` (7 cases), `ToolchainFenceNoteTests.swift` (12 cases).

### Platform change: `packages/devkit` (approved by David)
CLAUDE.md requires discussion before touching `packages/`. Raised and resolved: devkit has two consumption targets (npm-installed CLI vs. the IDE's embedded toolchain) and one code path serves both, since esbuild is a declared devkit dependency in either case — no mode switch needed.
- New `packages/devkit/src/standalone/esbuild-bin.ts` — `resolveEsbuild()` resolves esbuild from devkit's own dependency instead of shelling to `npx`. Reads the first two bytes of `bin/esbuild` to route a `#!` shim through `process.execPath` vs. spawning a native binary directly, so the spawn never depends on `node` being on PATH. `npx esbuild` demoted to a fallback.
- Call sites updated: `browser-core.ts` (Chord story `game.js`, ~line 680; playground, ~line 868) and `build.ts` (TS-project story `story.js`, ~line 141). The `build.ts` site was also converted from a shell string to `execFileSync` — `--external:@sharpee/*` was passing through a shell unquoted, one matching directory away from glob expansion.
- New `packages/devkit/src/standalone/esbuild-bin.test.ts` (4 tests, real-path): spawns the resolved command and asserts it reports the exact version devkit depends on (an npx-downloaded copy would differ), and that it actually bundles an import graph.

### REAL-PATH TEST harness
New `tools/ide/toolchain-realpath-test.sh` — the rule 13a stand-in for AC6. Runs the assembled shim under `env -i` with `PATH` cut to system binaries, a fresh empty `HOME`, and a work directory outside any checkout. It asserts the scrub is real (no node/npm/npx/sharpee/pnpm reachable) *before* asserting anything about the toolchain, so a leaky sandbox can't produce a false pass.

## Key Decisions

### 1. Node vendored as committed `.tar.xz`, not raw binary or LFS
The raw `bin/node` (112.9 MB) exceeds GitHub's 100 MB hard limit; the official nodejs.org `.tar.xz` (25.9 MB) is committed instead and extracted at build time. Git LFS was rejected because it would reintroduce the fresh-clone bootstrap fragility repaired last session.

### 2. arm64-only toolchain
Apple's last Intel Mac shipped August 2020; macOS 26 Tahoe is the last OS with any Intel support, across four models. `project.yml` now pins `ARCHS: arm64` so the shipped app can never contain an architecture slice with no bundled toolchain behind it.

### 3. `packages/devkit` platform change approved, single code path for both consumption modes
esbuild is a devkit dependency regardless of whether devkit is npm-installed or embedded in the IDE's sealed toolchain, so `resolveEsbuild()` needs no mode switch — same code, same resolution logic, both contexts.
