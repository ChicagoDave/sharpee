### ADR-348 written, reviewed, accepted — "The world is authoritative on restore"
Wrote `docs/architecture/adrs/adr-348-the-world-is-authoritative-on-restore.md`, generalizing the #416 ruling. Five decisions: **D1** any path that replaces the world wholesale must re-derive every view derived from world state; **D2** a mechanical test for "derived view" (can world and view disagree after a restore? then it's derived); **D3** derivation happens at the seam, not continuously; **D4** a path that cannot re-derive must declare that at its signature, moving the obligation to the caller; **D5** does not rule on whether any given path should become a seam.

## Key Decisions

### 1. GH #416 ruled option B — document, don't rewire an unreachable path
Adding phase-sync logic to `restoreCheckpoint` would have built defensive plumbing for a path with zero production callers. Documenting the contract at the interface (world-only, caller owns phase) is the change that matches the actual risk. See ADR-348 for the generalized rule this ruling produced.

### 2. ADR-348: the world is authoritative on restore
Any wholesale world replacement must re-derive its dependent views (D1), with a mechanical test for what counts as a derived view (D2), derivation at the seam rather than continuously (D3), and a declared escape hatch when a path can't re-derive (D4). D5 deliberately stops short of mandating which paths become seams — that stays a case-by-case call.

### 3. AC-4 left open by design
Nothing pins that ending derivation stays at the seam rather than migrating into the turn loop — only the branch-tester's integration trees would catch that move, emergently. The ADR names this gap rather than closing it with a test that doesn't yet have an owner. Filed as GH #426.
