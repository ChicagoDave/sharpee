## Context — verified, not assumed

Every count below was produced this session against `packages/core/src/` at `2fd7336b5` (main, 2026-11-02) and is recorded with its method in `docs/work/refactoring-survey/assessment-20261102-remaining-packages.md`. "External" means a file under `packages/*/src`, `tools/*/src`, or `stories/*/src` outside `packages/core`, matched by whole word.

- **Core is the bottom of the stack.** 32 `package.json` files depend on `@sharpee/core`; it depends on none of them. It is 4,951 source lines across 46 files; the suite is 13 files, 176 passing (`pnpm --filter '@sharpee/core' test`, 2026-11-02). Churn is low: 15 commits since 2026-06-01, and the last commit to touch `constants/`, `debug/`, `execution/`, or `extensions/` was `38f12f621` (2026-07-19), a cross-package ADR-242 sweep, not work on them.
- **The contract is 71 symbols; the barrel publishes 241.** Other packages import 71 distinct names from `@sharpee/core` — led by `ISemanticEvent` (309 import sites), `EntityId` (101), `RandomService` (25), `definePoint` (19), `IEntity`, `createEvent`, `Presence`, `SeededRandom`, `ISaveData`, the platform-event types, the restore/reconciliation types, and the IFID functions. `src/index.ts` (35 lines) is eight `export *` lines over sub-barrels that are themselves `export *` (`events/index.ts:11-21` nine lines; `types/index.ts` five; `query/index.ts`, `extensions/index.ts`, `debug/index.ts`, `execution/index.ts`), plus one named block (`index.ts:19-26`, the six execution interfaces). The result is 241 exported symbols, of which **143 have no consumer outside the package**, and **121 of those are referenced by nothing inside the package either** beyond their own definition and barrel line. `package.json` exposes one entry (`exports["."]`), so the root barrel is the whole public surface.
- **Two directories the barrel does not reach.** `src/constants/` (`attributes.ts`, `core-events.ts`, `entity-types.ts`, `relationships.ts`, `index.ts`; 220 lines; header: "generic, system-level constants that don't assume any particular type of narrative") is exported by no line of `src/index.ts`; nothing imports it from inside `core` either. `src/extensions/registry.ts` (174 lines, `ExtensionRegistry`, `createExtensionRegistry`) is likewise unreachable — `index.ts:16` exports `extensions/types.js` only — and its one reader is `tests/extensions/registry.test.ts` (160 lines), which tests a class no runtime constructs.

A type-only removal that breaks a consumer fails `tsc` in the same commit; that is the whole point of doing this at the bottom of the stack.

## Decision

- **D1 — The root barrel names the contract (resolved Q-1, David, 2026-11-02: "a").** `src/index.ts` becomes a named export list: every symbol another package imports (the 71, plus the entries D4 and D5 keep public), each written out, in the shape `world-index/src/index.ts` already uses. No `export *` remains in the root barrel. Sub-barrels (`events/index.ts`, `types/index.ts`, …) may keep `export *` for intra-package convenience or go; they are not the public surface and `package.json` exposes only the root. A structural test, `tests/surface.test.ts`, asserts (i) the root barrel contains no `export *` line and (ii) every name the barrel exports resolves to a definition — so a deleted module cannot leave a dangling line. There is no count assertion and no line budget (ADR-334 D2): the invariant is that the public surface is a list someone wrote, not that the list has a size. A symbol used inside `core` and not listed is internal by that fact alone; nothing else changes about it.
- **D2 — The dead subsystems go.** Deleted whole, with their barrel lines and their tests, **after David confirms the list** (CLAUDE.md: never delete files without confirmation): `src/constants/` (5 files, 220 lines; unreachable), `src/extensions/` (`types.ts`, `registry.ts`, `index.ts`; 278 lines; `registry.ts` unreachable, `types.ts` implemented by nothing) with `tests/extensions/registry.test.ts` (160 lines), `src/debug/` (2 files, 78 lines), `src/execution/` (2 files, 132 lines; the `index.ts:19-26` block with it), `src/events/typed-event.ts` (78), `src/events/standard-events.ts` (31; `tests/events/event-system.test.ts` drops its `StandardEventTypes` reference, the rest of that test is live), `src/types/attribute.ts` (54), `src/types/relationship.ts` (53). About 924 source lines and 160 test lines in whole files, every one read by nothing outside its own directory.
- **D3 — The dead halves are trimmed symbol by symbol, from a table.** The plan carries one row per symbol named in the Context's "dead halves" bullet, each with a verb: **delete** (no reader anywhere — the eight `isGame*` guards, `GameState`, the seven orphan `GameLifecycle*Data` interfaces, `isSystemEvent`, `SubsystemType`, `isQueryEvent`, `IQueryContext`, the three `ISerialized*State` types, `IStoryConfig`, `IEntityOperationOptions`, `ICommandResult`, `StoryConfigValidationResult`, `EventDataFor`), **un-export** (read in its own file only — `createGameEvent`, the factory-side `GameLifecycle*Data` and `GameEvent*Data` interfaces, `PlatformEventTypeValue`, `CreateEventOptions`, `MessageVariant`), or **keep** (every function in `event-helpers.ts` — D8). **The test-only rows are `delete` (resolved Q-2, David, 2026-11-02: "a")**: `isPlatformEvent`, `isPlatformCompletionEvent`, `IUndoContext`, `createEmptyEvent`, `createMessageEvent`, `resetEventCounter`, and the `event-system.test.ts` / `typed-events.test.ts` cases over `StandardEventTypes` and `SimpleEventSource` go with the cases that read them — a test whose subject nothing calls pins no behavior the platform depends on, the reasoning ADR-338 Amendment A2 applied when it deleted the eight scope tests whose subject the platform rejects; `isPlatformRequestEvent` and `createTypedEvent`, the engine's guard and factory, stay. David confirms the table before the phase runs.
- **D4 — Registry entries are live by declaration merging, and the file says so.** `events/event-registry.ts` keeps its 22 `*Data` interfaces and `EventDataRegistry`; its header gains one paragraph stating that the entries are reached by event-type key through declaration merging (`media`, `stdlib`) and will show as unreferenced to any name-based scan, so that the next survey does not file this finding. Whether the entry interfaces stay exported from the root is D1's list: `EventDataRegistry` is listed (it is merged into from outside); the entries are not unless a consumer names one.
- **D5 — The facade does not move.** Every symbol another package imports keeps its name, shape, module, and semantics: `ISemanticEvent`, `EntityId`, `IEntity`, `createEvent`, `createTypedEvent`, `getUntypedEventData`, the random service and choice points, the IFID functions, the save/restore/reconciliation types, `GameEventType` and the factories the engine calls, the platform events, the query manager, `ISystemEvent`, `Subsystems`, `Result`. No importer outside `core` changes a line; `tsc` across the workspace is the proof.
- **D6 — Every phase lands byte-identical.** Each phase ends with `tsc --noEmit` clean for every package, the core suite at 176 passing or higher minus the cases D2/D3 delete with their subjects (the plan records the arithmetic), every downstream suite at its recorded count, and the Dungeo chain and the three Chord test trees byte-identical to the run before it. Order: D1 first — the named barrel is written against the *current* tree, so it proves the 71-symbol contract before anything is deleted and `tsc` catches any name the scan missed; then D4 (a header); then D2 (deletions, after confirmation); then D3 (the table, after confirmation). `./repokit build dungeo` regenerates `genai-api/core.md` at the end.
- **D7 — Not now.** Discuss-first `packages/` work with its own plan on `main`, sequenced at David's call. Acceptance of this ADR authorizes the plan, not the edits; D2 and D3 each wait on a confirmation recorded in the plan.
- **D8 — `event-helpers.ts` is out of scope; the event model is recorded as debt, not decided here (resolved Q-3, David, 2026-11-02: "getUntypedEventData is worse than `any`" and, of the typed helpers and the registry's payload interfaces, "none of those types match any kind of DDD pattern").** All seven functions in `event-helpers.ts` — the six typed helpers nobody calls and `getUntypedEventData`, called from `event-processor/src/handlers/device/index.ts` (3 sites), `handlers/complex-manipulation.ts` (3), `handlers/observation/sensory.ts` (1), and imported by `engine/src/game-engine.ts:39` — stay exactly as they are, and D1's barrel lists `getUntypedEventData` because its consumers exist. Neither side of the question is a shape worth migrating to: `ISemanticEvent` is a string-typed envelope (`type: string`, `data?: unknown` — `events/types.ts:17-31`), `EventDataRegistry` is a string-keyed map of payload interfaces bolted on by declaration merging, the six helpers are checked lookups into that map, and the untyped accessor is the same payload as a dictionary of `unknown`. A domain event is a typed fact a handler narrows on, and nothing in `core` is that. Choosing between two lookups into a map that should not be the model is a stepping stone, so this ADR does not choose. **The debt is recorded**: the event model — the envelope, the registry, the `*Data` payload families in `event-registry.ts` and `game-events.ts`, and every accessor over them — is the next finding in `core`, is its own ADR when David opens it, and is filed as a GitHub issue beside this ADR's so it is not lost. Until then the six unused helpers are not deleted either; they are evidence of the shape that was tried, and the ADR that replaces the model decides what survives.

**Amendment A1 (2026-11-03, session 99293e — D1 applied, Phase 1 of `docs/work/adr-391-core-contract/plan.md`).** The contract is **95 names, not 71**. The assessment's count came from a single-line scan of `import … from '@sharpee/core'` statements; the multi-line-aware scan Phase 1 ran across `packages/*/src`, `packages/extensions/*/src`, `tools/*/src` and `stories/*/src` (tracked files, whole statements, `import type` and aliases included) finds 95 distinct imported names, and the barrel lists those plus `EventDataRegistry` (D4): 96 lines of contract. The finding is unchanged in kind — 241 published, 145 that nobody imports — and every number above that says "71" reads as 95 from here. Two names the Context's tables treated as internal have importers and are therefore listed: `GameLifecycleStartedData` (D3's "factory-side" row; it stays public, the other factory-side payload interfaces lose their export as D3 says) and `createGenericEventSource`, which exists only as an alias in `events/index.ts` and is now carried by the root barrel as `createEventSource as createGenericEventSource` from `events/event-source.js`. As built: `src/index.ts` is a named list grouped by module, `export type` for names declared only as `interface` or `type` (including `ChoicePoint`, `RandomService`, `SeededRandom`, which are interfaces) and plain `export` for values; `Result`, declared as both a type and a const, is exported plain. The sub-barrels stay as intra-package conveniences (`query-manager.ts` imports through `events/index.ts`; the suite imports through `src/ifid`); `package.json` exposes only the root, so they are not public. `tests/surface.test.ts` carries three cases, not two: no `export *` line, every listed name declared in the module it names, and every plain export present at runtime (so a value name mistakenly marked `type`, or a type mistakenly exported plain, fails). Evidence for AC-1 and the gates is in the plan's Phase 1 outcome.

## Consequences

- `@sharpee/core`'s public surface is a list a reader can see in one screen, and adding to it is an act. A symbol that is not on the list is internal, which is the inside the package did not have.
- Roughly 1,100 lines nothing calls leave the bottom of the stack, and the generated API reference stops advertising an extension system, a command-handler framework, a debug event bus, and a constants table that no code honors.
- `ISemanticEvent`, the random streams, the save types, and everything else 32 packages actually use are untouched; the proof is a clean workspace `tsc` and byte-identical transcripts.
- **Tech debt, recorded and not paid here (D8)**: `core`'s event model is a string-typed envelope with a string-keyed payload registry bolted on, and no accessor over it — typed or untyped — makes an event a typed fact. The seven functions in `event-helpers.ts` and the `*Data` families stay as they are until an ADR replaces the model; this ADR's barrel lists what consumers use and nothing more. The issue filed beside this ADR carries the finding.
- A name-based dead-export scan of `core` becomes repeatable: D4's header explains the one file that will always look dead, and D1's test keeps `export *` from quietly republishing a directory.
- The pattern now has two instances (ADR-338, this). If a third package shows it, the survey's method is settled and the ADR can be shorter.

## Acceptance

- **AC-1 (named contract)**: `grep -c 'export \*' packages/core/src/index.ts` → 0; `tests/surface.test.ts` passes, and fails by name when a scratch `export *` line is added to the root barrel or a listed name's definition is removed (verify, then revert).
- **AC-2 (dead code gone)**: `packages/core/src/{constants,debug,execution,extensions}/` absent; `src/events/typed-event.ts`, `src/events/standard-events.ts`, `src/types/attribute.ts`, `src/types/relationship.ts` absent; `tests/extensions/` absent; the plan records David's confirmation of the D2 list and the D3 table; the regenerated `genai-api/core.md` has no `Extension*`, `ICommandHandler*`, `IExecutionContext`, `IDebug*`, or `CoreConstants` entry.
- **AC-3 (nothing outside moved)**: `git diff --stat <before>..<after> -- packages ':!packages/core' ':!packages/sharpee/docs/genai-api'` is empty across the plan; `tsc --noEmit` clean in every package.
- **AC-4 (byte-identical)**: after each phase, the Dungeo walkthrough chain and the three Chord test trees (`secret-letter`, `fernhill`, `ides-of-march`) report the same counts and byte-identical captured output as the run before the phase; evidence inline in the plan, with command, count, and date.
- **AC-5 (registry explained)**: `event-registry.ts`'s header carries the declaration-merging paragraph; `media` and `stdlib` still compile their merges.
- **AC-6 (debt recorded)**: `event-helpers.ts` is byte-identical before and after the plan; the GitHub issue for the event model exists and is linked from this ADR's Status line.
