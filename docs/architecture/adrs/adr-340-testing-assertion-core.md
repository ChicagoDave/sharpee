## Context — verified, not assumed

Every line reference below was read this session against `packages/transcript-tester/src/` and `packages/branch-tester/src/` at `6ad2faeba`.

- **Two packages, one lineage.** `transcript-tester` is 6,656 lines across 15 files (`runner.ts` 1765, `parser.ts` 1068, `types.ts` 560, `cli.ts` 514, `reporter.ts` 510, `golden.ts` 405, `run-event-stream.ts` 370, `serializer.ts` 294); `branch-tester` is 3,783 across 7 (`runner.ts` 1500, `tree-walker.ts` 685, `types.ts` 564, `tree-document.ts` 507, `auto-assertion.ts` 241, `channel-assert.ts` 211). Suites: 23 files, 282 passing; 8 files, 114 passing (2026-09-07). Neither has a skipped test (transcript-tester's four `describe.skipIf(!hasCorpus)` blocks are corpus gates, not skips). Neither package depends on the other (`package.json`): transcript-tester depends on `bootstrap, core, engine, world-model, stdlib, lang-en-us, parser-en-us, channel-service, ide-protocol`; branch-tester on the same set plus `story-loader`. The IDE's testing surface builds against `@sharpee/branch-tester` (`tools/ide/web/testing-surface/build.mjs`, `tsconfig.json`).
- **The assertion runtime exists twice.** `branch-tester/src/runner.ts` opens with transcript-tester's header, edited ("Transcript Runner — assertion-tier execution (ADR-294, golden tier retired by ADR-306 …)", `:1-11`, against transcript-tester's "Transcript Runner — golden replay/record and assertion-tier execution (ADR-294)", `:1-14`). Measured this session with a line-level diff and a per-function comparison: **1,129 of branch-tester's 1,501 runner lines are identical to lines in transcript-tester's runner**; **20 top-level functions exist in both by name, 10 byte-identical** (`captureEntityTraits`, `checkEventAssertion`, `collectStrings`, `configureRandomInstruments`, `directiveFailResult`, `executeDirective`, `getEntityProperty`, `normalizeOutput`, `resolveValue`, `unfiredForceError`), 2 near-identical (`checkAssertion` at `transcript-tester:1322` / `branch-tester:990`, similarity 0.80; `findEntity`, 0.92), and 8 diverged (`evaluateStateExpression` at `:1548` / `:1206`, similarity 0.65; `checkStateAssertion` 0.78; `runCommand` 0.78; `forcesFailResult` 0.76; `runAssertion` 0.72; `runTranscript` 0.65; `errorResult` 0.43; `openingResult` 0.14 — the last two are the tree world's own result shapes and are expected to differ). The two `types.ts` files share 442 identical lines of about 560. `aggregateTestRun` is defined in both (`transcript-tester/src/aggregate.ts:48`, `branch-tester/src/runner.ts:175`). What is *only* in transcript-tester is the golden tier (`runGolden`, `diffTurn`, `goldenPathFor`, `executeForGolden`, `synthesizePolicyAssertions`, …); what is only in branch-tester is the tree and Chord side (`evaluateChordStateClaim`, `captureWorldSnapshot`, `worldEntityRef`, `endingFrom`, `allAssertionsOf`).
- **The fork was ruled, and the ruling was a firewall.** ADR-307 made branch-tester by copying, and declared transcript-tester untouched so the platform's text world (Dungeo's walkthrough chain, the unit transcripts, `--chain`) could not be disturbed by the author world's tree work. That held: transcript-tester's suite verified it (`:241`). The cost the ruling did not name is the one the diff measures: every fix to a claim evaluator since then landed in one runner or the other, the two `evaluateStateExpression`s and two `checkStateAssertion`s have already diverged, and the byte-identical count only goes down. Core-concepts' description — branch-tester "owns the shared assertion machinery … that both the walker and the IDE's Testing tab consume" — is true of the IDE and false of transcript-tester, which shares nothing and carries its own.
- **Small leftovers.** `run-event-stream.ts` exports `RunEventStream` and `ndjsonEventLine` (used through the barrel by the CLI) and three `Streamable*` result types referenced nowhere outside the file; `reporter.ts`'s `ReporterOptions` likewise. `parser.ts`'s header is a four-line stub ("Parses .transcript files into a structured format for testing") on a 1068-line module that owns the transcript grammar and the `REMOVED_FORMS` table (`:52`, ADR-294 D4).
- **The revamp is coming, and this is what it would inherit.** The testing-UX revamp (memory, 2026-08-08/09) treats the platform contracts as the durable layer and the surface as replaceable. The claim language and its evaluator are a platform contract — the same `[OK]`/state/event claims are what an author writes in a tree card and what a walkthrough transcript asserts. A revamp that builds on two evaluators of one claim language inherits their drift.
- **The regression net.** Both suites; the Dungeo walkthrough chain (952, recorded) and the unit transcripts, which are transcript-tester's world; the three Chord test trees, which are branch-tester's; all byte-deterministic at their pinned seeds (recorded in `CLAUDE.md` under ADR-293 Phase D; re-established by AC-4 at each phase). For this ADR the net is unusually direct: the evaluator under refactor *is* the thing that decides whether the nets pass, so any change in its verdict is a count change, not a byte diff.

## Decision

- **D1 — The assertion core has one owner.** The functions that exist in both runners — state-expression evaluation, assertion and event-assertion checking, directive execution, random-instrument configuration (ADR-293), entity and trait capture, value resolution, output normalization, the fail-result and unfired-force helpers, and the shared result types — become one module set with one home, and both runners call it. Where the two copies have diverged, the plan's first phase diffs them function by function and records which behavior is kept, with the reason; a divergence that turns out to be a fix one side never received is a bug fixed on the other side, and a divergence that is a genuine difference between the tree world and the transcript world stays as a parameter or a caller-side wrapper, never as a second copy. **The home is `transcript-tester` (resolved Q-1, David, 2026-09-07: "a")**: it already owns the claim grammar (core-concepts), and its dependencies are a strict subset of branch-tester's, so `@sharpee/branch-tester` gains `@sharpee/transcript-tester` as a dependency with no new transitive weight and no new package. The core is exported from transcript-tester as `assertion-core` (one module or a small directory, the plan decides), and branch-tester's runner imports it; ADR-307's untouched package gains an exported module, additively, and nothing about how it parses a `.transcript` or replays a golden changes. ADR-307 gains a one-line note beside its "Untouched" statement (`:23-24`) recording that transcript-tester now exports the assertion core branch-tester consumes, written by the plan phase that lands D1, so the flip has an owner and a trigger.
- **D2 — What is not shared stays where it is.** The golden tier (`runGolden` and its helpers, `golden.ts`, the serializer, the transcript grammar in `parser.ts` and its `REMOVED_FORMS`) is transcript-tester's and stays; the tree document, walker, auto-assertion, channel-assert, and the Chord state claim (`evaluateChordStateClaim`) are branch-tester's and stay. ADR-307's firewall is honored in the direction it was drawn: the tree work cannot change how a `.transcript` is parsed or how a golden is replayed.
- **D3 — Drift becomes a test.** A structural test in branch-tester asserts that its runner defines no function by any name in the shared set (the names D1 lists, pinned in a fixture) and imports each from `@sharpee/transcript-tester`; a second copy of any of them fails the test by name.
- **D4 — Headers say what the modules are.** `parser.ts` gets a rule-9 header naming its purpose (the transcript grammar and its canonical serializer pair, ADR-294), public interface, and owner; the three `Streamable*` types and `ReporterOptions` are removed or kept with a stated reason; branch-tester's runner header stops describing itself as the transcript runner.
- **D5 — The facade does not move.** `runTranscript`, `goldenPathFor`, the CLI flags, `RunEventStream`, the `.transcript` grammar and its serializer, `<story>.tests.json`, the walker's and the IDE's imports from `@sharpee/branch-tester` keep their names and shapes. branch-tester gains a dependency whose packages it already carried transitively.
- **D6 — Every phase lands count-identical and byte-identical.** Each phase ends with the Dungeo chain, the unit-transcript suite, and the three Chord trees reporting the same pass counts and byte-identical captured output as the run before it, and both package suites green. Order: D3's fixture and the per-function diff record first (read-only), then D4, then D1 function by function from the ten byte-identical ones outward (each move is zero-risk by construction) to the eight diverged ones (each a recorded decision), then D2's cleanup of whatever the moves left behind.
- **D7 — Not on this branch, not now.** Discuss-first `packages/` work with its own plan on `main`, sequenced before the testing-UX revamp so the revamp inherits one evaluator; the Secret Letter port's plan closes first.

## Consequences

- One evaluator of the claim language. A fix to how a state claim reads a trait lands once and both worlds get it; the revamp builds on one contract.
- ADR-307's "untouched" becomes "unchanged in behavior and format, sharing its evaluator": the transcript world keeps its grammar, its golden tier, and its CLI, and stops carrying a private copy of code that has already drifted from the copy the IDE uses.
- About 1,100 duplicated lines leave branch-tester; its dependency list gains `@sharpee/transcript-tester`, whose own dependencies are already a subset of branch-tester's — no new transitive dependency, no new package, no registration checklist.

## Acceptance

- **AC-1 (one owner)**: `grep -n 'function evaluateStateExpression\|function checkAssertion\|function checkEventAssertion\|function executeDirective\|function configureRandomInstruments' packages/transcript-tester/src packages/branch-tester/src` finds each name once, under `packages/transcript-tester/src`; `packages/branch-tester/package.json` lists `@sharpee/transcript-tester`; the D3 structural test fails by name when a shared function is redefined in branch-tester.
- **AC-2 (divergences decided)**: the plan carries a table of the ten non-identical functions (`checkAssertion`, `findEntity`, `evaluateStateExpression`, `checkStateAssertion`, `runCommand`, `forcesFailResult`, `runAssertion`, `runTranscript`, `errorResult`, `openingResult`) with, for each, which behavior was kept and why, and — where one side was a missed fix — the test that now pins it on the other side.
- **AC-3 (worlds intact)**: `node dist/cli/sharpee.js --test --chain stories/dungeo/walkthroughs/wt-*.transcript` and the unit transcripts report the same counts as before; `./sharpee test branch-stories/<story> --tree` for the three trees likewise; the IDE testing-surface suite passes with no source change.
- **AC-4 (byte-identical)**: after each phase, captured output of the runs in AC-3 is byte-identical to the run before the phase (evidence inline in the plan: command, count, date).
- **AC-5 (headers)**: `parser.ts` and `branch-tester/src/runner.ts` open with rule-9 headers that name their own purpose; the four unreferenced types are absent or annotated.
