## Decision

- **D1 — One module per sub-step, in its subsystem's directory.** Each of the seven sub-step bodies moves out of `tick-phases.ts` into the directory of the subsystem it drives — `conversation/scene-sub-step.ts` (with `applySeizedExchange`), `goals/goal-sub-step.ts` (with `executeNpcGoals`), `influence/influence-sub-step.ts` (with `handleInfluenceResults`), `propagation/propagation-sub-step.ts`, `act-detection/observe-sub-step.ts`, `arbiter/decay-sub-step.ts` for the decay sub-step (resolved Q-1, David, 2026-09-07: "b" — lucidity decay is one 124-line module, not a subsystem, and the sub-step already drains `arbiter/pressure.ts` each turn, so the two per-turn decays sit together; a `lucidity/` directory would promise more than it holds, and is earned if lucidity ever grows into one), and `conversation/arrival-sub-step.ts` for arrival reactions — each exporting one function with the signature it has today (`(npcs, ctx, registry, surface) => ISemanticEvent[]` or the decay variant) and a rule-9 header. `tick-phases.ts` keeps `createCharacterModelPhase`, `registerCharacterModelPhase`, `CharacterPhaseRegistry`, `CharacterPhaseConfig`, and the ordered list; no sub-step body changes. Shared helpers the sub-steps use in common (`recordTransfer` `:722`, `authorNarratesArrival` `:750`, `mutation` `:924`) go with their first caller or into a `tick-support.ts` beside the tick — decided per helper in the plan, by fan-in.
- **D2 — The two `stdlib` sub-step bodies come home.** `lucidity-decay.ts` and `character-observer.ts` move from `packages/stdlib/src/npc/` into `packages/character/src/` — `arbiter/lucidity-decay.ts` and `act-detection/character-observer.ts`, beside the sub-steps that call them (D1), with their tests (`stdlib/tests/unit/npc/character-observer.test.ts` and the decay cases) moving alongside. Both modules import only `@sharpee/core`, `@sharpee/world-model`, and `./character-messages.js` (`character-observer.ts:11-20`, `lucidity-decay.ts:12-20`); after the move the last becomes `CharacterMessages` from `@sharpee/stdlib`, which the tick already imports that way (`tick-phases.ts:51`). `stdlib/npc/index.ts` stops re-exporting `processLucidityDecay`, `DECAY_RATE_TURNS`, `observeEvent`, and `DefaultStateTransitions`; `stdlib/npc/` becomes exactly the decision layer core-concepts describes. `CharacterMessages` (`character-messages.ts`, 42 lines) stays in `stdlib` — it is language-layer message ids the tick emits, not model logic.
- **D3 — The order is pinned, in the shape the file already has.** The seven spread calls become an exported `CHARACTER_TICK_SUB_STEPS` array of `{ name, run }` iterated by `createCharacterModelPhase`, and `character-model-phase.test.ts` gains one case asserting the seven names in order and that one tick runs each exactly once. The header's contract sentence moves onto the array as its doc comment. This is ADR-334 D2 and ADR-336 D3 applied to a list that is already a list.
- **D4 — The facade does not move.** `createCharacterModelPhase`, `registerCharacterModelPhase`, `CharacterPhaseRegistry`, `CharacterPhaseConfig`, `CHARACTER_MODEL_PHASE_NAME`, every subsystem's existing exports, the trait, and the emitted event types keep their names and shapes. The only public-surface change is D2's two retired `stdlib` re-exports, which have no consumer outside `character` and tests.
- **D5 — Every phase lands byte-identical.** Each phase ends with the three Chord test trees byte-identical to the run before it and the character suite at 600 passing or higher, the stdlib suite green. Order: D3 first (the list and its test, no bodies move), then D1 sub-step by sub-step, largest first (`scene`, then `goal`, `influence`, `propagation`, `arrival`), then D2 (the two cross-package moves, each a `git mv` plus import edits), with the byte-identical check after each.
- **D6 — Not on this branch, not now.** Discuss-first `packages/` work with its own plan on `main`, sequenced with the other survey ADRs at David's call; the Secret Letter port's plan closes first. This is the lightest plan of the set — seven mechanical moves, two cross-package moves, one test.

## Consequences

- `tick-phases.ts` returns to what its header says it is — one registration and an ordered list — at roughly its January size; the subsystem directories hold their own sub-steps next to the evaluators those sub-steps call.
- A new sub-step is one module in its subsystem and one entry in the list; the order test fails by name if the entry is placed where its inputs do not yet exist.
- `stdlib/npc/` matches its documented purpose; the character model's update logic lives in the character package with the rest of the model. `stdlib` loses 415 lines it was hosting for one caller.
- Nothing in this ADR touches the trait, the save format, Chord, or any story.

## Acceptance

- **AC-1 (sub-steps home)**: `tick-phases.ts` contains no `run*SubStep`/`runArrivalReactions` body; each of the seven lives in its subsystem directory with a rule-9 header; a `grep` for the seven names shows one definition each, outside `tick-phases.ts`.
- **AC-2 (stdlib is the decision layer)**: `packages/stdlib/src/npc/` contains no `lucidity-decay.ts` or `character-observer.ts`; `grep -rn 'processLucidityDecay\|observeEvent\|DefaultStateTransitions' packages/stdlib/src` → 0; the moved tests pass under `packages/character/tests`.
- **AC-3 (order pinned)**: `CHARACTER_TICK_SUB_STEPS` exists with seven entries; swapping `scene` above `goal` in a scratch branch fails the order test naming both; one tick of a two-NPC fixture runs each sub-step exactly once.
- **AC-4 (byte-identical)**: after each phase, `./sharpee test branch-stories/<story> --tree` for `secret-letter`, `fernhill`, and `ides-of-march` reports the same counts and byte-identical captured output as the run before the phase (evidence inline in the plan: command, count, date).
- **AC-5 (facade unchanged)**: `story-loader`, `engine`, and the IDE build with no source change; `packages/sharpee/docs/genai-api/` shows no removed public member of `@sharpee/character`, and the two retired `stdlib` re-exports are the only change under `stdlib`.
