# ADR-338: One world surface, no dead subsystems — `world-model`'s structure

**Status**: **ACCEPTED** (David, 2026-09-07, session 354dfe — "accepted" after the rule-11a interview resolved Q-1 (keep `IWorldModel`; David: "we tried to remove the interface and everything broke … I'm skeptical") and Q-2 (b, the trait is the recorded exception), and `adr-review` returned 19/19 after one fold: D1 rewritten from a subclass to a proxy view of the live world, because the registries are instance fields). ## Decision

- **D1 — `AuthorModel` is a view of the live world, not a copy of its surface (folded from `adr-review` 2026-09-07, David: "yes" — the first draft made it a subclass, which is unsound: `WorldModel`'s registries are instance fields (`WorldModel.ts:580-654` — capability and interceptor bindings, exit resolvers, evaluators, the event system, the score ledger, scene conditions, the scope registry), so a second instance over the shared `IDataStore` would neither see nor receive the registrations the four construction sites make through the author model during `initializeWorld`).** `createAuthorModel(world: WorldModel): AuthorModel` returns a `Proxy` over the same `WorldModel` instance whose `get` trap forwards every member to the live world, bound to it, except the two bypasses (`createEntity`, `moveEntity` — the same bodies as today, writing through the shared data store) and the three author helpers (`populate`, `addTrait`, `removeTrait`). Its type is `WorldModel & AuthorHelpers`, so it satisfies `IWorldModel` and every existing call site; the four construction sites become `createAuthorModel(world)`. Registrations made through the author view land on the live world because there is no second instance. The 89 delegations are deleted; the header's promise ("all other methods delegate") becomes structurally true; a new world method reaches the author view with no edit. **`IWorldModel` stays (resolved Q-1, David, 2026-09-07: "we tried to remove the interface and everything broke — that was months ago, but I'm skeptical that's the correct action").** The first draft read the interface as an accidental copy of the class; it is a deliberately *thin* published contract — `queries` augments only the concrete class so that the interface stays narrower than it (`queries/src/augmentation.ts:78-83`), and the 2026-08-11 ruling ("you need a very good reason to modify `IWorldModel`") governs when a member is added to it. D1 removes the delegate that made every addition a third edit; the interface's own rule stays as it is. No importer changes.
- **D2 — The dead subsystems go, and the parser contract has one owner.** `src/extensions/` (six files, 1100 lines) and `src/examples/` (one file, 174 lines) are deleted, with their barrel lines; the list is confirmed by David before the phase runs (CLAUDE.md: never delete files without confirmation). `src/interfaces/parser.ts`'s `IParser` is removed and its four importers take `Parser` (or `BaseParser`, whichever member set they use) from `@sharpee/if-domain`, the owner core-concepts names; the rest of `src/interfaces/` (command-executor, command-processor, command-validator, language-provider) is audited in the same phase against `if-domain` and each is either the sole definition or removed the same way — the audit's table goes in the plan, not here.
- **D3 — The character-model trait is the recorded exception (resolved Q-2, David, 2026-09-07: "b").** The eleven mutators stay on the trait. ADR-310 D17 gains one paragraph, written by the plan phase that lands this ADR, stating that the character model's mutators live on the trait by design — the model is one stateful object whose invariants span mood, threat, goals, and lucidity together, and a behavior would hold no state of its own and only forward to the trait, the same delegation shape D1 deletes from `AuthorModel` — and core-concepts' behaviors section names the exception in one sentence, so the next reader does not file this finding again. Nothing moves. The *read* methods (effective state, facts, beliefs, goals, predicates) stay on the trait — they are the model's queries, and ADR-310 D8's influence overlay is a read.
- **D4 — Trait registration is pinned.** A test in `tests/unit/traits/` asserts that every `TraitType` key (excluding the category constants) has an `implementations.ts` entry, that every entry's class reports that type, and that the root barrel and `traits/index.ts` export every trait class and behavior the directory holds. The five-place checklist stays as documentation; the test is what fails when a step is missed.
- **D5 — The facade does not move.** `WorldModel`'s public methods, `IWorldModel` and its sixteen importers, `IFEntity`, every trait class and behavior, every `TraitType` value, the save format, and `index.ts`'s exports other than the D2 removals keep their names and shapes.
- **D6 — Every phase lands byte-identical.** Each phase ends with the Dungeo chain and the three Chord test trees byte-identical to the run before it and the world-model suite at 1506 passing or higher, with every downstream suite green. Order: D4 first (a test, no code moves), then D2 (deletions after confirmation; the `IParser` migration is compile-checked), then D1 (the proxy view; the two bypass bodies are unchanged and the story-loader boot is the real-path test that registrations still land on the live world), then D3 (two documentation edits; no code moves).
- **D7 — The skipped tests are resolved, not carried.** As ADR-337 D7: each of the ten is implemented, deleted, or replaced by a one-line note naming the gap and its owner. The four "violates architecture" and "magic sight should affect" cases read as deletions with a note; the plan's table decides each.
- **D8 — Not on this branch, not now.** Discuss-first `packages/` work with its own plan on `main`, sequenced with the other survey ADRs at David's call; the Secret Letter port's plan closes first.

**Amendment A1 (2026-09-08, session 4a2d5f — D1 and D3 applied with the code, `refactor/survey-adr-334-340`; D2 and D7 held for David's confirmation; D4 landed the same night).** D1 as built: `createAuthorModel(world)` returns a `Proxy` over the live `WorldModel` whose `get` trap serves the two bypasses (`createEntity`, `moveEntity`, bodies verbatim), **`canMoveEntity` kept returning `true`** (a third bypass the ADR's list omitted; kept so a placement through the view never fails), and the three helpers; every other member forwards to the world, **bound once per member per view and cached** (only functions are cached; a non-function member is read through live) — the umbrella assessment's refinement. `AuthorModel` is now the type `WorldModel & AuthorHelpers` plus a constructor shim, so all twelve `new AuthorModel(world.getDataStore(), world)` sites (the ADR counted four; the loader, three helpers builders, three Dungeo regions, Dungeo's GDT context, the testing extension's debug context, the devkit fixture, and the doc example) compile and run unchanged; the data-store argument is accepted and not read. The header records why `Object.create(world)` was rejected. D6's order was inverted for D1 (landed before D2's held deletions), since `AuthorModel.ts` references nothing under `extensions/` or `examples/`. D3's paragraph is in ADR-310 under D17, core-concepts names the exception in one sentence, and the trait header states it. Gate: Dungeo chain and the three Chord trees byte-identical; world-model 1511 passing (1504 + 3 registration + 4 view cases); the unit-transcript suite's differences were traced to unpinned clock seeds (the thief's random walk), not to the view.

## Consequences

- A new world method is the class plus, when the interface's own rule says so, the interface — never a delegation line in a second class. `AuthorModel.ts` shrinks from 658 lines to the proxy factory, the two bypasses, three helpers, and a header.
- 1274 lines of code nothing calls leave the package; the root barrel stops exporting an extension mechanism the platform never adopted, which removes a false affordance from the generated API reference (`packages/sharpee/docs/genai-api/world-model.md`).
- The parser contract has one home. Engine files that today import a one-method interface from the world model import the real contract from `if-domain`.
- The behaviors-own-mutations rule is explicitly excepted for the character model in the ADR that built it and in core-concepts; a reader is not misled, and the rule stays intact for every other trait.
- The five-place trait checklist becomes a failing test instead of a memory.
- Ten tests stop being skipped.

## Acceptance

- **AC-1 (one surface)**: `grep -c 'this.worldModel\.' packages/world-model/src/world/AuthorModel.ts` → 0; `createAuthorModel(world)` is the only construction path and the four sites use it; a story loaded through `story-loader` (the Secret Letter tree's boot) and the helpers' builders place an item in a closed container through the author view's `moveEntity` exactly as before (the existing `AuthorModel` tests pass unchanged); a test registers an event handler and a capability through the author view and asserts the live `WorldModel` holds them — the registration-through-the-view case the subclass draft would have failed.
- **AC-2 (dead code gone)**: `packages/world-model/src/extensions/` and `src/examples/` are absent; `src/interfaces/parser.ts` is absent; `grep -rn IParser packages/*/src` → 0; `./repokit build dungeo` regenerates `genai-api/world-model.md` with no `Extension*` entries; the plan records David's confirmation of the deletion list.

- **AC-4 (byte-identical)**: after each phase, the Dungeo chain and `./sharpee test branch-stories/<story> --tree` for `secret-letter`, `fernhill`, `ides-of-march` report the same counts and byte-identical captured output as the run before the phase (evidence inline in the plan: command, count, date).

- **AC-6 (no skips)**: `grep -rn 'it.skip\|test.skip\|describe.skip' packages/world-model/tests` → 0; the plan's ten-row table records each verb.
