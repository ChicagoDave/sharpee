## Decision

- **D1 — One identity: the IR id is the world id, and nothing translates between them.** `worldIds`, `irIds`, `entityId`, `irIdOf`, the loader's `requireWorldId`, the evaluator's `EntityIdResolver` and `requireWorldId`, and `ExtensionInstallContext.worldId`/`requireWorldId` are deleted; every reader uses the IR id directly as the world id. The one invariant that replaces the maps is asserted where the entity is made (DevArch rule 6): after each `createEntity` in `buildEntity`, `entity.id === irEntity.id` or a `LoadError` naming both. The one check the translation layer actually performed — "referenced before it exists in the world" — survives as a single `requireEntity(world, irId)` in one module, returning the entity, used by the readers that today call `requireWorldId` and then fetch the entity anyway. `EntityIdResolver` shrinks to `playerWorldId()` (the start-block-aware player id, `loader.ts:649`), the one thing the evaluator asks the story that is not an id lookup; it is renamed for what it is. The `'player'` alias write at 848 does NOT go with the map, as first written: the compiler emits `player` as an entity id in load-time positions (`analyzer.ts:8444–8448`, 28 sites) and readers resolve it through the map with IR-carried ids. ADR-390 (accepted 2026-10-31) makes the role one world fact and resolves the sentinel through `world.playerCharacter.id` in one loader function; that lands as its own phase ahead of this decision's, so D1 here stays the pure deletion it describes (amended 2026-10-31). The `createPlayer`/`finalizeRoleHolder` path keeps the player's id in `this.playerId` as today. **As landed (2026-10-31, Phase 3)**: the one module is `src/identity.ts`, exporting `worldIdOf(world, irId)` (the sentinel read from the world, `undefined` before the role is assigned, every other reference the id itself — ADR-390 D3's function, given the world as a parameter because the runtime sections hold no world of their own) and `requireEntity(world, irId, at?)`. The Context above miscounted: the eight `createEntity` calls did pass the IR id, but the region branch called `createRegion(\`rg-${id}\`)`, so a region's world id was `rg-maze` while every reader of the map got `maze` back — the new assertion caught it on the first run (118 tests failing on "`Maze` was built as `rg-maze`, not as its id `maze`"). Regions now take their IR id too, which retires the parenthetical "a region keeps its `rg-<id>` spelling" in ADR-388's amendment; nothing outside the loader read the prefix, the three tree captures hold no region id, and the save format stays dormant. Two seams gained a `world` argument rather than a host hook: `ExtensionInstallContext` carries `world` (state machines resolve roles and trigger targets through it, and the role-bound `$name` target is never looked up), and `DialogueSection.matchTopicFilters`, `matchExchangeRow`, `askedTopicKey`, `exchangeResponses` and the thread row matcher take the world, because a topic row `about the player` carries the sentinel and must compare against the role holder. The evaluator keeps one private `worldId(ctx, irId)` for value positions (`it`, `the match`, an entity literal) that yields the id whether or not the entity is still in the world, so `entityValue`'s "Expected an entity" stays the existence check (`gone-semantics.test.ts` pins it). `EntityIdResolver` was also an exported type and `Evaluator`'s constructor lost its resolver parameter — both public, noted under AC-7.
- **D2 — The world build and the engine wiring become named step lists, one module per step.** `initializeWorld`'s stages, in today's order, become `WORLD_BUILD_STEPS` (extensions' `registerWorld`; create entities; wire entities; stamp exit admittance and pushing ways; door backstop; story state, counters, scores, ranks; removal observer; detail channels; location names; pending entity refs; runtime bind; cuttable check; start block and role holder), each a module under `src/build/` exporting one `run(story: BuildContext, world: WorldModel): void`, listed as data with a `requires` per entry exactly as `RUNTIME_BIND_STEPS` does (`runtime.ts:214`), and a test that pins the order and faults a reordered copy by name. `onEngineReady`'s stages become `ENGINE_READY_STEPS` in the same shape. `buildEntity`, `wireEntity`, `wireExit`, and the adjective lowering (D3) move into the entity step's module family; `extendParser` and `registerPassageGrammar` into `src/build/grammar.ts`; `onWorldRestored`/`reconcileRestoredWorld` beside `reconcile.ts`. Bodies move verbatim; the only change inside a body is re-targeting `this.X` to the context the step receives. `ChordStory` remains the `Story` facade the engine constructs — it owns the context, calls the two lists, and keeps every public member (ADR-335 D5 unchanged, extended to this record).
- **D3 — Core adjective lowering is a table, pinned to the catalog.** The 41-arm `switch` in `applyTraitAdjectives` becomes `CORE_TRAIT_ROUTES: ReadonlyMap<string, TraitRoute>`, where a `TraitRoute` is the one function an arm's body is today — `(entity, irEntity, composition, ctx) => void` — so arms that construct a trait, arms that stamp a field on an existing trait (`plural`, `proper`), and arms that queue work (`guard`/`patrol`/`follower`/`wanderer`, which push `npcBehaviors`) are all rows, and the conditional-composition prelude (2209–2227) stays as the one guard before the lookup. The table lives beside `COMBAT_FIELD_ROUTES` and `NPC_FIELD_ROUTES`, and `tests/manifest-conformance.test.ts` gains the two assertions it already makes for combat: every word in `TRAIT_ADJECTIVES` has a route, and every route's word is in `TRAIT_ADJECTIVES` (NPC and combat words excluded, as they have their own tables). A word that matches no row is a `LoadError` naming the word, never a silent fall-through. Adding a core adjective is then one catalog word, one row, and the test says so when either is missing.
- **D4 — One rule, two callers: the IR's invariants live in `@sharpee/chord` as `validateIR`, and the loader asks (resolved Q-1, David, 2026-10-31: "why not c and be done").** `@sharpee/chord` exports `validateIR(ir: StoryIR): Diagnostic[]`, a pure, browser-safe function over the finished IR alone — no AST, no analyzer state — carrying every gate that is a fact of the IR. The analyzer runs it as the last entry of `ANALYSIS_PASSES` (ADR-336 D3's list, `analyzer.ts:1074`), so a compile reports the same diagnostics it does today, under the same codes and author-facing text, from one implementation; the in-analyzer copies of those gates are deleted as each moves. The loader calls it once in `createStory`, right after the format check and the three identity assertions (`loader.ts:608–613`), and throws a `LoadError` carrying the message and span of the first diagnostic whose severity is `error`; diagnostics of lower severity are the compile's to report and the load ignores them, so a story that compiles with warnings loads exactly as it does today. With the gated-construct gates in `validateIR`, `ExtensionRegistration.gatedConstruct` (ADR-335 D3's slot, `extension-registry.ts`) and the loop over it at `loader.ts:1273` are deleted — the slot's only job was that backstop. Of the 28 "defensive backstop" throws in `loader.ts`, 25 are facts of the IR and are deleted in favour of that one call — the 23 that read the IR today, and the two that read the built world for an IR-derivable fact (door never wired by a `through` exit, 697; worn target not wearable, 1758), which `validateIR` expresses over `ir.entities` as the analyzer already does (`analysis.door-unconnected`, `analysis.worn-not-wearable`). Three are not backstops and stay where they fire: the gerund implementation count (2188, authoritative for the ADR-090 capability surface the compiler cannot see), the removal that matched no live grammar rule (1567, the real grammar is the fact), and the direction word with no `Direction` value (3101, a cross-package drift guard pinned by its conformance test). So are the 20 `LoadError` throws that were never backstops — load-time facts (`createPlayer`'s empty role, the cuttable implementation check, `requireEntity`). The eleven tests in `tests/adr-276-backstops.test.ts` (compile clean, mutate the IR, expect the loader to throw) become `validateIR` tests in `packages/chord`, one per gate, and one loader test keeps the seam: a mutated IR handed to `createStory` throws a `LoadError` naming the diagnostic. ADR-276 D1's "corresponding `LoadError` sites remain as defensive backstops" is amended by this record: the backstop is one call to the rule's one home, never a second copy of the rule. The one-line amendment note under ADR-276 D1 is written by the plan phase that lands the first gate in `validate-ir.ts`, in that phase's commit, so the flip has an owner and a trigger; ADR-276's Status line does not change — it is amended, not superseded. ADR-210's direction rule is untouched — chord still imports no platform package; the loader already imports chord. **As landed, first gate group (2026-11-01, Phase 4)**: `validateIR` is the analyzer's `checkCompositionLegality` moved verbatim (`src/validate-ir.ts`) — it was already a pass over the finished IR alone, so moving the whole method keeps its `continue` ordering exact — plus the unconnected-door gate lifted out of `checkDoors`; it carries the inventory's D4a rows 1, 3, 10, 13, 15, 17, 18, 20, 21, 22, 23, 26 and 27 and the method's companions (the kind-noun `-needs-use` gate, `thing-with-kind`, `conditional-kind`, `settable-*`, `powered-*`, `night-vision-*`, `transparent-*`, `detachable`, `fragile`, `costs-*`, `hearing-not-listener`, `gerund-implementation`). ## Consequences

- A Chord feature that adds a construct adds one build step or one table row, not a method to a 2,800-line class. The comments that are today the only map of `initializeWorld` become the file listing, as the runtime's rulers did under ADR-335.
- One identity for an entity across the compiler, the loader, the runtime, the evaluator, the extensions, and the save: the thirteen files that translate stop translating, and "referenced before it exists" is one function.
- The core adjectives get the drift gate the extension adjectives already have; a catalog word with no lowering fails a test instead of composing nothing.
- The engine's `Story` contract loses its last `any`; `Parser` declares the story-grammar surface every locale parser must offer, and `extendParser`'s cast goes.
- ADR-335 D5's "facade does not move" covers `ChordStory` too. ADR-276 D1 is amended: the IR's invariants have one implementation, `validateIR` in `@sharpee/chord`, and the loader's backstop is one call to it. A new IR gate is written once, in chord, and both the compile and the load see it; the author text exists in one place.
- Persisted IR (the published browser build's embedded `story-ir.ts`) is checked at load by format, identity, and `validateIR` — the same rules the compile applied — so a hand-edited or stale artifact fails with the compiler's own diagnostic, not wherever it first misbehaves.
- Nothing touches the IR, the language, the wire, the save format, or any test story.
